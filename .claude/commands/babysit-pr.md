## Context

PR to babysit: $ARGUMENTS (if empty, use the PR linked to the current branch).

## Your Task

Watch the PR until every required gate is green, fixing real failures. Stop when the PR is mergeable, then hand back. Do not merge unless asked.

### Steps

1. Read PR state: checks, review comments, `pr-flow/ready` status (use `rtk gh pr checks`, `rtk gh pr view`, or the `pull_request_*` tools when listed).
2. Classify each red check / comment:
   - **Real failure** (CI, Test, Build, Security Audit, Kilo inline findings on the current head SHA) → fix.
   - **Non-blocking noise** → note and skip (see Guardrails).
3. Fix the root cause (not the symptom). Keep commits small, conventional-commit format, no plan/finding codes in code comments.
4. Verify before pushing: lint, Prettier on every changed `.js/.cjs/.ts/.tsx`, `npm run test-only`; for `.github/workflows/**` changes also `cd .github/workflows && node --test scripts/__tests__/*.test.cjs` and update `docs/workflow-e2e-scenarios.md` if behavior changed.
5. Push, then wait for the next CI/review event instead of polling: where the T3 tools exist, start the watch once with `watch_pull_request` and end your turn (it wakes you on changes); otherwise re-check with `rtk gh pr checks`. Re-check that results are for the **current head SHA**.
6. Repeat until all required checks and `pr-flow/ready` pass. Then, if you started a watch, call `unwatch_pull_request`, and report the final state (head SHA, check counts).

### Guardrails

- Local Windows runs fail some tests before any change (CRLF: Prisma safe-SQL guard, upsertComment, formatDate, etc.). Treat Linux CI as the source of truth; report local failures honestly, do not "fix" them.
- Non-blockers: github-actions "Large PR" notice, Mergify queue checkbox, Build Performance comment without baseline, PR Improve suggestions (they go to a separate planning PR, e.g. #1237).
- Kilo findings: fix only those on the current head; a Kilo inline note about a non-blocking suggestion may be left with a stated reason.
- Never commit `.qwen/`, `prisma/*.broken*`, `prisma/dev.db.backup-*`, `graphify-out/`, or dotenv files.
- Do not force-push; do not bypass hooks.

### Sub-agent mode

When the task came from a parent agent ("Round N on PR #…", "fix on the same branch, push, do not merge/watch"):

- Fix only the listed findings on the same branch and push; do not merge, do not call `watch_pull_request`, do not rebase onto bot commits.
- Answer each finding as `fixed (commit)` or `not applicable (reason)`; skip step 6 (`unwatch`).
- Report to the parent in the form Status / Summary / Concerns, with the head SHA you pushed.
