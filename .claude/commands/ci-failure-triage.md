## Context

Failed job: $ARGUMENTS (URL like `.../actions/runs/<run>/job/<job>?pr=<n>`).

## Your Task

Diagnose and propose options. Diagnosis only: make no file edits, commits or pushes unless the user then picks an option.

### Steps

1. Get the status/conclusion rollup first: `rtk gh run view <run> --json status,conclusion,jobs`.
2. Pull only the failing part: `rtk gh run view <run> --job <job> --log-failed`, grep for the first real error (not the cascade).
3. Check whether the same failure exists on `main` / other PRs (flaky vs introduced vs infra, e.g. rate limit, runner disk, Dependabot/permissions).
4. Report: root cause with `file:line` or log evidence, confidence, and 2-3 fix options with trade-offs and a recommendation.

### Guardrails

- Do not dump full logs; quote only the decisive lines.
- Distinguish a code failure from a workflow/infra failure (GitHub API rate limits, missing secrets on fork PRs, etc.).
- For several URLs ("same"), apply the same procedure to each and note common causes.
