## Context

Many agent worktrees accumulate under `~/.t3/worktrees/amnezia-control-panel/` and `.claude/worktrees/`. Arguments: $ARGUMENTS (`--clean` means propose deletions; without it, report only).

## Your Task

### Steps

1. `rtk git fetch --prune origin`, then fast-forward local `main` only in the worktree where `main` is checked out and clean (`git -C <that-worktree> pull --ff-only`, found via `git worktree list`). If `main` is not checked out anywhere, or you are in another worktree, skip the pull; never run it on a PR branch or switch another worktree's branch.
2. List worktrees: `rtk git worktree list --porcelain`. The `branch` line holds a full ref (`refs/heads/NAME`): strip `refs/heads/` to get the short name `<branch>`; a worktree with no `branch` line is detached and goes straight to **Unknown**. For each one report: path, branch, last commit date, ahead/behind of `origin/main`, uncommitted changes (`git -C <worktree-path> status --short`, run per worktree, never in the current directory), and whether its branch is merged or has an open/closed PR (`rtk gh pr list --head <branch> --state all --json number,state,mergedAt,headRefOid`; `state` is OPEN, MERGED or CLOSED).
3. Classify:
   - **Stale**: PR merged, or branch already merged into `origin/main`; clean tree, nothing unpushed.
   - **Active**: open PR, or dirty tree, or unpushed commits.
   - **Unknown**: no PR and not merged, or PR closed without merging — do not touch; report them so the user decides (`git branch -d` would refuse them anyway).
4. Show the table first. With `--clean`, ask the user to confirm the exact list of **Stale** worktrees, then remove them with `git worktree remove <path>` (no `--force`) and delete their local branches with `git branch -d`. PRs here land as merge commits or squashes, and `git branch -d` can refuse a squash-merged branch (it has no ancestry in the target). If it refuses, delete with `git branch -D` only when the PR `state` is MERGED and the local branch tip equals the PR `headRefOid`; otherwise report the branch and skip it.

### Guardrails

- Never remove a worktree with uncommitted changes, unpushed commits, or an open PR; never use `--force`.
- Never remove the main checkout or the worktree you are running in.
- Remote branches are out of scope; do not delete them.
- Do not touch the `git stash` stack; it is shared across worktrees.
