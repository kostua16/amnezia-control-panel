## Context

Request: $ARGUMENTS. Parent thread delegates one bounded task to a sub-agent. The sub-agent starts with no history, so the brief must stand alone. Each new review or re-check is a new delegation, not a follow-up to an old one (except `round`, which continues the same implementer).

## Your Task

Produce the brief text (and pass it to `delegate_task` if the user asked to start the run). Pick the template by kind, fill the placeholders from real facts (PR head SHA, issue number, paths) after checking them, and keep it under ~40 lines.

### Common header (all kinds)

```
Act as the <review|implementation|research> sub-agent for this task.

Repo: kostua16/amnezia-control-panel. Work context: <git root>. Reports: <root>/plans/reports/. Plans: <root>/plans/.
Goal: <one sentence>.
Files to read first: <list>. Files you may modify: <list or "none">.
Acceptance criteria: <list>.
Report back to the parent only, in the format: Status (DONE | DONE_WITH_CONCERNS | BLOCKED | NEEDS_CONTEXT), Summary, Concerns.
```

### review

- Read-only: no edits, commits, pushes, or comments on GitHub. Shared checkout is fine.
- Name the head SHA and the issue/PR; list focus areas (repo standards in `docs/code-standards.md`, correctness, test gaps, rebase impact).
- Ask for findings with `file:line` and severity, and for evidence, not impressions.

### implementation

- Work in a fresh git worktree off `origin/main`; one branch, one PR; Conventional Commits; no plan/finding codes in code comments.
- Verify before reporting: lint, Prettier on changed `.js/.cjs/.ts/.tsx`, `npm run test-only`; for `.github/**` changes also `cd .github/workflows && node --test scripts/__tests__/*.test.cjs` and `docs/workflow-e2e-scenarios.md`.
- State merge policy explicitly: "do not merge, do not watch" unless the user said otherwise.
- Never commit `.qwen/`, `prisma/*.broken*`, `prisma/dev.db.backup-*`, `graphify-out/`, dotenv files.

### research

- Read-only; write temp files only under the scratchpad, never in the repo.
- Say which data sources are allowed (e.g. logs, `rtk gh`), and what must not be called (GitHub write APIs).
- Ask for numbers with the method used and the limits of the method.

### round (follow-up on the same PR)

```
Round <N> on PR #<n> (head <sha>). <check name> fails with <k> findings.
Read the latest bot issue comment and the inline comments on <sha>: <exact command>.
Fix on the same branch, push. Do not merge, do not watch. Do not rebase onto bot commits.
Reply per finding: fixed (commit) | not applicable (reason).
```

### Guardrails

- Verify facts (PR number, head SHA, paths) with a command before writing them into a brief.
- Do not paste the parent's conversation; summarize decisions in 3-5 lines.
- Do not include secrets or tokens.
- Call `orchestrator_capabilities` once per thread before the first `delegate_task`; use only the models the user named.
