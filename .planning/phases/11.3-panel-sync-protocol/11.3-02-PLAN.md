Add the following model to `prisma/schema.prisma`, after the PanelConnectionHistory model:

```prisma
// ─── CachedPanelConfig ─────────────────────────────────

model CachedPanelConfig {
  id            Int      @id @default(autoincrement())
  /** Remote panel ID this config belongs to (null = this panel's own cached config) */
  panelId       Int?
  /** Monotonically increasing config version from central */
  configVersion Int
  /** The full config JSON payload */
  config        Json
  /** ISO timestamp when this config was received */
  receivedAt    DateTime @default(now())

  @@unique([panelId])
  @@map("cached_panel_configs")
}
```

Design decisions per CONTEXT.md:
- Single row per panel: `@@unique([panelId])` ensures upsert semantics
- `configVersion` as Int (simple incrementing counter per CONTEXT.md decision)
- `config` as Json (stores full PanelSyncPayload)
- `panelId` is nullable because on a remote panel, the config is "for this panel" -- panelId references the central panel's ID for the remote panel entry. Use panelId = null for the local panel's own config, or use a sentinel value. Per Claude's discretion: use `panelId Int?` with `@@unique([panelId])` where null means "this panel's config".

**File 2: src/app/api/sync/receive/route.ts**

Create POST endpoint implementing the full receive flow:

1. **Extract headers**: Read `X-API-Key` and `X-Signature` from request headers

2. **Auth check**: Find the RemotePanel by matching the API key against `apiKeyHash` using `bcrypt.compare(requestApiKey, panel.apiKeyHash)`. If no panel matches or key is invalid, return 401: `{ success: false, error: "Invalid API key" }`

3. **Idempotency check**: Query CachedPanelConfig where `panelId` matches. If found AND `cachedConfig.configVersion === payload.configVersion`, skip write and return 200: `{ success: true, data: { applied: true, configVersion, message: "Config already applied (idempotent)" } }`

4. **Zod validation**: Validate the request body with this schema:
```typescript
const panelSyncPayloadSchema = z.object({
  configVersion: z.number().int().positive(),
  panelRole: z.enum(['entry', 'middle', 'exit', 'domestic', 'foreign']),
  chainNodes: z.array(z.object({
    label: z.string(),
    serverId: z.number().int(),
    role: z.enum(['entry', 'middle', 'exit', 'domestic', 'foreign']),
    protocol: z.enum(['wireguard', 'xray']),
    hostname: z.string(),
    port: z.number().int(),
  })),
  routingRules: z.array(z.object({
    type: z.enum(['ip', 'domain', 'geoip']),
    value: z.string(),
    outboundTag: z.string(),
    priority: z.number().int(),
  })),
  wireguardPeers: z.array(z.object({
    publicKey: z.string(),
    allowedIPs: z.string(),
    endpoint: z.string(),
    persistentKeepalive: z.number().int().optional(),
  })),
  generatedAt: z.string().datetime({ offset: true }).or(z.string().min(1)),
});
```
If validation fails, return 400: `{ success: false, error: "Invalid payload: {first Zod error message}" }`

5. **HMAC verification**: Call `verifySignature(body, apiKey, signature)` from `src/lib/hmac.ts`. If signature does not match, return 401: `{ success: false, error: "Invalid signature" }`

   NOTE: `verifySignature` expects the raw payload object (not stringified). Import it from `@/lib/hmac`. If the file does not exist yet (11.3-01 not completed), create a minimal version:
   ```typescript
   import { createHmac, timingSafeEqual } from 'crypto';
   export function verifySignature(payload: unknown, secret: string, signature: string): boolean {
     const expected = createHmac('sha256', secret).update(JSON.stringify(payload)).digest('hex');
     try { return timingSafeEqual(Buffer.from(expected, 'hex'), Buffer.from(signature, 'hex')); } catch { return false; }
   }
   ```

6. **Store config**: Upsert to CachedPanelConfig:
```typescript
await prisma.cachedPanelConfig.upsert({
  where: { panelId_panelId: panel.id }, // SQLite unique constraint name
  update: {
    configVersion: parsed.configVersion,
    config: parsed.data, // the raw payload object
    receivedAt: new Date(),
  },
  create: {
    panelId: panel.id,
    configVersion: parsed.configVersion,
    config: parsed.data,
    receivedAt: new Date(),
  },
});
```

IMPORTANT: Prisma SQLite generates unique constraint names differently. The upsert `where` clause for a `@@unique([panelId])` with nullable field uses `panelId` directly if it is non-null. Since panelId references the RemotePanel ID (always a valid integer), the `where` clause should be:
```typescript
where: { panelId: panel.id }
```
If this fails at runtime, fall back to querying first then create/update:
```typescript
const existing = await prisma.cachedPanelConfig.findUnique({ where: { panelId: panel.id } });
if (existing) {
  await prisma.cachedPanelConfig.update({ where: { id: existing.id }, data: { ... } });
} else {
  await prisma.cachedPanelConfig.create({ data: { panelId: panel.id, ... } });
}
```

7. **Return success**: 200: `{ success: true, data: { applied: true, configVersion: parsed.data.configVersion } }`

8. **Error handling**: Wrap in try/catch. On unexpected errors, log and return 500: `{ success: false, error: "Failed to process sync" }`
