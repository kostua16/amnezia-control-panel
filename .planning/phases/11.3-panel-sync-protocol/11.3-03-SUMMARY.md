## Accomplishments
- Health checker extended with fallback detection (3 consecutive failures triggers fallback mode)
- WebSocket event `panel:fallback-change` emitted on fallback enter and exit
- Auto-resync triggered automatically when a panel reconnects after fallback
- POST /api/panels/push endpoint triggers config push to all active panels
- GET /api/sync/status endpoint returns cached config and fallback state

## Files Created/Modified
- `src/lib/panel-health-checker.ts` - Added fallback detection (consecutiveFailures Map, fallbackPanels Set), auto-resync (triggerAutoResync with dynamic import), API key cache (panelApiKeyCache), and exported query functions (isPanelInFallback, getFallbackPanels, cachePanelApiKey, removePanelApiKey)
- `src/lib/websocket.ts` - Added `panel:fallback-change` to WsEventType union
- `src/app/api/panels/push/route.ts` - POST endpoint accepting chainConfig + panelApiKeys with Zod validation, caches keys for auto-resync, calls pushConfigToAllPanels
- `src/app/api/sync/status/route.ts` - GET endpoint returning cached config, configVersion, receivedAt, and inFallback status with optional panelId query param

## Decisions Made
- API keys stored in volatile memory only (Map) -- never persisted to DB or logs. Acceptable risk per T-11.3-12 (memory is volatile, keys survive only as long as process runs)
- Dynamic import of panel-sync-client in triggerAutoResync to avoid circular dependency between health checker and sync client
