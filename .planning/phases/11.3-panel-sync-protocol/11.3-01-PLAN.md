**File 2: src/lib/hmac.ts**

Create HMAC-SHA256 signing and verification using Node.js built-in `crypto` module (no external deps):

```typescript
import { createHmac, timingSafeEqual } from 'crypto';

/**
 * Sign a JSON payload with HMAC-SHA256.
 * payload is stringified internally to ensure deterministic input.
 */
export function signPayload(payload: unknown, secret: string): string {
  const data = JSON.stringify(payload);
  return createHmac('sha256', secret).update(data).digest('hex');
}

/**
 * Verify an HMAC-SHA256 signature using timing-safe comparison.
 * Returns true if the signature matches the payload+secret.
 */
export function verifySignature(payload: unknown, secret: string, signature: string): boolean {
  const expected = signPayload(payload, secret);
  try {
    return timingSafeEqual(
      Buffer.from(expected, 'hex'),
      Buffer.from(signature, 'hex'),
    );
  } catch {
    return false;
  }
}
```

**File 3: src/lib/panel-sync-client.ts**

Create the PanelSyncClient module with these exported functions:

1. **`generatePerPanelConfig(chainConfig: ChainConfig, panelId: number): PanelSyncPayload | null`**
   - Iterates `chainConfig.nodes` to find which node has `serverId === panelId`
   - If no matching node, return null (this panel has no role in the chain)
   - Set `panelRole` from the matched node's `role` field
   - Include ALL `chainNodes` from the chain (the remote panel needs the full topology for routing decisions)
   - Filter `routingRules` to only those where `xrayRoutingRule.nodeId` matches any node label in chainConfig
   - Filter `wireguardPeers` to only those where `wireguardPeer.nodeId` matches the matched node's label
   - Use `configVersion: 0` as placeholder (real version from central-side counter is used at push time)

2. **`pushConfigToPanel(panel: { id: number; name: string; panelUrl: string; apiKey: string }, payload: PanelSyncPayload): Promise<PushResult>`**
   - Build target URL: `${panel.panelUrl}/api/sync/receive`
   - Sign payload with `signPayload(payload, panel.apiKey)` from hmac.ts
   - POST with `Content-Type: application/json`
   - Headers: `X-API-Key: ${panel.apiKey}`, `X-Signature: ${signature}`
   - Body: JSON.stringify(payload)
   - Timeout: `AbortSignal.timeout(15000)` (15s per CONTEXT.md decision)
   - Retry logic: on failure, retry up to 3 times total with delays [1000, 2000, 4000]ms (exponential backoff)
   - On 200 response with `{ applied: true, configVersion: N }`: return success PushResult
   - On non-200 or network error after retries: return failed PushResult with error message
   - Track `retries` count in PushResult

3. **`pushConfigToAllPanels(chainConfig: ChainConfig, panelApiKeys: Map<number, string>): Promise<PushAllResult>`**
   - Fetch all active remote panels from DB: `prisma.remotePanel.findMany({ where: { isActive: true } })`
   - For each panel, call `generatePerPanelConfig(chainConfig, panel.id)` -- skip panels with no role (null result)
   - For panels with a config, call `pushConfigToPanel` sequentially (per CONTEXT.md decision: sequential push, 1-3 panels)
   - Increment configVersion starting from 1 for the first panel in this push batch
   - Collect all PushResults into PushAllResult
   - Set `pushedAt: new Date().toISOString()`
