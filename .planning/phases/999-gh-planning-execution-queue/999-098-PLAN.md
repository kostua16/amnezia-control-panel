# Quick Plan: PR #692 workflow improvement intake

## Source
- PR #692: fix: partial #680 - [todo-backlog] security-audit-weekly: optimize/audit review backlog (SEC)
- URL: https://github.com/kostua16/amnezia-control-panel/pull/692

## Summary
PR #692 adds 'persist-credentials: false' to 'actions/checkout' in 'security-audit-weekly.yml' — credential hygiene preventing GITHUB_TOKEN retention in runner git config. Correct but only 1 of 22 truly read-only workflows. 21 remain unprotected.

## Quick Wins
- Add persist-credentials: false to remaining 21 read-only workflows -- These 21 workflows all have 'contents: read' with zero 'contents: write' jobs. Leaving credentials persisted on runners that only read/audit is unnecessary attack surface. (owner: claude, type: quick-task)
- Add e2e test asserting persist-credentials:false on all contents:read workflows -- Without a test, the same class of drift will recur. The existing e2e suite already validates checkout ordering; this extends it to credential hygiene. (owner: claude, type: quick-task)

## pr692.x Phase Candidates
- pr692.2: Workflow checkout-hardening lint policy -- Create a CI pre-merge check that scans all workflow YAMLs for 'actions/checkout@' steps missing 'persist-credentials: false' when the job declares 'contents: read'. Flags at merge time rather than in post-hoc security reviews. (owner: claude)
- pr692.1: Least-privilege credential policy for self-hosted runners -- Formalize a repo-level policy: all workflows on self-hosted runners must set 'persist-credentials: false' unless the job explicitly needs git push. Document in policy.json or ADR. Self-hosted runners are shared resources — a leaked credential from persisted git config is exploitable if the runner is compromised. (owner: claude)
