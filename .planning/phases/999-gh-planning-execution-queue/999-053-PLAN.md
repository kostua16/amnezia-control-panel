# Quick Task 260605-67p: Implement maintainer-approved label and /approve command for PR flow

## Goal

Add `maintainer-approved` as a head-scoped final human approval signal for same-repo pull requests. Maintainer approval should override only manual-only/manual-review gating, while preserving draft, required-check, hard-blocker, and review-signal gates before auto-merge.

## Implementation Tasks

1. Add policy/config support for the `maintainer-approved` label and reset it on head-changing PR events.
2. Update PR policy and orchestration decisions so approved manual-only PRs proceed through normal checks, workers, and finalizer dispatch.
3. Update the finalizer to treat maintainer approval as final human approval without bypassing same-repo, required-check, hard-blocker, or review-label requirements.
4. Add `/approve` PR comment handling with maintainer-only trigger gating, label application, acknowledgement, and normal orchestrator execution.
5. Add targeted tests for policy output, orchestration decisions, trigger gating, and workflow invariants.
6. Run npm tests, lint, targeted Prettier checks, and actionlint for touched workflows.

## Acceptance Criteria

- `maintainer-approved` is available as a workflow label and removed on PR head changes.
- Labeling a PR with `maintainer-approved` reruns PR orchestration via existing label triggers.
- A maintainer PR comment containing standalone `/approve` applies `maintainer-approved` and runs PR orchestration.
- Approval overrides manual-only/manual-review only; hard blockers, draft status, pending/failing checks, missing review labels, and same-repo restrictions still apply.
