# Quick Task 260520-ghw: GitHub workflows audit and automation roadmap

## Goal

Review the current GitHub Actions setup, identify concrete correctness and security issues, and outline an implementation roadmap for safer automation, PR approval/merge policy, and Claude+GSD planning flows.

## Findings To Address

### 1. Privileged automation trust boundary
- **files**: `.github/workflows/claude.yml`, `.github/workflows/fix-pr.yml`, `.github/workflows/fix-branch.yml`, `.github/workflows/fix-issue.yml`, `.github/workflows/issue-catch-up.yml`
- **action**: Add explicit trust gates before any workflow that can write code, approve PRs, push branches, or use long-lived secrets.
- **verify**: Only trusted actors, trusted branches, or trusted labels can trigger write-capable flows.

### 2. Workflow correctness gaps
- **files**: `.github/actions/commit-and-push/action.yml`, `.github/workflows/perf-check.yml`, `.github/workflows/dependency-review.yml`, `.github/workflows/release-notes.yml`, `.github/workflows/code-review.yml`, `.github/workflows/triage.yml`
- **action**: Fix silent failures, impossible prompts, conflicting review behavior, and stale documentation/secrets assumptions.
- **verify**: Each workflow can complete its stated task with the tools it is granted, and failures stop the pipeline instead of being hidden.

### 3. Supply-chain hardening
- **files**: `.github/actions/setup-environment/action.yml`, third-party `uses:` references across `.github/workflows/` and `.github/actions/`
- **action**: Pin mutable downloads and external actions to immutable versions/SHAs where practical; replace `GH_PAT` with a GitHub App installation token where possible.
- **verify**: No critical workflow depends on `@latest`, `master`, or `curl | sh` without pinning and review.

### 4. PR governance automation
- **files**: new reusable/finalizer workflow(s), likely `.github/workflows/pr-governance.yml`
- **action**: Separate “review verdict”, “approval”, and “merge enablement” into distinct states with a single authority flow.
- **verify**: PRs are only approved or auto-merged after required checks, required review state, and explicit trust conditions are satisfied.

### 5. Claude + GSD planning extensions
- **files**: new workflow(s) plus `.planning/` integration points
- **action**: Add a non-writing recommendation flow that opens or updates planning artifacts instead of making code changes directly.
- **verify**: Suggestions become auditable `.planning` artifacts or draft issues/PR comments, not silent edits.

## Recommended Execution Order

### Phase A. Safety and credentials
- Disable or heavily gate `claude.yml` for public/untrusted actors.
- Gate `fix-pr.yml` / `fix-branch.yml` / `fix-issue.yml` behind trusted-author checks or manual labels.
- Replace `GH_PAT` with a GitHub App token wherever push/comment scopes are needed.
- Pin `get-shit-done-cc` and RTK installation sources.

### Phase B. Fix broken or misleading flows
- Make `commit-and-push` fail hard after the final failed push attempt.
- Add `set -o pipefail` to `perf-check.yml` build steps.
- Rewrite prompts in `dependency-review.yml` and `release-notes.yml` so the agent can actually perform the requested work with its allowed tools.
- Split code review verdicting from inline comment generation so only one workflow/job owns formal PR review state.
- Align workflow docs with reality, especially required secrets and copied local actions.

### Phase C. PR automation policy
- Prefer auto-merge over blind auto-approval for trusted bot PRs.
- If approval is required, use a dedicated bot identity or GitHub App distinct from the PR authoring identity.
- Make approval contingent on:
  - `CI` success
  - code-review pass
  - security-review pass
  - no `needs-review` / `ai-review-concerns` / `do-not-merge` labels
  - trusted PR source

### Phase D. Claude + GSD suggestions
- Add a PR comment workflow that runs on demand (`/improve`, label, or manual dispatch).
- Scope it to planning only:
  - review changed files
  - produce a markdown improvement report
  - create or update `.planning/quick/...` or a dedicated `.planning/phases/...` artifact
  - optionally open a tracking issue with proposed milestone/phase additions
- Add a second, explicit human-approved follow-up flow to transform accepted suggestions into `/gsd-plan-phase` or `/gsd-new-milestone` work.

## Options For PR Approval / Merge

### Option 1. Conservative
- AI review leaves labels/comments only.
- Human keeps approval responsibility.
- Workflow enables auto-merge for trusted PRs after required human approval and green checks.

### Option 2. Bot approval for trusted bot-authored PRs
- Enable the repository setting that allows GitHub Actions to create and approve pull requests.
- Use a dedicated bot/App token for approval.
- Restrict to PRs opened by your automation branches only.

### Option 3. Two-bot separation
- Bot A opens the fix PR.
- Bot B performs the final approval after checks pass.
- Best fit if you want stronger separation of duties.

## Claude + GSD Extension Pattern

### Improvement suggester flow
- **trigger**: `/improve`, `workflow_dispatch`, or `planning-needed` label on a PR/issue
- **inputs**: PR number or issue number, optional scope
- **behavior**:
  - run Claude in read-only/planning mode
  - summarize risks, technical debt, and candidate improvements
  - emit:
    - PR comment summary
    - `.planning/quick/...` plan for small work, or
    - `.planning/phases/...` phase stub for milestone-scale work

### Milestone / phase enricher flow
- **trigger**: maintainer applies `accepted-improvement`
- **behavior**:
  - map accepted suggestions to milestone/phase entries
  - update `.planning/ROADMAP.md`
  - create phase folder scaffold with `PLAN.md` / `CONTEXT.md`
  - optionally open a draft PR for human review
