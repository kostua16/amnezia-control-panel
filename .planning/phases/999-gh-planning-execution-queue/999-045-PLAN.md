# Quick Plan: PR #182 workflow improvement intake

## Source
- PR #182: fix(audit): address autonomous audit findings
- URL: https://github.com/kostua16/amnezia-control-panel/pull/182

## Summary
PR #182 fixes $queryRawUnsafe in the users traffic route, adds 3 lib test files (api-response, format, hmac). One $queryRawUnsafe remains in the main traffic route due to dynamic SQL. Suggestions map to: quick follow-ups (remaining SQL fix, traffic route tests, test coverage gaps) and phase 13.x milestones (CI test isolation, release-note generation from PR labels, audit-safe policy expansion, PR analysis automation).

## Quick Wins
- Convert remaining $queryRawUnsafe in traffic/route.ts to safe $queryRaw -- src/app/api/stats/traffic/route.ts:74 still uses $queryRawUnsafe with dynamic truncExpr/whereClause. The comment says 'server-controlled' but the route accepts user input via query params (period, serverId). Refactor to use Prisma.sql with Prisma.join for the dynamic parts, or extract the dynamic SQL builder into a tested helper with explicit parameter binding. (owner: developer, type: quick-task)
- Add integration tests for /api/stats/traffic and /api/stats/traffic/users endpoints -- PR #182 added lib-level tests but the actual route handlers (which had the SQL injection) have zero test coverage. The users route now uses $queryRaw with tagged template interpolation — a test should verify the parameterized query works correctly with real-ish data and that invalid inputs are rejected by the Zod schema. (owner: developer, type: quick-task)
- Add negative test cases to hmac.test.ts for timing-attack resistance -- The existing verifySignature tests check correctness but don't test for timing-safe comparison. The HMAC module uses crypto.timingSafeEqual in verifySignature — add a test confirming that verification of wrong-length signatures doesn't throw (returns false gracefully) and that the function handles Buffer allocation edge cases. (owner: developer, type: quick-task)
- Expand policy.json auditSafe.allowedPathGlobs with newly tested modules -- PR #182 added tests for api-response.ts, format.ts, and hmac.ts. format.ts is not listed in auditSafe.allowedPathGlobs (only api-response.ts is). hmac.ts is correctly in manualOnlyPathGlobs (security-sensitive). Consider adding format.ts to allowedPathGlobs since it's pure utility with test coverage. (owner: developer, type: quick-task)

## 13.x Phase Candidates
- 13.2: Add CI gate that fails on $queryRawUnsafe usage -- PR #182 manually found and fixed one $queryRawUnsafe but another remains. Add a grep-based CI step (or ESLint custom rule) that fails the build if $queryRawUnsafe appears anywhere in src/, forcing all raw SQL through Prisma's tagged template $queryRaw. This prevents regressions and catches new unsafe SQL in PRs automatically. (owner: CI pipeline)
- 13.2: Decouple test job from lint+typecheck in CI for faster feedback -- Current ci.yml gates the test job behind lint+typecheck. PR #182's new tests (173 lines) won't even run if lint fails for an unrelated reason. Run test in parallel with lint/typecheck to surface test failures faster and avoid masking regressions behind unrelated lint issues. (owner: CI pipeline)
- 13.3: Auto-label PRs that add tests for audit-manual-only modules -- PR #182 added hmac.test.ts — hmac.ts is in manualOnlyPathGlobs. The PR finalizer should detect when a PR touches test files for security-sensitive modules and apply a 'security-review-concerns' or informational label so maintainers are aware, even if the test file itself is safe. (owner: PR automation)
- 13.4: Automate PR analysis → roadmap intake for audit remediation PRs -- This analysis task (PR #182 → follow-up suggestions) is exactly the pattern Phase 13.4 describes. Build the automation that: (1) reads a PR diff from a trusted branch, (2) classifies findings into quick-task vs phase buckets, (3) appends to the ROADMAP.md intake section. This PR is a test case for that automation. (owner: planning automation)
