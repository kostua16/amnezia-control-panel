# Quick Plan: PR #181 workflow improvement intake

## Source
- PR #181: fix(workflows): harden planning PR helper output
- URL: https://github.com/kostua16/amnezia-control-panel/pull/181

## Summary
PR #181 fixes a null-pointer crash in upsert-planning-pr.cjs by refactoring the run() helper and wrapping the script in a testable main() export with 5 unit tests. The fix is narrow and correct. Follow-ups fall into two categories: expanding test coverage for the untested helper functions, and hardening the planning automation pipeline against edge cases in JSON validation, markdown injection, stale planning PR lifecycle, and cross-directory test conventions.

## Quick Wins
- Add unit tests for upsert-planning-pr render and markdown helpers -- Only run() and dry-run CLI are tested; renderQuickPlan, renderQuickSummary, buildPhaseBlock, upsertSingleLineEntry, upsertNamedBlock, collectTrackedPaths, and the non-dry-run main() path have zero coverage. A malformed suggestions JSON (e.g., missing title/rationale fields) would silently produce broken PLAN.md content. (owner: maintainer, type: quick-task)
- Validate required fields in each quick_task and phase_suggestion entry -- upsert-planning-pr.cjs filters phase_suggestions by known phase numbers but never checks that individual items have title, rationale, or owner. Claude's structured output could omit a field, producing `undefined` in rendered markdown. (owner: maintainer, type: quick-task)
- Sanitize suggestion text for markdown injection in PLAN.md and phase blocks -- escapeInline only collapses whitespace. PR titles and suggestion rationale containing backticks, HTML comments, or markdown links would be rendered verbatim into tracked planning files, potentially breaking marker-based upsert logic or confusing reviewers. (owner: maintainer, type: quick-task)
- Document the cross-directory test convention for workflow scripts -- Tests live in src/lib/__tests__/ but test .github/workflows/scripts/upsert-planning-pr.cjs via createRequire. This is fragile if the script moves or the test runner changes. A brief convention note in docs/ or a README in .github/workflows/scripts/ would prevent confusion. (owner: maintainer, type: quick-task)
- Add stale debug doc cleanup to maintenance workflow -- PR #181 adds .planning/debug/gh-issue-178-pr-improve.md with status:resolved. No workflow garbage-collects resolved debug docs. Over time these accumulate. A quick task or maintenance.yml addition could prune entries older than N days with status:resolved. (owner: maintainer, type: workflow-improvement)

## pr181.x Phase Candidates
- pr181.1: Formalize stdout-isolation trust gate for JSON-emitting workflow scripts -- PR #181's core fix routes capture:false child stdout to stderr so it cannot corrupt JSON on stdout. This pattern should be a codified trust gate: any script whose stdout is consumed as structured data (upsert-planning-pr.cjs, evaluate-pr-policy.cjs, resolve-pr-context.cjs) must guarantee child commands never reach stdout. Currently only upsert-planning-pr.cjs enforces this; the other scripts use console.log/error inconsistently. (owner: maintainer)
- pr181.2: Pin action refs to SHA and add workflow script test gate to ci.yml -- pr-improve.yml uses actions/checkout@v5 and actions/github-script@v8 (tag refs, not SHAs). The new tests in src/lib/__tests__/upsert-planning-pr.test.ts run under npm test, but ci.yml should explicitly gate workflow script changes with a targeted test run and actionlint, preventing regressions like the one PR #181 fixes. (owner: maintainer)
- pr181.3: Add planning-draft-reviewed label and stale planning PR auto-close -- Planning PRs get planning-draft-open but there is no signal when a maintainer has reviewed and accepted/rejected the suggestions. Additionally, if PR Improve runs on the daily cron, it force-pushes the planning branch each time (via --force-with-lease), potentially overwriting maintainer edits. A planning-draft-reviewed label and a stale-PR timer would give maintainers control without losing edits. (owner: maintainer)
- pr181.4: Add structured metadata and rollback for phase plan injection -- upsert-planning-pr.cjs injects PR-IMPROVE blocks into pr181.x phase plans using HTML comment markers, but there is no structured index of which PRs contributed which blocks, and no rollback command to cleanly remove all artifacts for a given source PR. A metadata sidecar file (e.g., .planning/quick/YYMMDD-prN-META.json) and a --cleanup-pr-number flag would make the planning intake reversible and auditable. (owner: maintainer)
