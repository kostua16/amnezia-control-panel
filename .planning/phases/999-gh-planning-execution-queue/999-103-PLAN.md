# Quick Plan: PR #719 workflow improvement intake

## Source
- PR #719: fix: resolve #714 - APR-E01: Weekly human-disposition digest issue (audit-auto-prs)
- URL: https://github.com/kostua16/amnezia-control-panel/pull/719

## Summary
PR #719 adds a publish-digest job to audit-auto-prs that upserts a GitHub issue with human-disposition findings. The new script introduces its own escapeCell/escapeListItem helpers that duplicate patterns already in render-claude-report.cjs and upsert-planning-pr.cjs. No shared markdown-safety utility exists, leading to drift risk across the 50+ workflow scripts.

## Quick Wins
- Extract shared md-escape helpers into a common module -- DRY — three independent escape functions with subtly different coverage is a maintenance hazard. A shared module ensures consistent sanitization as more digest/report scripts are added. (owner: workflow-infrastructure, type: quick-task)
- Add test coverage for the no-op empty-output path in publish-digest -- The no-op paths are the most common runtime case (most audit runs produce no human dispositions). Untested no-op paths are where regressions hide. (owner: workflow-infrastructure, type: quick-task)
- Gate publish-digest job on structured_output being non-empty -- Most audit runs produce no human dispositions. Skipping the unnecessary checkout + setup saves self-hosted runner capacity. (owner: workflow-infrastructure, type: quick-task)

## pr719.x Phase Candidates
- pr719.1: Centralize agent-output sanitization policy for all workflow scripts -- As more workflows emit structured agent output to GitHub artifacts, inconsistent sanitization becomes a systemic injection risk. A governance-level policy with a shared module and CI enforcement prevents each new script from reinventing its own escape logic. (owner: workflow-governance)
- pr719.2: Add structured_output passthrough validation in audit-auto-prs workflow outputs -- Silent no-op is safe but opaque. A CI-level validation step makes it visible in the Actions UI whether the digest was skipped due to no dispositions vs. malformed output, improving debuggability. (owner: ci-correctness)
