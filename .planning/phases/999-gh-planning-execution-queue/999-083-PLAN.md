## Summary
PR #596 adds a missing 'actions/checkout' step before the 'fix' job's "Resolve PR head and eligibility" step in '.github/workflows/fix-review.yml'. Without it, 'evaluate-fix-review-eligibility.cjs' and 'policy.json' didn't exist on disk, causing silent failures. The fix is correct but the root cause (missing checkout before script execution) could recur in other workflows.

## Quick Wins
- Add e2e structural invariant: checkout-before-node-script -- The 'fix' job in 'fix-review.yml' ran 'node .github/workflows/scripts/evaluate-fix-review-eligibility.cjs' without a prior 'actions/checkout'. No e2e test caught this. An e2e scenario in 'e2e-autonomous-pr.test.cjs' (or a new dedicated file) should parse all workflow YAMLs and assert: every job step that runs 'node .github/workflows/scripts/' must have a preceding 'uses: actions/checkout@' step in the same job. This prevents recurrence across all 20+ workflow files. (owner: gh-workflow-engineer, type: quick-task)
- Annotate dual-checkout intent in fix-review.yml fix job -- The 'fix' job now has two 'actions/checkout' steps: line 102 (new, default branch for scripts/policy) and line 170 (existing, PR head ref for code changes). Without a comment explaining why both exist, a future maintainer may remove the first one thinking it's redundant. Add a brief step name like 'name: Checkout (default branch — scripts and policy)' to the new checkout at 'fix-review.yml:102'. (owner: gh-workflow-engineer, type: quick-task)

## pr596.x Phase Candidates
- pr596.2: Workflow structural lint: enforce checkout-before-local-script across all jobs -- This PR fixes a latent bug where a job ran local 'node' scripts without checking out the repo. The same pattern could exist in other workflows (e.g., 'audit-auto-prs.yml', 'claude.yml', 'fix-pr.yml' all run 'node .github/workflows/scripts/' steps). A phase could build a structural linter (or extend the existing e2e suite) that parses every workflow YAML, builds a DAG of steps per job, and asserts that any 'run:' step invoking 'node .github/' has an 'actions/checkout@' ancestor in the same job's step sequence. Integrate into 'npm run test-only' so regressions are caught in CI. (owner: gh-workflow-engineer)
