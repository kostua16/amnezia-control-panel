# Quick Plan: PR #720 workflow improvement intake

## Source
- PR #720: fix: resolve #708 - WHO-I05: Lighten the hourly collect job (workflow-health-optimize)

## Summary
PR #720 lightens the hourly collect job by switching from self-hosted to ubuntu-latest and removing the unnecessary setup-environment step. Two quick follow-ups identified: fleet-gate can receive the same treatment, and report-blocked-gate/report-failure are also API-only jobs still consuming self-hosted capacity. One phase suggestion: codify the API-only-vs-local-deps runner selection pattern into workflow governance.

## Quick Wins
- Lightweight fleet-gate runner to match collect-runs -- fleet-gate (workflow-health-optimize.yml:28) still runs on self-hosted but only calls .github/actions/fleet-back-pressure — a pure GitHub API check with no local deps. Same class as collect-runs before this PR. Switch to ubuntu-latest to free self-hosted capacity. (owner: workflow-maintenance, type: quick-task)
- Lightweight report-blocked-gate and report-failure runners -- report-blocked-gate (line 409) only runs gh CLI commands. report-failure (line 444) only calls report-failure action — both use setup-environment solely for GH_TOKEN. gh is pre-installed on ubuntu-latest. Switch both to ubuntu-latest, remove setup-environment from report-blocked-gate (report-failure may keep it if report-failure action requires local node). Verify with test suite. (owner: workflow-maintenance, type: quick-task)
- Pin actions/github-script to a named version tag -- workflow-health-optimize.yml:58 uses actions/github-script@3a2844b7e9c422d3c10d287c895573f7108da1b3 (immutable SHA — good). No action needed here; noting as already correct per repo pinning standards. (owner: none, type: quick-task)

## pr720.x Phase Candidates
- pr720.1: Codify API-only job runner policy: default ubuntu-latest unless local deps required -- PR #720 established the pattern: jobs using only actions/github-script or gh CLI don't need self-hosted. The fleet-gate, collect-runs, report-blocked-gate, and report-failure jobs are all API-only. Add a workflow policy rule (e.g. in .github/policy.json or a shared doc) that new workflow jobs default to ubuntu-latest and must justify self-hosted with a comment naming the required local dependency (node + GSD + Prisma, rtk, etc.). This prevents self-hosted capacity waste and makes the decision auditable. (owner: workflow-governance)
- pr720.2: Add e2e scenario for runner-type switching validation -- The e2e test suite (docs/workflow-e2e-scenarios.md) should cover the invariant: API-only jobs must not pull setup-environment. A new scenario that asserts collect-runs and fleet-gate have no setup-environment step and runs-on != self-hosted would catch regression if someone adds local deps back without updating the runner type. (owner: ci-correctness)
