```markdown
# Quick Task 260609-q9l: Gate PR flow label triggers to relevant labels only

**Date:** 2026-06-09
**Status:** Executing

## Goal

Stop generic PR labels from waking `PR Orchestrator` while preserving the label and lifecycle events that actually affect PR-flow policy or review state.

## Implementation Tasks

1. Confirm the duplicate trigger pattern from exact GitHub run data and identify which label events are causing redundant orchestrator runs.
2. Add a shared PR-flow trigger-policy check that allows normal PR lifecycle events and only label changes that affect orchestration decisions.
3. Update `pr-flow.yml` to evaluate that gate before the expensive setup/orchestration steps.
4. Add regression coverage for the new trigger policy mode and workflow invariants.
5. Run targeted verification: tests, lint, Prettier, and `actionlint`.

## Acceptance Criteria

- Generic labels such as `javascript` or `auto-fix` do not run the expensive PR-flow path on `pull_request_target` label events.
- PR lifecycle events like `opened`, `synchronize`, and `ready_for_review` still run PR flow.
- Relevant orchestration labels like `do-not-merge`, `needs-review`, `skip-improve`, review result labels, and `maintainer-approved` still wake PR flow.
- Workflow/test coverage makes the trigger gate hard to regress.
```
