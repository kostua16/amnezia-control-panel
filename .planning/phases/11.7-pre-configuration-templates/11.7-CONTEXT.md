# Phase 11.7: Pre-Configuration Templates - Context

**Gathered:** 2026-05-01
**Status:** Ready for planning

<domain>
## Phase Boundary

Pre-built templates for VPN protocols (VLESS-REALITY, Hysteria2, TUIC, existing), server configuration presets for common VPS providers/OS, routing rule bundles (geo presets), and chain presets combining topology + protocols + routing rules into a single apply operation. Template gallery page for discovery, modal preview before apply, append-mode for routing presets, and custom template creation via "Save as template". Scope covers requirements TMPL-01 through TMPL-04.

</domain>

<decisions>
## Implementation Decisions

### Template Architecture & Storage
- Extend existing `ConfigTemplate` Prisma model — add `category` field to distinguish protocol/server/routing/chain templates
- Server presets extend existing in-memory `ConfigPreset` array — add new presets for Hetzner, DigitalOcean, Vultr, etc. No new DB model needed
- New `ChainPreset` Prisma model combining ChainTemplate reference + protocol overrides + routing rule bundle reference. Store in SQLite
- No versioning — single latest version per template name. Keep simple at 1-3 server scale

### Template Discovery & Apply UX
- Template gallery page at `/templates` with tabs: Protocols / Server / Routing / Chain
- Apply flow: click template card → modal with preview → "Use this" copies settings into node config form
- Routing preset apply in append mode: adds preset rules below existing custom rules. Admin can reorder after
- Admin can create custom templates via "Save as template" action, stored in DB alongside built-ins

### Chain Presets Content & Extensibility
- 3 built-in chain presets: "Simple Relay" (2-node linear), "Privacy Chain" (3-node entry+middle+exit), "High Performance" (2-node VLESS-REALITY)
- 3 built-in routing bundles: "Russia Direct" (geo:RU direct, rest via chain), "EU Privacy" (EU direct, RU via chain, block ads), "Full Tunnel" (all via chain exit)
- Built-in templates are read-only — admin forks to customize (copy pattern), originals stay untouched

### Claude's Discretion
- Exact Prisma schema fields for ChainPreset model
- Template gallery page layout and component structure
- Modal preview content format
- "Save as template" UX flow details

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `ConfigTemplate` Prisma model + CRUD (src/lib/config-templates.ts) — getTemplates, getTemplate, createTemplate, updateTemplate, deleteTemplate. Already supports isBuiltIn flag
- `ConfigPreset` in-memory array (src/lib/config-presets.ts) — 5 presets: home-office, business, stealth, performance, cdn-relay. Has applyPreset() merge function
- `ProtocolTemplate` type (src/types/config.ts) — name, protocol, serviceType, defaultConfig, description
- `RoutingRuleTemplate` type + Prisma model (src/types/routing-rule-template.ts) — category field already supports 'bundle'
- `ChainTemplate` type (src/types/chain.ts) — id, name, description, topology, requiredServers, nodes[], icon
- Chain builder components (src/components/chains/) — ChainBuilder, ChainNodeCard, ChainTemplatesList
- Config components (src/components/config/) — config-list.tsx

### Established Patterns
- Templates use `isBuiltIn` boolean flag for read-only protection
- Prisma models follow createdAt/updatedAt timestamps
- In-file type definitions in src/types/, CRUD operations in src/lib/
- API routes follow /api/{resource} pattern

### Integration Points
- Templates page needs new route: /templates (app/templates/page.tsx)
- Chain presets integrate with ChainBuilder component and chain apply flow
- Routing presets integrate with existing routing rules API (src/app/api/routing/)
- Server presets integrate with server configuration flow
