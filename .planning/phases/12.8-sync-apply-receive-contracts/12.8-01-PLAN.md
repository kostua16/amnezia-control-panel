## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12.8-01 | S | config-applier fetch calls | mitigate | API key passed only as X-API-Key header (HTTP); never logged, never included in URL query params. The signPayload() call uses the key to generate HMAC. Per CLAUDE.md: "API keys are operator-chosen shared secrets, plaintext is not recoverable from the DB after save." |
| T-12.8-02 | I | config-applier error messages | mitigate | Error messages from enrichError use panelName (not apiKey). The 401 path returns a generic HTTP error message without echoing the API key. Ensure `console.error` calls do not log headers or API keys. |
| T-12.8-03 | T | config-applier response parsing | mitigate | After unwrapping `resp.data`, check `data?.applied` with optional chaining. If the response shape is unexpected (e.g., data is null), treat as failure rather than crash. The optional chaining `data?.applied` and `data?.message` prevents null pointer exceptions on malformed responses. |
| T-12.8-04 | S | panel-sync-client fetch calls | accept | panel-sync-client already correctly sends X-API-Key and X-Signature headers (this phase only fixes response parsing). No auth change needed. |
</threat_model>
