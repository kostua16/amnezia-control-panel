## Architecture Patterns

### VERIFICATION.md Template Structure (from 12.11-VERIFICATION.md)

The canonical VERIFICATION.md format this phase must replicate:

1. **YAML frontmatter:** `phase`, `verified` (ISO timestamp), `status` (passed/gaps_found), `score` (N/M must-haves verified), `overrides_applied`, `gaps` (list)
2. **Phase Goal + metadata header:** goal text, verified date, status, re-verification note
3. **Observable Truths table:** `# | Truth | Status | Evidence` -- each truth references specific file:line evidence
4. **Required Artifacts table:** `Artifact | Expected | Status | Details` -- confirms expected files exist with substantive content
5. **Key Link Verification table:** `From | To | Via | Status | Details` -- confirms imports/wiring between modules
6. **Behavioral Spot-Checks table (optional):** `Behavior | Command | Result | Status`
7. **Requirements Coverage table:** `Requirement | Description | Status | Evidence`
8. **Anti-Patterns Found table:** `File | Line | Pattern | Severity | Impact`
9. **Human Verification Required:** list of items needing manual confirmation
10. **Gaps Summary:** textual summary of findings

## Common Pitfalls

### Pitfall 1: Verifying 12.7 requirements instead of 12.7 meta-activity
**What goes wrong:** 12.7-VERIFICATION.md re-verifies TSCL-01-04 directly against source code instead of verifying that 12.7 *created the correct verification artifacts*.
**Why it happens:** TSCL-01-04 are listed as 12.7 requirements, so it's tempting to treat 12.7 like 11.1.
**How to avoid:** 12.7-VERIFICATION.md truths should be about "11.1-VERIFICATION.md exists with correct content" and "REQUIREMENTS.md checkboxes updated", not about the underlying Tailscale code. The Tailscale code is already covered by 11.1-VERIFICATION.md.
**Warning signs:** Truth #1 says "Admin can configure Tailscale subnet router" -- that's 11.1's truth, not 12.7's.

### Pitfall 2: Missing GEO-04 in 12.6 verification
**What goes wrong:** Focusing only on GEO-03 (the more interesting wiring) and forgetting that GEO-04 (v2fly geoip.dat loading) was also part of 12.6's scope.
**Why it happens:** GEO-03 involves code wiring (more visible), while GEO-04 was a text change + TODO comment (less visible).
**How to avoid:** Include explicit truths for REQUIREMENTS.md text change and TODO comment, plus geoip-manager download/parse verification.
**Warning signs:** 12.6-VERIFICATION.md has no mention of geoip.dat, v2fly, or REQUIREMENTS.md text.

### Pitfall 3: Incorrect score count
**What goes wrong:** Frontmatter says "8/8" but only 7 truths are listed in the table, or vice versa.
**Why it happens:** Copy-paste from template without adjusting counts.
**How to avoid:** Count observable truth rows explicitly; score = number of VERIFIED truths / total truths listed.
**Warning signs:** Table has 7 rows but frontmatter says 8/8.

### Pitfall 4: Referencing line numbers without verification
**What goes wrong:** Evidence column says "chain-router.ts:170" but the actual line is 168 after code changes.
**Why it happens:** Line numbers shift as code evolves; using stale numbers from the 12.6 SUMMARY.
**How to avoid:** Re-verify all line numbers against current source code before writing VERIFICATION.md. This research confirms current line numbers.
**Warning signs:** Research was done at time X but code has been committed since.
