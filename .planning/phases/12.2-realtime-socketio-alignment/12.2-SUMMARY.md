## Decisions Made
- **Custom server over instrumentation-only:** Next.js `register()` in `instrumentation.ts` is called before the HTTP server exists -- it provides no access to the `http.Server` instance. The only way to attach Socket.IO is via a custom server that creates the HTTP server first, then passes it to Next.js. This is the documented Next.js pattern for Socket.IO integration.
- **globalThis bridge:** `server.mjs` is plain JavaScript (not compiled by Next.js) so it cannot import `.ts` modules. The Socket.IO instance is stored on `globalThis.__socketIO` and read by `src/lib/websocket.ts` which runs inside Next.js's compiled environment.
- **Broadcaster in instrumentation.ts:** The `startBroadcaster()` needs access to Prisma and other TypeScript modules. It cannot run in `server.mjs` (plain JS). The `instrumentation.ts` `register()` function is compiled by Next.js and can dynamically import `.ts` modules, making it the right place for broadcaster initialization.
