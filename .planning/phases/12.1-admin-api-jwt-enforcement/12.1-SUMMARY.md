- Deleted dead `src/proxy.ts` that was never wired into the application
- All 76+ API routes now require valid JWT except 4 public endpoints

## Files Created/Modified
- `src/middleware.ts` - Next.js middleware with JWT verification for all /api/* and page routes
- `src/app/api/auth/me/route.ts` - Simplified to use decodeJwt instead of jwtVerify
- `src/app/api/panels/rollback/route.ts` - Removed authenticateAdmin helper and auth check
- `src/proxy.ts` - Deleted (logic moved to middleware, was never imported)

## Decisions Made
- API routes return JSON `{ error: 'Unauthorized' }` with 401 status (not redirect) since API consumers are not browsers
- Page routes redirect to `/login?expired=true` preserving the existing UX pattern from proxy.ts
- `auth/me` uses `jose.decodeJwt` (decode-only) rather than `jwtVerify` since middleware already validated the token -- this avoids redundant cryptographic verification while still extracting user info
- Kept `sync/receive` in the public list since it uses HMAC + API key auth, not JWT session tokens
