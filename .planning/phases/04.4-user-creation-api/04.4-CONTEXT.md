# Phase 4.4: User Creation API - Context

**Gathered:** 2026-04-29
**Status:** Ready for planning
**Mode:** Infrastructure phase — extending existing API with VPN service integration

<domain>
## Phase Boundary

Extend existing POST /api/users to also create users in actual AWG and 3x-ui VPN services via shell commands. Currently the API only creates DB records. Needs shell integration layer for both VPN systems.

</domain>

<decisions>
## Implementation Decisions

### Claude's Discretion
All implementation choices are at Claude's discretion — infrastructure phase. Shell command structure, error handling patterns, and service communication approach are technical decisions best left to implementation.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- POST /api/users already exists in src/app/api/users/route.ts (creates DB User + UserProtocol + UserQuota)
- src/lib/prisma.ts — Prisma client singleton
- src/lib/service-monitor.ts — existing shell command patterns for service checks
- CreateUserPayload type in src/types/user.ts
- User, UserProtocol, UserQuota models in Prisma schema

### Established Patterns
- Shell commands via exec/child_process
- API response helpers in src/lib/api-response.ts
- zod validation for request bodies
- Error handling with try/catch and structured responses

### Integration Points
- src/app/api/users/route.ts — POST handler to extend
- Shell commands to amneziawg and xray services on the server
- AWG: likely wg commands or amnezia CLI
- 3x-ui: likely xray API or 3x-ui CLI

</code_context>

<specifics>
## Specific Ideas

- Create a service abstraction layer (src/lib/vpn-service.ts or similar)
- Separate functions for AWG user creation and 3x-ui user creation
- If VPN service is offline, still create DB record but mark service assignment as pending
- Log all VPN service interactions for debugging

</specifics>
