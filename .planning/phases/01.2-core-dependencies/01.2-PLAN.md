<action>
Install TypeScript type definition packages for libraries that do not ship their own types:

```bash
npm install --save-dev @types/shelljs @types/bcryptjs
```

Rationale:
- `@types/shelljs` — shelljs is a pure JavaScript package without bundled type definitions
- `@types/bcryptjs` — bcryptjs is a pure JavaScript package without bundled type definitions

The following packages already include their own TypeScript types and do NOT need @types/ packages:
- prisma, @prisma/client (bundled types)
- socket.io (bundled types)
- jose (bundled types)
- zustand (bundled types)
- @tanstack/react-query (bundled types)
- lucide-react (bundled types)
- recharts (bundled types)
- clsx (bundled types)
- zod (bundled types)
</action>

<action>
1. Verify the project still builds with all new dependencies installed:

```bash
npm run build
```

2. If the build succeeds, verify TypeScript compilation resolves all types:

```bash
npx tsc --noEmit
```

3. Verify that the Next.js development server starts without errors (start and immediately stop):

```bash
timeout 15 npm run dev 2>&1 || true
```

If any build errors occur, diagnose whether the error is from a package conflict or a missing type and resolve before continuing. Common issues:
- Peer dependency warnings are acceptable and should not block
- TypeScript errors from missing types for a package mean a @types/ package is needed
- Build errors from invalid imports mean a package was not installed correctly
</action>
