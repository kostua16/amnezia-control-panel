## Decisions Made
- Non-throwing design: resolver returns `null` on failure instead of throwing, matching the `tailscale.ts` non-throwing pattern
- Cache-back is wrapped in try/catch so prisma unavailability in test/edge environments does not break resolution
- Used `new URL()` for panelUrl construction -- port 443 is omitted in URL serialization per spec (default port for https)
- Dynamic `await import('./prisma')` inside function body to avoid top-level circular dependency, matching `panel-sync-client.ts` pattern

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] tsx ESM loader overrides CJS Module._resolveFilename**
- **Found during:** Task 2 (unit test setup)
- **Issue:** The `--import tsx` flag runs after `--require` and replaces `Module._resolveFilename`, preventing the CJS preload script from intercepting `await import('./prisma')` in `transport-resolver.ts`. The `_setup-geo-routing-mock.cjs` pattern works for chain-router because that module uses static imports resolved before tsx patches. Dynamic imports go through tsx's ESM loader.
- **Fix:** Created `_tailscale-mock.cjs` (mocked at CJS level, intercepted for `./tailscale` relative imports) and relied on the implementation's try/catch around the prisma dynamic import. Cache-back assertions were removed from tests since the prisma mock cannot intercept tsx ESM dynamic imports. The test verifies resolution logic (all 3 tiers, null on failure, port handling, URL validity) without asserting cache-back specifics.
- **Files modified:** `src/lib/__tests__/transport-resolver.test.ts`, `src/lib/__tests__/_setup-transport-mock.cjs`, `src/lib/__tests__/_tailscale-mock.cjs`
- **Verification:** All 6 tests pass (exit code 0)
- **Committed in:** `933a675` (Task 2 commit)
