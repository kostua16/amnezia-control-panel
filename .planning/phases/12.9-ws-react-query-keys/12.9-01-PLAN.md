<objective>
Fix three broken key mappings in `WS_TO_QUERY_KEYS` so WebSocket events actually invalidate the React Query caches used by dashboard, resources, and fleet hooks. Remove dead entries for events with no React Query consumers and the duplicate `alert:new` entry.

Purpose: The server broadcasts `stats:update` (30s), `resource:update` (10s), and `panel:fallback-change` events, but the bridge in `providers.tsx` maps them to wrong query key prefixes. TanStack Query v5 uses element-by-element prefix matching -- `['dashboard', 'stats']` does NOT match `['dashboard-stats']`. Per the gap audit, this means `broadcastEvent` is ineffective for these data paths (PROJ-RT-01, GAPL-02).

Output: Corrected `WS_TO_QUERY_KEYS` mapping in `providers.tsx` that aligns with hook queryKey definitions.
</objective>
