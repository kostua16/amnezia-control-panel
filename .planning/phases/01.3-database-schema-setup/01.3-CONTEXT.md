<domain>
## Phase Boundary

Initialize Prisma and create the complete database schema with all models needed for the Amnezia Control Panel. This includes users, services, servers, configurations, traffic logging, routing rules, alerts, quotas, and protocol assignments. Run the first migration to create the SQLite database file.

</domain>

<decisions>
## Implementation Decisions

### Schema Scope
- **D-01:** Full schema with all models from the roadmap — not incremental per-phase
- **D-02:** SQLite as the database provider (Prisma 7.x with built-in SQLite WASM engine)
- **D-03:** Prisma schema file location: `prisma/schema.prisma` (standard Next.js location)

### Models to Create
- **User** — id, username, passwordHash, displayName, isActive, isBlocked, trafficQuotaBytes, speedLimitKbps, createdAt, updatedAt
- **Service** — id, type (AWG/3XUI), status (running/stopped/error), config (JSON), port, lastCheckedAt, createdAt
- **Server** — id, name, hostname, port, apiKeyHash, isActive, createdAt
- **Configuration** — id, serviceId (optional), type, name, content (JSON), isActive, createdAt, updatedAt
- **TrafficLog** — id, userId, serverId, bytesIn, bytesOut, timestamp
- **RoutingRule** — id, userId (optional), protocol, destination, action (allow/block/route), priority, isActive, createdAt
- **Alert** — id, type, severity (info/warning/critical), message, isRead, createdAt
- **UserQuota** — id, userId, quotaBytes, period (daily/weekly/monthly), resetAt
- **UserProtocol** — id, userId, serviceType (AWG/3XUI), protocol, config (JSON), isActive

### Claude's Discretion
- Exact field types, constraints, indexes, and relations
- Whether to use Json type or separate tables for config data
- Migration strategy (name, whether to seed initial admin user)
- Prisma client generation location

</decisions>
