## Interaction Patterns

### 1. API Key Input in PushWizard Step 1

**Location:** Within each selected panel row in `PanelSelector` or as a new collapsible section below `PanelSelector` in step 1.

**Behavior:**
- When a panel is selected (checkbox checked), an API key input field appears inline below the panel row (or within an expandable area).
- Input is `type="password"` with a show/hide toggle (eye icon from lucide-react).
- Label: "API Key" (per panel).
- Placeholder: "Enter shared secret for {panel.name}".
- Validation: `min(1)` -- push button disabled if any selected panel has empty API key.
- Keys stored in component state (`Record<number, string>`), not persisted.
- Keys reused for rollback (step 4) -- no re-entry required.

**State:**
- `panelApiKeys: Record<number, string>` -- added to PushWizard state.
- Push "Next" button disabled condition adds: `!Object.values(panelApiKeys).every(key => key.length > 0)`.

**Visual:** Uses existing `Input` component (`src/components/ui/input.tsx`) with `type="password"`. Field wrapped in a `<div>` with `mt-2 ml-8` indent below panel row (matches `ErrorRecommendation` indent pattern at `ml-8`).

### 2. API Key Collection for ChainFlowEditor "Save Chain"

**Location:** Pre-save dialog triggered by "Save Chain" button click in `ChainFlowEditor`.

**Behavior:**
- Clicking "Save Chain" opens a `Dialog` (existing `src/components/ui/dialog.tsx`) instead of immediately calling `/api/chains/apply`.
- Dialog title: "Provide API Keys".
- Dialog body: One `<Input type="password">` per unique panel referenced by chain nodes.
- Each field labeled with panel name: "API Key for {panel.name}".
- "Save" button in dialog calls `/api/chains/apply` with `panelApiKeys` in request body.
- "Cancel" button closes dialog without saving.

**State:**
- `saveDialogOpen: boolean` -- added to ChainFlowEditor state.
- `panelApiKeys: Record<number, string>` -- collected in dialog, sent to API.
- Error response from `/api/chains/apply` displayed as `setPushError` or toast.

### 3. Push Result -- configVersion and retries (fix)

**Location:** `PushResultSummary` per-panel result row.

**Current bug:** `configVersion: null` and `retries: 0` always displayed.

**Fix approach:** Use the `PushAllResult` from the push API response (not WebSocket events) for final results. WebSocket events drive step 3 progress only.

**Visual change:** Per-panel result row shows `configVersion` as "v{N}" badge and `retries` as "{N} retries" subtext when > 0. These fields already exist in `PushResult` type; the component just needs correct data.
