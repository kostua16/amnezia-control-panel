### Intake from PR #191: [codex] ci: orchestrate PR automation flow
- Source: https://github.com/kostua16/amnezia-control-panel/pull/191
- Add retry logic and rate-limit awareness to worker dispatch and check polling -- The orchestrator has no retry mechanism — if a worker fails (flow/review-failed, flow/improve-failed), the state is terminal until the next push or label change. Additionally, collectWorkerRuns() fetches 50 runs per worker (4 workers × 50 = 200 list entries) on every invocation, which can exhaust API rate limits on busy repos. Phase 191.2 should add: (1) configurable retry with exponential backoff for transient worker failures; (2) a single gh api call with pagination instead of N per-worker queries; (3) a dedicated re-trigger mechanism (e.g., /recheck comment) that re-runs the orchestrator for a stuck PR. (owner: ci-automation)
