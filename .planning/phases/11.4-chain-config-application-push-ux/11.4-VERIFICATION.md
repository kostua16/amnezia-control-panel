### Gaps Summary

The backend infrastructure for Phase 11.4 is complete and well-implemented:
- Config applier with shell injection guards and 404 fallback
- Error enrichment with 6 categories
- Rollback manager with one-level config swap and re-push
- Diff computation with 3-section comparison
- All API endpoints (diff, rollback, push via existing route)
- WebSocket push progress events
- Prisma schema extended for previous config storage

**The critical gap is in push-wizard.tsx:** The `chainConfigRef` is initialized to `null` and never assigned a value. This makes the 4-step wizard permanently stuck on Step 1. There is no chain selection mechanism -- no chain picker, no API call to fetch available chains, and no assignment to `chainConfigRef.current`. As a result, Steps 2 (Preview), 3 (Push), and 4 (Results) are unreachable code paths.

A secondary gap: the polling fallback references a non-existent `/api/panels/push/status` endpoint. This is non-blocking (caught by try/catch) but represents dead code.
