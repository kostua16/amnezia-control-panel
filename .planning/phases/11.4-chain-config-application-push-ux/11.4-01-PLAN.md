Implement `enrichError(rawError: string, panelName: string): StructuredPushError` that:
1. Pattern-matches raw error strings against known failure patterns
2. Returns a StructuredPushError with type, message, recommendation, and knownFix

Known error patterns to match (per D-01 from CONTEXT.md):
- Timeout patterns (`timeout`, `ETIMEDOUT`, `ABORT_ERR`) -> type: 'connection_timeout', recommendation: "Check Tailscale status on the remote panel", knownFix: "Verify panel is reachable: `ping <panelUrl>`"
- Auth patterns (`401`, `403`, `unauthorized`, `invalid api key`, `invalid signature`) -> type: 'auth_failure', recommendation: "Verify API key is correct in panel settings", knownFix: "Re-enter API key on the panel edit page"
- Config patterns (`invalid`, `malformed`, `validation failed`, `ECONNREFUSED`) -> type: 'invalid_config', recommendation: "Check chain configuration for invalid values", knownFix: "Review the config diff before pushing"
- Docker patterns (`docker`, `container not found`, `container is not running`) -> type: 'docker_error', recommendation: "Check Docker container status on the remote server", knownFix: "`docker ps` to verify container is running, `docker restart <container>`"
- Service patterns (`service not found`, `command not found`, `amneziawg: not found`, `wg: not found`) -> type: 'service_error', recommendation: "Verify VPN service is installed on the remote server", knownFix: "Install or restart the service on the remote panel"
- Default: type: 'unknown', recommendation: "Check panel logs for details", knownFix: null

Each pattern should use case-insensitive matching. The function must NOT throw -- always return a StructuredPushError.

Create `src/lib/config-applier.ts` implementing real config application:

**applyAwgConfig(panelUrl: string, wireguardPeers: WireGuardPeerConfig[]): Promise<ConfigApplierResult>**
- Determines if the remote panel uses Docker or native AWG by first trying a non-destructive read command
- Docker path: `docker exec amnezia-wg wg setconf <interface> /dev/stdin` with peer config piped via stdin
- Native path: `amneziawg setconf <interface> /dev/stdin` (fallback: `wg setconf`)
- Constructs WG config format: `[Peer]` sections with PublicKey, AllowedIPs, Endpoint, PersistentKeepalive
- Executes via `fetch()` to the remote panel's `/api/sync/apply-awg` endpoint (the remote panel runs this command locally)
- If that endpoint doesn't exist, falls back to `executeOnServer` pattern (for same-server panels)
- Uses `AbortSignal.timeout(15000)` for connection timeout
- On error: wraps with `enrichError` from error-reporter.ts

**applyThreeXuiConfig(panelUrl: string, xrayRules: XrayRoutingRule[]): Promise<ConfigApplierResult>**
- Calls the 3x-ui REST API on the remote panel: `POST <panelUrl>/xui/inbound/update`
- Request body: `{ routingRules: xrayRules }` in the format 3x-ui expects
- Uses `AbortSignal.timeout(15000)` for connection timeout
- The remote panel proxies this to its local 3x-ui instance
- On error: wraps with `enrichError` from error-reporter.ts

**applyPanelConfig(panelUrl: string, panelName: string, payload: PanelSyncPayload): Promise<ConfigApplierResult[]>**
- Determines which services this panel uses based on `payload.chainNodes` protocol field
- Calls applyAwgConfig if any node uses 'wireguard' protocol
- Calls applyThreeXuiConfig if any node uses 'xray' protocol
- Returns array of ConfigApplierResult (one per service applied)
- Does NOT throw -- always returns results with errors embedded

| T-11.4-01 | I | config-applier (applyAwgConfig) | mitigate | WireGuard peer config values (publicKey, endpoint, allowedIPs) are validated against injection patterns before being passed to CLI commands or API payloads. Reject values containing shell metacharacters (`;`, `|`, `$`, `` ` ``, `&&`) |
| T-11.4-02 | I | config-applier (applyThreeXuiConfig) | mitigate | Xray routing rules are JSON-serialized (not string-interpolated) before sending to 3x-ui API. Zod validation ensures rule type/value are within allowed enums |
