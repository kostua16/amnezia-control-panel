| `Input` | `src/components/ui/input.tsx` | Search/filter in panel selector |

### New Components Required

| Component | Purpose |
|-----------|---------|
| `PushWizard` | Multi-step container: Select Panels -> Preview Changes -> Push -> Results. Tracks wizard step state. |
| `PanelSelector` | Checklist of registered panels with status badges. Pre-selects all connected panels. |
| `ConfigDiffView` | Side-by-side diff display: current config (left) vs new config (right) per panel. Highlights additions (green tint), removals (red tint), unchanged (default). |
| `PushProgressTracker` | Per-panel progress: pending -> pushing (spinner) -> success (green check) / failed (red X) with latency. Real-time via WebSocket. |
| `PushResultSummary` | Summary card after push: succeeded/failed counts, per-panel detail list with error recommendations. |
| `ErrorRecommendation` | Inline expandable block for each failed panel showing `type`, `message`, `recommendation`, `known_fix`. |

## Interaction Patterns

### Push Flow (Multi-Step Wizard)

```
Step 1: Select Panels
  - Panel list with checkboxes, status badges, and connection indicators
  - "Select all connected" quick action
  - Cannot proceed with zero panels selected
  - "Next: Preview Changes" button (disabled if no selection)

Step 2: Preview Changes (ConfigDiffView)
  - Tab bar or accordion listing selected panels
  - Side-by-side diff for each panel (current vs new)
  - Visual indicators: green = addition, red = removal, default = unchanged
  - "Back" and "Push Configuration" buttons

Step 3: Push (PushProgressTracker)
  - Sequential per-panel progress display
  - Real-time WebSocket events for each panel status change
  - Polling fallback if WebSocket unavailable (30s interval, matching existing pattern)
  - Cannot navigate back during active push
  - Auto-advances to Results step when all panels complete

Step 4: Results (PushResultSummary)
  - Summary: "{succeeded}/{total} panels updated"
  - Per-panel list: status badge, latency, error details if failed
  - "Rollback" button per failed panel (ghost variant, destructive text color)
  - "Push Again" button (outline variant) to retry
  - "Back to Panels" link (navigates to /panels)
```

### Real-Time Progress

- WebSocket events via existing `real-time-broadcaster.ts`
- Event payload: `{ panelId, status: 'pushing' | 'success' | 'failed', latencyMs?, error? }`
- UI shows spinner during 'pushing', green check on 'success', red X + error on 'failed'
- 30-second polling fallback if Socket.io connection is unavailable

### Rollback Flow

- Single-click per panel (no confirmation dialog per CONTEXT.md decision)
- Button appears inline on the result row for failed or recently-pushed panels
- Uses `variant="ghost"` with `text-destructive` icon color
- Shows brief success toast/notification after rollback completes
- Admin can always push again after rollback (no state lock)

### Error Display

- Structured error card per failed panel with three fields:
  1. **Error message** -- what happened (e.g., "Connection timeout after 10s")
  2. **Recommendation** -- what to do next (e.g., "Check Tailscale status on the remote panel")
  3. **Known fix** -- if pattern-matched (e.g., "Restart amneziawg service: `sudo systemctl restart amneziawg`")
- Known fixes are collapsible (expanded by default for first error)
- Monospace font for CLI commands in known fixes
