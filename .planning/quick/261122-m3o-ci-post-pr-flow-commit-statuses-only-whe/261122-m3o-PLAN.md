# Plan: post pr-flow commit statuses only when they change (success only)

Issue: #1156. Goal: cut ~3 of ~20 REST calls per orchestrator wake without changing any flow decision.

## Facts (verified against real runs and code)

- `publishFlowStatuses(pr, visibility)` (`orchestrate-pr-flow.cjs`, ~line 1313) POSTs every entry of `visibility.orderedStatuses` (7 contexts: ready, code-review, security-review, dependency-review, kilo-review, pr-improve, finalizer) on every wake.
- PR #1090 head `dea80a6`: 4 wakes -> 28 POSTs, many with identical state and description.
- Status age and history are load-bearing:
  - `watch-pr-flow.cjs`: `hasExpiredStatusInState` on `pr-flow/ready` pending (30 min) and failure (finalizer lane), pending-history loop count on `pr-flow/ready`, `pr-flow/kilo-review` pending expiry.
  - `evaluate-external-review.cjs`: `latestPendingStatus` age of `pr-flow/kilo-review`.
  So re-posting `pending`, `failure` and `error` must keep refreshing the timestamp and history exactly as today.
- `fetchCommitStatuses(headSha)` (~line 1361) already reads `repos/{repo}/commits/{sha}/status`, which returns the latest status per context.

## Behavior (the whole change)

A status is skipped only if ALL hold: the latest known status for that context on `pr.headSha` has state `success`, the new status state is `success`, the descriptions are equal after the same truncation the poster applies (`truncateStatusDescription`, ~line 331), and target_url is "stable": equal to the previous one, OR the new `targetUrl` is the volatile current-run URL (`getCurrentRunUrl()`, which embeds `GITHUB_RUN_ID` and differs on every wake; requiring equality there would make the skip never fire for N/A workers, kilo-review and `pr-flow/ready`). A worker-run URL that differs from the previous one means a new worker run and still posts. Everything else posts as today: pending, failure, error, changed success, no previous status, previous status in another state. Accepted cosmetic effect: a skipped success status keeps a link to an older orchestrator run.

Validated by independent review: the only runtime readers of commit statuses are `evaluate-external-review.cjs` (kilo pending age), `watch-pr-flow.cjs` (ready/kilo pending age, pending/failure history counts, failure age) and `fetch-auto-cover-context.cjs`; none reads age or history of a `success` status. `orchestrate-pr-flow.cjs` is the only writer of `pr-flow/*`.

Fail open: if reading the current statuses throws or returns an unexpected shape, post every status.
