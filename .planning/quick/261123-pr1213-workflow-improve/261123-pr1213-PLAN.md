## Quick Wins
- Port closed-issue prefilter from fix-issue.yml to claude.yml -- Verified gap: claude.yml (lines 3-11) triggers on issue_comment created and issues opened with no state check (grep for state/closed returns nothing), so an @claude comment on a closed issue still burns a runner + Zai agent run — the same race PR #1213 fixes in fix-issue.yml (claude.yml gates on '@claude', not '/claude'). claude.yml's authorize 'if' ORs per-event branches and has no pull_request==null/comment-body term to insert before, so add 'github.event.issue.state != 'closed' &&' inside the issue-linked branches: the issues-opened branch, and the issue_comment branch guarded by 'github.event.issue.pull_request == null' — for issue_comment on a PR, github.event.issue.state is the PR state, so leaving PR-comment triggers unguarded keeps @claude working on closed PRs. Add the matching /github\.event\.issue\.state != 'closed'/ guard entry for claude.yml to src/lib/__tests__/workflow-triggers.test.ts 'prefilters standalone AI mention workflows before runner checkout' (lines 348-373 — the claude.yml assertions live there, not in the :375 issue-command test), and add a workflow-e2e-scenarios.md scenario row. Per the workflow change protocol, run npm run test-only AND 'cd .github/workflows && node --test scripts/__tests__/*.test.cjs'. (owner: gh-workflow-engineer, type: quick-task)
- Extract Docker main-push classifier into a tested scripts/*.cjs helper -- After PR #1213 the classify script on #1213's branch (docker-image.yml listMainPushFiles + matchesRelevantPath + redaction, ~lines 127-176 there) is ~150 lines of inline JS in YAML, testable only by vm.runInNewContext over the YAML string in workflow-yaml-parse.test.cjs G8d. Keeps should_publish/should_validate outputs and fail-open semantics byte-identical; verify with both suites and Prettier/ESLint on the changed .cjs. (owner: gh-workflow-engineer, type: quick-task)
