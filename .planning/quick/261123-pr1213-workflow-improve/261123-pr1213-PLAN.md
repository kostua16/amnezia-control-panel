## Quick Wins
- Port closed-issue prefilter from fix-issue.yml to claude.yml -- Verified gap: claude.yml (lines 3-11) triggers on issue_comment created and issues opened with no state check (grep for state/closed returns nothing), so an @claude comment on a closed issue still burns a runner + Zai agent run — the same race PR #1213 fixes in fix-issue.yml (claude.yml gates on '@claude', not '/claude'). claude.yml's authorize 'if' (lines 30-40) ORs four per-event branches — issue_comment, pull_request_review_comment, pull_request_review, issues-opened — and the comment-body terms already exist (:31-32 both contain contains(github.event.comment.body, '@claude')); no branch carries a pull_request==null term, and the issue_comment branch at :31 matches both issue and PR comments, so gating it wholesale on state would also gate PR comments (for issue_comment on a PR, github.event.issue.state is the PR state). Spell the split out instead: keep the PR-comment paths unguarded, and in both options edit the existing :31 branch — (A) narrow the existing :31 branch to PR comments (prepend 'github.event.issue.pull_request != null &&' to its existing terms) and add a separate issue-only branch 'github.event_name == 'issue_comment' && github.event.issue.pull_request == null && github.event.issue.state != 'closed''; adding the branch alone is not enough, because the :31-40 branches are OR'd, so an un-narrowed :31 still matches a closed-issue comment and authorize still runs; or (B) rewrite the existing :31 branch in place as '(github.event.issue.pull_request != null || github.event.issue.state != 'closed')', which narrows it by itself. Both options leave every surviving issue_comment path requiring a PR or an open issue, preserving @claude on closed PRs. Leave the issues-opened branch alone: claude.yml subscribes only to issues: [opened] (:8-9) and an opened issue is always open, so a state term there is vacuous. The guard must land in both layers, not YAML alone: scripts/evaluate-trigger-policy.cjs mode 'claude' (:81-103) has no closed-issue check today, unlike the fix-issue (:190-201) and approve-auto-fix (:346-353) modes, so a YAML-only guard would leave the policy script still reporting triggered: true for closed issues. Add the matching /github\.event\.issue\.state != 'closed'/ guard entry for claude.yml to src/lib/__tests__/workflow-triggers.test.ts 'prefilters standalone AI mention workflows before runner checkout' (lines 348-373 — the claude.yml assertions live there, not in the :375 issue-command test), and add a workflow-e2e-scenarios.md scenario row. Per the workflow change protocol, run npm run test-only AND 'cd .github/workflows && node --test scripts/__tests__/*.test.cjs'. (owner: gh-workflow-engineer, type: quick-task)
