## Summary

Follow-ups found in the diff itself: (1) prisma 7.10.1 now directly depends on mysql2 3.24.4 (package-lock.json 'node_modules/prisma' deps), which satisfies the documented removal condition for the 'mysql2' override — the override becomes redundant only once #1142 merges (this branch's base still resolves prisma 7.10.0 declaring mysql2 3.15.3, with 3.24.4 forced only by the override); (2) the 2026-09-24 changelog note in docs/npm-overrides.md still lists 'Remaining: deepmerge-ts <8' as open even though 8.0.2 is now in the tree; (3) nothing enforces the documented policy that every 'overrides' entry has a matching row in docs/npm-overrides.md ('_overrideNotes' points there) — drift between package.json overrides and the doc table is detectable in CI. ## Quick Wins
- Remove the mysql2 override only after PR #1142 merges and the precondition is re-verified -- package-lock.json in PR #1142 shows node_modules/prisma@7.10.1 depends on mysql2 3.24.4 directly, meeting the removal condition documented in the mysql2 row of docs/npm-overrides.md ("prisma ships mysql2 >=3.24.x"). That condition does NOT hold on this plan's base branch: here node_modules/prisma is 7.10.0 declaring "mysql2": "3.15.3", and node_modules/mysql2 resolves to 3.24.4 only because the override forces it — dropping it now would re-expose the mysql_clear_password / decompression-bomb advisories the override blocks. Intake planning merges and is executed independently of #1142 (executors run four times daily), so gate the task: only run it once #1142 is merged, and first confirm prisma itself declares mysql2 >=3.24.x via 'npm explain mysql2' (or 'npm view prisma@7.10.1 dependencies'). Then verify with 'npm ls mysql2' after dropping the override (only ≥3.24.4 should remain, 'npm audit --omit=dev' stays 0), remove the 'mysql2' key from 'overrides' in package.json, and retire the table row in docs/npm-overrides.md with a dated note. Smaller override surface = fewer pinned deps for Dependabot and lock regens to fight. (owner: kos-audit-fix, type: quick-task)
- Close the stale deepmerge-ts <8 note in docs/npm-overrides.md -- The 2026-09-24 entry in docs/npm-overrides.md ends with 'Remaining: deepmerge-ts <8 ... left open', but PR #1142's lock now carries deepmerge-ts 8.0.2 (via @prisma/config 7.10.1) and the new 2026-11-21 entry only lists it among refreshed deps without closing the older note. Update the 2026-09-24 note (or add a strikethrough/closed marker) so the audit trail stops reporting a resolved stack-exposure risk as open — this doc is the source reviewers consult before touching overrides. (owner: kos-audit-fix, type: quick-task)
- Add overrides↔docs drift guard script -- docs/npm-overrides.md states 'New override entries should be documented here and flagged in PR review per the policy (see proposal pr974.3)' and package.json's '_overrideNotes' points at the doc, but nothing checks it. Add a small Node script (e.g. .github/workflows/scripts/check-npm-overrides-docs.cjs) that parses 'overrides' from package.json, normalizes each key — recursively dot-flatten nested object values (overrides.minimatch -> { "brace-expansion": ... } becomes "minimatch.brace-expansion") and strip any "@range" specifier from a key segment ("minimatch@^3.0.0" -> "minimatch", so a scoped "minimatch@^3.0.0.brace-expansion" entry matches the documented row "minimatch.brace-expansion") — then asserts each normalized key has a matching first-column row in the docs table, and vice versa. Compare key presence only, not pinned versions: versions legitimately move per refresh (brace-expansion 5.0.8→5.0.13 in #1142) and version equality would false-positive on every bump. Wire it into the workflow e2e suite (cd .github/workflows && node --test scripts/__tests__/*.test.cjs) with a test in scripts/__tests__/ — 'npm test' cannot host it, since test-only only globs src/**/__tests__/*.test.ts and lint/format:check are src-scoped, so a .cjs helper under .github is never picked up there; wire any failure to the audit-fix workflow. Keeps the pr974.3 policy machine-enforced as the overrides block keeps evolving (three entries changed in this PR alone). (owner: kos-audit-fix, type: quick-task)
