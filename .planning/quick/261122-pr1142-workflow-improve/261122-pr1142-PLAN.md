## Quick Wins
- Remove the mysql2 override only after PR #1142 merges and the precondition is re-verified -- package-lock.json in PR #1142 shows node_modules/prisma@7.10.1 depends on mysql2 3.24.4 directly, meeting the removal condition documented in the mysql2 row of docs/npm-overrides.md ("prisma ships mysql2 >=3.24.x"). That condition does NOT hold on this plan's base branch: here node_modules/prisma is 7.10.0 declaring "mysql2": "3.15.3", and node_modules/mysql2 resolves to 3.24.4 only because the override forces it — dropping it now would re-expose the mysql_clear_password / decompression-bomb advisories the override blocks. Intake planning merges and is executed independently of #1142 (executors run four times daily), so gate the task: only run it once #1142 is merged, and first confirm from prisma's own manifest that it declares mysql2 >=3.24.x — resolve the installed prisma version from the branch's package-lock.json at execution time (Dependabot bumps this weekly per docs/npm-overrides.md Notes, so never hardcode a version) and check its declared dependencies via 'npm view prisma@<resolved> dependencies' or by reading the 'node_modules/prisma' deps block in package-lock.json. Do NOT use 'npm explain mysql2' as the precondition: while the override is still active it reports the forced resolution (3.24.4, marked overridden) even when prisma still declares 3.15.3, so the check can look satisfied before the documented removal condition is met — keep 'npm explain mysql2' for post-removal verification only. Then verify with 'npm ls mysql2' after dropping the override (only ≥3.24.4 should remain, 'npm audit --omit=dev' stays 0), remove the 'mysql2' key from 'overrides' in package.json, and retire the table row in docs/npm-overrides.md with a dated note. Smaller override surface = fewer pinned deps for Dependabot and lock regens to fight. (owner: kos-audit-fix, type: quick-task)
- Close the stale deepmerge-ts <8 note in docs/npm-overrides.md -- The 2026-09-24 entry in docs/npm-overrides.md ends with 'Remaining: deepmerge-ts <8 ... left open', but PR #1142's lock now carries deepmerge-ts 8.0.2 (via @prisma/config 7.10.1) and the new 2026-11-21 entry only lists it among refreshed deps without closing the older note. Update the 2026-09-24 note (or add a strikethrough/closed marker) so the audit trail stops reporting a resolved stack-exposure risk as open — this doc is the source reviewers consult before touching overrides. (owner: kos-audit-fix, type: quick-task)
- Add overrides↔docs drift guard script -- docs/npm-overrides.md states 'New override entries should be documented here and flagged in PR review per the policy (see proposal pr974.3)' and package.json's '_overrideNotes' points at the doc, but nothing checks it. Add a small Node script (e.g. .github/workflows/scripts/check-npm-overrides-docs.cjs) built around one canonical form — a leaf path, the ordered list of raw 'overrides' keys from the tree root down to a version string — and compare by rendering that structure, never by parsing a flat string back into segments. (a) package.json side: walk 'overrides' structurally; each own key is exactly one segment taken verbatim (never split on '.' or '@'), recurse into plain-object values, and emit a leaf path when the value is a version string ({"minimatch": {"brace-expansion": ...}} -> ["minimatch", "brace-expansion"]; post-#1142, {"minimatch@^3.0.0": {"brace-expansion": ...}} -> ["minimatch@^3.0.0", "brace-expansion"]). (b) From each leaf path derive exactly two accepted spellings by joining its segments with '.': the verbatim spelling ("minimatch@^3.0.0.brace-expansion") and the range-stripped spelling, where a segment loses its trailing '@range' — the text from the last '@' in that segment when its index is > 0, so "@babel/core" keeps its leading scope '@', "minimatch@^3.0.0" becomes "minimatch" and "@scope/pkg@^1.0.0" becomes "@scope/pkg" — giving "minimatch.brace-expansion". (c) Docs side: read only the active table in docs/npm-overrides.md (the one whose header row starts with '| Package |' — fail if absent; skip the header and separator rows, since retired entries such as @hono/node-server live under Notes and must not count) and take each row's first-column cell under a strict cell grammar: optional whitespace, a backtick, the path, a closing backtick, optional whitespace — strip the backticks and nothing else, and treat any other Markdown (bold, a link, a bare name) as a failure in itself. The resulting path is never split, tokenized, or semver-parsed: a flat path like "minimatch@^3.0.0.brace-expansion" is ambiguous by construction (ranges contain dots, and the never-split rule forbids recovering segments from it), so the row is effectively rebuilt from the structure — the cell is matched as a whole string against the spellings rendered in (b). (d) Matching rule: a leaf claims a row by its verbatim spelling first and only then by its range-stripped spelling, and no other spelling is accepted; every leaf must claim exactly one row and every row must be claimed by exactly one leaf — a second claim on the same row is drift, which is how two leaves that render alike (a literal 'a.b' key next to a nested 'a' -> { 'b': ... }) get caught. Report both directions with the offending key path or row name. (e) Acceptance: the guard must land green on its first run, with nothing routed to audit-fix for its own false positives — on this tree 8 leaves map to 8 rows, and on the post-#1142 tree 9 map to 9, because docs/npm-overrides.md already spells the nested entry as the verbatim 'minimatch@^3.0.0.brace-expansion'. Compare key presence only, not pinned versions: versions legitimately move per refresh (brace-expansion 5.0.8→5.0.13 in #1142) and version equality would false-positive on every bump. Wire it into the workflow e2e suite (cd .github/workflows && node --test scripts/__tests__/*.test.cjs) with a test in scripts/__tests__/ — 'npm test' cannot host it, since test-only only globs src/**/__tests__/*.test.ts and lint/format:check are src-scoped, so a .cjs helper under .github is never picked up there; wire any failure to the audit-fix workflow. Keeps the pr974.3 policy machine-enforced as the overrides block keeps evolving (three entries changed in this PR alone). (owner: kos-audit-fix, type: quick-task)
