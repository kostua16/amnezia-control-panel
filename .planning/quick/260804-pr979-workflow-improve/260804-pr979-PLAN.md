# Quick Plan: PR #979 workflow improvement intake

## Source
- PR #979: fix: resolve #978 - MNT-E02: Schedule-drift detector (maintenance)
- URL: https://github.com/kostua16/amnezia-control-panel/pull/979

## Summary
PR #979 adds 'detect-schedule-drift.cjs' + 193-line test suite. The script parses cron schedules from workflow YAML, fetches recent schedule-triggered runs via 'gh run list', and reports median drift. It is NOT wired into any workflow YAML — purely a standalone CLI tool. Two concrete follow-ups identified.

## Quick Wins
- Wire drift detector into maintenance.yml -- detect-schedule-drift.cjs exists but is never invoked. Add a pre-sweep step in .github/workflows/maintenance.yml (before the kos-maintenance agent) that runs 'node detect-schedule-drift.cjs --json' and surfaces chronic drift as a GitHub Actions warning annotation ('$GITHUB_STEP_SUMMARY'). This gives the daily maintenance run actionable drift telemetry without agent involvement. (owner: kos-maintenance, type: workflow-improvement)
- Add range+step support to expandField -- expandField() in detect-schedule-drift.cjs:296 handles '*/N' (wildcard step) and 'A-B' (range) but NOT combined 'A-B/N' (range with step). If any workflow adopts a cron like '*/15 0-6 * * *' or '0 8-17/2 * * *', those slots silently drop. Add a regex for '(\d+)-(\d+)/(\d+)' before the existing range match. Tests already cover wildcard-step and range — add one case for '3-20/5'. (owner: kos-maintenance, type: quick-task)

## pr979.x Phase Candidates
- pr979.2: Drift-based runner health signal in CI -- Extend the maintenance workflow to treat chronic drift (>2h median) as a CI health signal. When detect-schedule-drift.cjs reports chronic workflows, post a targeted GitHub Issue (not just console output) with the drift data so it tracks across runs. Today the script exits 0 always ('observability tool') — chronic drift gets lost in workflow logs. (owner: kos-maintenance)
- pr979.1: Per-workflow drift thresholds in policy.json -- detect-schedule-drift.cjs uses a flat 2h threshold for all workflows. Not all workflows have equal SLAs — security-audit-weekly (runs once/week) tolerates more drift than daily maintenance. Add a 'schedule_drift_threshold_hours' override per workflow name in .github/policy.json, read by the script via --config flag. Aligns with the repo's existing policy.json governance pattern. (owner: kos-workflow-health-optimize)
