## Summary
PR #1208 replaces Auto Cover's seven per-PR REST calls with the shared GraphQL adapter plus a commits query, adds PR_FLOW_AUTO_COVER_SOURCE as rollback, scan-wide retry/wall budgets, and manifest.graphql quota accounting. Analysis found: the quota block has no production consumer (silent REST degradation is invisible), repo/name validation is duplicated between the fetcher and the shared lib, and two GraphQL helpers are imported from the 2848-line orchestrator. Phase-level: unify the two gh GraphQL transports, govern the growing PR_FLOW_*_SOURCE rollback-variable pattern, and build an Auto Cover REST↔GraphQL parity harness mirroring compare-review-input-sources.cjs.

## Quick Wins
- Consume manifest.graphql: warn when a scan degraded to REST -- fetch-auto-cover-context.cjs now writes manifest.graphql (cost/remaining/fallbackPrs) but grep shows zero production consumers — run-auto-cover-repairs.cjs never reads manifest.json. In the bash step right after the fetch in auto-cover-review.yml:211 and auto-cover-dispatch.yml:127, jq the manifest and emit a ::warning:: annotation + job-summary line when fallbackPrs is non-empty or remaining crosses a low-water threshold. Without this, the 7-call REST path the PR's own docs warn about can silently be back in production after a wall-budget or retry-budget spend. (owner: kos-audit-fix, type: quick-task)
- Dedupe assertRepoAndNumber into lib/review-inputs-graphql.cjs -- fetchPrCommitsGraphql's assertRepoAndNumber (fetch-auto-cover-context.cjs) re-implements the exact owner/name + positive-integer check already in lib/review-inputs-graphql.cjs:283-289 (throws via unavailable()). Export a plain validator from the lib and call it from both paths so the two cannot drift on edge cases (leading zeros, '1e2', empty segments). (owner: kos-audit-fix, type: quick-task)
- Extract buildGraphqlArgs + headCommittedAtFromCommits into lib/ -- fetch-auto-cover-context.cjs now requires the 2848-line orchestrate-pr-flow.cjs just for buildGraphqlArgs (:1617) and headCommittedAtFromCommits (:1683); compare-review-input-sources.cjs:220 also imports the latter. Move both pure helpers into a lib/ module (e.g. lib/graphql-transport.cjs), re-export from orchestrate-pr-flow.cjs for back-compat, and import from all three consumers — the context fetcher stops loading the full orchestrator module graph for two functions, and future transport tweaks land in one place. (owner: kos-audit-fix, type: quick-task)
- Test coverage for the two new GraphQL-only failure classes -- docs/workflow-e2e-scenarios.md C11b documents that timeout kills (isTimeoutKill: error.killed/ETIMEDOUT/SIGTERM) are retried as transient, and that 200-with-errors envelopes and transport-failure bodies (error.stdout) still feed rateLimit accounting. Both behaviors are only exercised via injected execFileSyncImpl fakes; the real 'gh' wiring (env passthrough, stdio pipes, JSON parse of trimmed stdout) has no harness. Add a small integration test that runs createAutoCoverGraphqlRunner against a stubbed gh binary to pin the contract. (owner: kos-audit-fix, type: workflow-improvement)

## pr1208.x Phase Candidates
- pr1208.2: Unify the two gh GraphQL transports into one budget-parameterized runner -- This PR deliberately built a second gh GraphQL transport (createAutoCoverGraphqlRunner in fetch-auto-cover-context.cjs: 64 MiB maxBuffer, 30s per-call timeout, scan-wide retry/wall budgets) beside orchestrate-pr-flow.cjs:1629's run('gh', buildGraphqlArgs(...), {retry: true}). A phase to unify both behind one parameterized runner in lib/ prevents the divergence-class bug pattern where a timeout/buffer/retry fix lands in one transport and not the other, and gives any future GraphQL consumer (compare-* scripts, monitor) the same budget semantics for free. (owner: kos-suggest-improvements)
- pr1208.1: Central governance for PR_FLOW_* source rollback variables -- The repo now has three PR_FLOW_*_SOURCE escape hatches, each with the same typo-safe resolver contract (unknown value -> the safe path, never the fast one): PR_FLOW_REVIEW_SOURCE in orchestrate-pr-flow.cjs, PR_FLOW_AUTO_COVER_SOURCE in fetch-auto-cover-context.cjs resolveAutoCoverSource (maps typos to the safe 'rest' path), and PR_FLOW_WORKER_RUNS_SOURCE in lib/worker-runs-by-head.cjs resolveWorkerRunsSource (maps typos to the safe 'legacy' per-workflow lookup, wired in pr-flow.yml). Each toggle independently needs docs (documentation.md), an e2e scenario row (C11b), typo-safe resolution and env-snapshot tests — duplicating that per toggle will miss one, so a phase scoped to only two of the three would omit worker-runs from the registry. A governance phase: first inventory all three resolvers with their docs and e2e rows, then add the shared resolveSource(name, {safe, fast}) helper plus a generated registry/table of all rollback vars and an e2e test asserting every unknown value resolves to the SAFE path, never the fast one. (owner: kos-suggest-improvements)
- pr1208.2: REST↔GraphQL parity harness for Auto Cover context files -- pr-flow already ships a read-only REST-vs-GraphQL parity script (compare-review-input-sources.cjs, also diffs head commit date and post/skip decisions). Auto Cover's swap rests on the mapped GraphQL objects matching the 8 written REST-shaped context files (comments, attempts, review-comments, reviews, commits, statuses, check-runs, pr.json incl. headCommittedAt) — currently guarded only by hand-built fixtures. An analogous compare-auto-cover-context-sources.cjs that runs both transports for the same PR set and field-diffs the artifacts catches unmapped/renamed REST fields (the class this PR patched: body, path, status, updated_at) on real data instead of fixtures. (owner: kos-suggest-improvements)
