## Summary
PR #1003 adds APR-E08 orphan-branch counting to audit-auto-prs.yml: runs cleanup-orphan-branches.cjs in dry-run, writes count to step summary, dispatches auto-pr-branch-cleanup.yml when count > 5. Clean implementation, good separation (existing script reused, new orchestration only). Found 3 concrete follow-ups.

## Quick Wins
- Extract hardcoded orphan threshold (5) into policy.json -- audit-auto-prs.yml:288 uses 'fromJSON(steps.orphan_check.outputs.orphan_count) > 5' with a magic number. policy.json already holds all other tunable thresholds (branch prefixes, age limits). Add 'orphanBranchThreshold: 5' to policy.json and read it via a step expression so operators don't need to edit workflow YAML to tune the trigger. (owner: kos-audit-auto-prs, type: quick-task)
- Add '--dry-run' output variable validation to cleanup-orphan-branches.cjs -- The script writes 'orphan_count' to GITHUB_OUTPUT (line 208) but only in the dry-run path. If the dry-run arg is malformed (e.g. '--dry-run yes'), dryRun evaluates to true (since it's not ''false''), so the count is emitted — but '--dry-run true' in audit-auto-prs.yml is passed as a shell string, not a boolean. The dispatch step uses '-f dry-run=false' which maps to workflow_dispatch input 'dry-run' (boolean). Add a '--dry-run' validation early in run() that rejects values other than 'true'/'false' with '::error::' and exit 1, matching the pattern already used by parseMaxAgeDays. (owner: kos-audit-auto-prs, type: quick-task)
- Add e2e scenario test for APR-E08 threshold-triggered dispatch -- cleanup-orphan-branches.test.cjs covers selectOrphanBranches/collectPolicyPrefixes thoroughly but there is no e2e test validating the audit-auto-prs → dispatch flow (orphan_count > threshold triggers gh workflow run). The P15c row in workflow-e2e-scenarios.md documents the contract; a corresponding e2e test exercising the threshold boundary (count=5 no dispatch, count=6 dispatch) would close the gap. (owner: kos-audit-auto-prs, type: workflow-improvement)

## pr1003.x Phase Candidates
- pr1003.1: Centralize all audit check thresholds in policy.json -- APR-E05, APR-E08, fleet-gate concurrency limits, and orphan thresholds are scattered across workflow YAML as magic numbers. A single 'auditThresholds' block in policy.json (mirroring the existing branch-prefix centralization) would give operators one place to tune all audit sensitivity knobs. (owner: kos-audit-auto-prs)
- pr1003.2: Add orphan-branch-count metric to structured audit output -- audit-auto-prs already emits structured_output (used by publish-digest). Orphan count is only in $GITHUB_STEP_SUMMARY (human-readable). Feeding it into structured_output would let downstream consumers (dashboards, alerting, the digest issue) track branch hygiene trends over time without scraping step summaries. (owner: kos-audit-auto-prs)
