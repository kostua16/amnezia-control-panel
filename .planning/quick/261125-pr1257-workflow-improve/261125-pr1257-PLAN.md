# Quick Plan: PR #1257 workflow improvement intake

## Source
- PR #1257: fix(prisma): make migration 20260617 apply to non-empty SQLite tables
- URL: https://github.com/kostua16/amnezia-control-panel/pull/1257

## Summary
PR 1257 rewrites the two SQLite-unsafe 'ALTER TABLE ... ADD COLUMN ... DEFAULT CURRENT_TIMESTAMP' statements in 'prisma/migrations/20260617_schema_hygiene_indexes_enums_timestamps/migration.sql' into table-recreation blocks (admins, user_quotas), adds README P3018/P3009 recovery docs for the already-shipped broken variant, and introduces '.gitattributes' with '* text=auto eol=lf' whose renormalization churns ~2.4MB of '.claude/skills' CSV/data files. Root-cause gap: no CI gate validates migrations apply to a non-empty SQLite database — 'prisma migrate deploy' runs first at container boot via 'docker/stack-entrypoint.sh:9' ('npx prisma migrate deploy --schema /app/prisma/schema.prisma --skip-generate' under 'set -e', so a P3018/P3009 aborts container startup before the Node scripts run) and at app startup via 'scripts/ensure-prisma-migrated.cjs' (called from 'scripts/dev.cjs' and 'scripts/start.cjs'), so the P3018 failure class ships to production and fails at boot. The same SQLite restriction was already known and documented in comments of two later migrations ('prisma/migrations/20260623034048_add_panel_fast_hash/migration.sql:5', 'prisma/migrations/20260927000000_add_server_redirect_ip/migration.sql:1-2'), but nothing enforces it. Secondary finding: the line-ending renormalization buries a critical data-preserving migration fix inside vendored-skill CSV churn, defeating pr-size-guard's signal.

## Quick Wins
- Add static guard for SQLite-unsafe ALTER TABLE ADD COLUMN in prisma/migrations -- The exact bug this PR fixes is statically detectable: 'ALTER TABLE ... ADD COLUMN' with a non-constant default ('CURRENT_TIMESTAMP', 'datetime()') fails on any populated SQLite table, and 'ADD COLUMN ... NOT NULL' without default fails likewise. Mirror the existing 'check-prisma-safe-sql.cjs' pattern: new '.github/workflows/scripts/check-sqlite-migration-safety.cjs' scanning 'prisma/migrations/**/migration.sql', wired as a step in the ci.yml Lint job next to 'Block Prisma unsafe raw SQL' (ci.yml:84-85). Would have rejected the original 20260617 statements at authoring time. Per docs/code-standards.md 'Workflow change protocol', must add the characterization test under '.github/workflows/scripts/__tests__/' and update 'docs/workflow-e2e-scenarios.md', keeping both 'npm run test-only' and 'node --test .github/workflows/scripts/__tests__/*.test.cjs' green (the CI form, ci.yml:124 — a repo-root 'scripts/__tests__/' glob resolves to an unrelated suite and gives a false-green). (owner: kos-audit-fix, type: quick-task)
- Isolate the .gitattributes line-ending renormalization from semantic fixes -- The new '.gitattributes' rule '* text=auto eol=lf' renormalized 13 '.claude/skills/**' data CSVs (~2.4MB of a 2.4MB diff), so a critical data-preserving migration fix is buried inside vendored-skill churn and pr-size-guard's warning fires on noise instead of signal. Add opt-outs in '.gitattributes' for generated/vendored skill data (e.g. '.claude/skills/**/data/** -text' or 'linguist-generated') and/or move the 'git add --renormalize .' result into a dedicated chore commit/PR so migration PRs stay reviewable. Verify the residual diff with 'git add --renormalize . && git diff --cached --stat'. (owner: gsd-quick, type: quick-task)
- Teach pr-policy.yml to label edits of already-applied migration directories -- pr-policy.yml currently only labels 'prisma/' changes as 'area/database' (pr-policy.yml:143). Extend its changed-file classifier to detect edits/deletes under 'prisma/migrations/' that are NOT the lexicographically-newest migration directory and attach a 'migration-history-edit' label plus an explanatory comment (edited migrations diverge from what deployed databases recorded, exactly the intentional drift this PR documents in README.md); the label must also be declared in the '.github/workflows/policy.json' 'labels' map ('ensure-workflow-labels.cjs' only creates declared labels) and added to the 'areaLabels' array in 'pr-policy.yml' (line 67) so the stale-label removal loop covers it. The label then gives reviewers and the auto-merge stack a concrete signal; characterizing it needs the standard e2e suite + 'docs/workflow-e2e-scenarios.md' row per the workflow change protocol. (owner: kos-audit-fix, type: quick-task)

## pr1257.x Phase Candidates
- pr1257.2: SQLite migration upgrade-path CI job (seeded-database replay) -- Today 'prisma migrate deploy' executes at container boot ('docker/stack-entrypoint.sh:9' under 'set -e') and at app startup ('scripts/ensure-prisma-migrated.cjs' invoked by 'scripts/dev.cjs'/'scripts/start.cjs'), and ci.yml has zero migrate steps, so a migration that only fails on non-empty tables reaches production and breaks boot (the P3018/P3009 incident this PR patches in README.md). Build a CI job triggered on 'prisma/migrations/**' changes that, for each migration boundary N: applies migrations 1..N-1 to a scratch SQLite file, inserts one row into every existing table using schema-derived minimal values per table (a generic one-row insert is not executable: 'admins' username/password and 'users' username/passwordHash are NOT NULL without defaults in 'prisma/migrations/20260428191601_init/migration.sql', and FK ordering matters even with 'PRAGMA foreign_keys=OFF'), runs 'prisma migrate deploy', and asserts success plus row survival. This catches the whole class the static lint cannot (bad INSERT column lists — note the PR's own comment that referencing a nonexistent column aborts mid-migration after earlier drops — FK ordering under 'PRAGMA foreign_keys=OFF', index recreation omissions). (owner: gsd-plan-phase)
- pr1257.3: Gate auto-merge on migration-history edits (human review required) -- Rewriting a shipped migration is the highest-blast-radius change class in this repo: deployments that already applied it keep the old statements and the divergence is only documented in prose (README.md's 'intentional drift' paragraph). Once the 'migration-history-edit' detection exists in pr-policy.yml, wire it into the approval stack: pr-finalizer/Mergify must not auto-merge a PR carrying that label until a maintainer acks it (dismiss or explicit approval), and the label should block the project-manager direct-merge path. This turns the lesson of 20260617 (and the earlier 20260623034048 / 20260927000000 precedent comments) into an enforced policy instead of comment-only knowledge. (owner: gsd-plan-phase)
- pr1257.4: Auto-inject migration conventions into GSD quick-task planning for prisma-touching tasks -- The 20260617 bug was authored through a '.planning/quick/' GSD session (artifacts in this PR), and the SQLite ADD COLUMN restriction was already written down in two later migration SQL comments the planner never saw. Add a domain-context hook to quick/planning intake: when a task's changed files or description match 'prisma|migrat|sqlite', the gsd-planner prompt auto-includes a curated conventions file (distilled from the migration comments, README recovery section, and the table-recreation pattern this PR establishes in 'prisma/migrations/20260617_schema_hygiene_indexes_enums_timestamps/migration.sql'). Closes the loop between run-mined failure knowledge and the agent session that authors the next migration. (owner: gsd-plan-phase)
