## Summary
PR #1075 adds WHO-E06: an auto-rerun preflight in workflow-health-optimize.yml's optimize job that reuses rerun-transient-failed-runs.cjs (MON-E04) with GH_PAT, feeds accepted rerun IDs into the optimizer prompt with transient-vs-permanent guidance, adds run_id to collected summaries, a static wiring e2e test, and a spec docs row. Wiring is sound (schedule/dispatch-only triggers keep the mutation in maintainer-controlled context; script's attempt>1 guard bounds retry loops). Follow-ups: preflight-failure ambiguity, missing step-summary observability vs MON-E04, serial preflight latency, and cross-schedule rerun governance/outcome feedback.

## Quick Wins
- Distinguish WHO-E06 preflight failure from 'none' and mirror MON-E04's step-summary ledger -- workflow-health-optimize.yml rerun_transient step has continue-on-error: true but the optimizer prompt only receives 'rerun_ids || 'none'' — a failed preflight (expired GH_PAT, 'run-list-failed' error path in rerun-transient-failed-runs.cjs:120) renders as 'none', so the optimizer may attribute transient failures to YAML defects. Pass steps.rerun_transient.outcome into the claude_run prompt ('rerun preflight status: succeeded|failed') and append the script's JSON ledger to $GITHUB_STEP_SUMMARY exactly as monitor-amnezia-control-panel-github-runs.yml:228-234 does for MON-E04. Extend the WHO-E06 test in rerun-transient-failed-runs.test.cjs to assert the outcome wiring, and update the WHO-E06 row in docs/workflow-e2e-scenarios.md. (owner: gsd-quick (workflow files + e2e suite), type: quick-task)
- Move the WHO-E06 rerun preflight into the collect-runs job to stop serial latency before claude_run -- classifyRun in rerun-transient-failed-runs.cjs:87 fetches 'gh run view --log-failed' serially for up to 10 runs (runGh timeout 30s each) — worst case ~5 minutes added inline in the optimize job before claude_run starts, all against inputs (since_timestamp, GH_TOKEN) already available in the collect-runs job where since_timestamp is produced (workflow-health-optimize.yml collect step). Moving the step to collect-runs (outputs flow via needs.collect-runs.outputs like since-timestamp already does) overlaps classification with the optimize job's checkout/bootstrap. Requires the same e2e test updates (steps lookup moves from jobs.optimize to jobs.collect-runs) and keeps continue-on-error semantics. (owner: gsd-quick (workflow files + e2e suite), type: quick-task)

## pr1075.x Phase Candidates
- pr1075.2: Rerun outcome feedback loop: persist MON-E04/WHO-E06 recovery ledgers and feed post-rerun status into the next WHO cycle -- Both schedules now rerun failed runs over overlapping windows (monitor since previous run, WHO since 1h ago) with only the post-hoc 'attempt > 1' guard in rerun-transient-failed-runs.cjs:142 — concurrent cycles can double-classify, and once a rerun is requested the optimizer permanently treats the run's outcome as unknown with no mechanism to revisit. Milestone-scale: persist the recovery ledger (schemaVersion 1 already emitted by buildRecoveryLedger) as an artifact or committed JSON, have collect-runs join previous rerun IDs with current run status so the optimizer sees final post-rerun conclusions, and dedupe classification across the two schedules. Touches rerun-transient-failed-runs.cjs, both workflows, the e2e suite, and docs/workflow-e2e-scenarios.md. (owner: workflow-health-optimize automation track (new WHO phase))
