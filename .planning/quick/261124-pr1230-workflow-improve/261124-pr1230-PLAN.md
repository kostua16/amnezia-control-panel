# Quick Plan: PR #1230 workflow improvement intake

## Source
- PR #1230: ci(rate-limit): per-job REST request counter
- URL: https://github.com/kostua16/amnezia-control-panel/pull/1230

## Summary
PR #1230 adds a job-local REST request counter (diagnostics_channel preload + post-step REST_COUNT report + log summarizer) wired into 9 of the 43 setup-environment workflows. Remaining gaps: ~34 workflows now emit uninstrumented noise with their github-script REST traffic uncounted, the gh CLI (dominant in shell-heavy jobs) stays invisible by design, and parseRestCount silently drops malformed reports during aggregation.

## Quick Wins
- Opt in the highest-volume scheduled workflows to the REST counter -- PR wires setup_environment + REST_COUNTER_PRELOAD only into _auto-fix-ci, antigravity*, deepseek-code-review, dependency-review, issue-catch-up, pr-flow, pr-improve, pr-policy. Scheduled fleet jobs (maintenance.yml, triage.yml, monitor-amnezia-control-panel-github-runs.yml, workflow-health-optimize.yml) keep calling github.rest.issues/labels uncounted while their post step reports status=uninstrumented. Add id: setup_environment + the guarded require() snippet to their github-script steps, matching the pattern asserted by checkRestCounterWiring in .github/workflows/scripts/__tests__/action-metadata-shape.test.cjs. (owner: workflow-maintainer, type: quick-task)
- Disable rest-counter for setup-environment jobs with no Node API traffic -- rest-counter defaults to 'true' in setup-environment/action.yml, so ~34 workflows (ci.yml, perf-check.yml, release-notes.yml, stale.yml, supply-chain.yml, etc.) whose jobs never run instrumented Node API calls now emit a status=uninstrumented REST_COUNT line every run. Pass rest-counter: 'false' in those setup-environment invocations (or set it in the composite steps that only run non-Node tooling) to cut telemetry noise; keep true only where an opt-in exists or is planned. (owner: workflow-maintainer, type: quick-task)
- Surface skipped REST_COUNT reports in summarize-rate-limit output -- parseRestCount in .github/workflows/scripts/summarize-rate-limit.cjs returns null when by_route counts don't sum to total or fields fail Number.isSafeInteger, and summarizeRestCounts drops those lines silently. Track a skipped count in summarizeRestCounts and emit skipped_reports=N in format() so aggregation gaps are visible instead of silently understating per-workflow totals. (owner: workflow-maintainer, type: quick-task)

## pr1230.x Phase Candidates

Phase: (1) opt in or explicitly disable counting across all remaining workflows, (2) add a scheduled workflow that fetches run logs via the API, pipes them through summarize-rate-limit.cjs, and publishes per-workflow/job totals (total, graphql, unavailable_jobs, unreadable_files) to a persistent summary/artifact, (3) update docs/workflow-e2e-scenarios.md with a G8f scenario for the aggregation run. Produces the baseline data needed to prioritize rate-limit budget work. (owner: workflow-maintainer)
- pr1230.2: gh CLI request accounting -- docs/workflow-e2e-scenarios.md (new 'Job-local GitHub API request counts' section) states gh traffic likely dominates shell-heavy jobs (~250 gh command mentions vs 60 github.rest mentions) but is outside the count because gh is a Go binary and a PATH shim cannot transparently count HTTP requests. Phase: evaluate and implement a gh visibility approach — PATH shim counting invocations plus GH_DEBUG=http output parsing, or migrate the hottest gh call sites (pr-flow orchestration, watchdog, catch-up loops) into instrumented Node scripts so the preload sees them. (owner: workflow-maintainer)
- pr1230.1: Governance rule: every setup-environment consumer declares counter intent -- The new e2e checkRestCounterWiring test validates wiring inside opted-in steps but nothing forces new workflows to decide. Add a workflow-governance check (workflow-governance.yml + helper script) asserting each workflow using ./.github/actions/setup-environment either wires REST_COUNTER_PRELOAD into its API-touching steps or passes rest-counter: 'false' — otherwise flag it. Codifies the opt-in contract in docs/workflow-e2e-scenarios.md so the uninstrumented signal stays meaningful as workflows multiply. (owner: workflow-maintainer)
