# Quick Plan: PR #1252 workflow improvement intake

## Source
- PR #1252: ci(rate-limit): count gh CLI REST calls and wire remaining jobs
- URL: https://github.com/kostua16/amnezia-control-panel/pull/1252

## Summary
PR #1252 adds a Linux gh CLI PATH-shim counter (gh-counter.cjs + rest-routes.cjs route classifier), via={node,gh} source split in REST_COUNT reports, and wires preload into ~11 workflows plus 4 composite actions. Remaining gaps: ~15 workflows still run node API scripts uninstrumented, the wiring test checks env presence but not the guarded require body, and report-failed inflates gh_unavailable_reports.

## Quick Wins
- Wire REST_COUNTER_PRELOAD into remaining API-heavy workflows' node script steps -- PR wires 11 workflows, but base still has maintenance.yml (3 'node .github/workflows/scripts/' steps, 16 gh calls), triage.yml (2/15), pr-finalizer.yml (6/10), monitor-amnezia-control-panel-github-runs.yml (4/8), gsd-planning-execute.yml (6/4), audit-auto-prs.yml, audit-fix.yml, project-manager.yml, rebase-pr.yml, merge-pr.yml, perf-check.yml, planning-intake-repair.yml whose node steps run without 'preload=(--require "$REST_COUNTER_PRELOAD")' — their github.rest/fetch calls stay uncounted even though the new gh shim covers CLI calls via setup-environment. Apply the existing code-review.yml step pattern and update docs/workflow-e2e-scenarios.md. (owner: kos-audit-fix, type: quick-task)
- Extend checkRestCounterWiring to assert the guarded require body, not just env presence -- action-metadata-shape.test.cjs checkRestCounterWiring only asserts env.REST_COUNTER_PRELOAD is set on actions/github-script steps. The 5-line 'try { require(process.env.REST_COUNTER_PRELOAD) } catch' preamble is hand-copied into ~12 places (code-review.yml, report-failure/action.yml x3, run-claude-params, collect-workflow-failure-context, auto-pr-branch-cleanup x2, docker-image.yml, fix-pr.yml, workflow-health-optimize.yml); a step that keeps the env but loses the require silently reports status=uninstrumented. Assert the script body contains 'require(process.env.REST_COUNTER_PRELOAD)' when the env is set. (owner: kos-audit-fix, type: quick-task)
- Stop counting reason=report-failed as CLI-unavailable in summarize-rate-limit.cjs -- parseRestCount sets 'ghUnavailable: unavailable[1] === 'report-failed'', and summarizeRestCounts then increments gh_unavailable_reports for it. report-failed means the post action itself could not build the report (Node reporting path) — the CLI counter may be healthy, and the job is already visible via unavailable_jobs. Drop the special case (or gate ghUnavailable on actual gh_status/gh_reason evidence) so gh_unavailable_reports tracks only real CLI-counter outages like launcher-shadowed or node-unusable. (owner: kos-audit-fix, type: quick-task)
