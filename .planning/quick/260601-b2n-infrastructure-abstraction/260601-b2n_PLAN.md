# Quick Task 260601-b2n: Infrastructure abstraction — HTTP client + command executor

## Problem

**HTTP calls:** 8 files do raw `fetch()` with ad-hoc timeout handling (`AbortSignal.timeout(15000)` repeated), inconsistent error patterns, and no retry logic. `panel-health-checker.ts` (369 lines) mixes DB access, HTTP, business logic, and WebSocket broadcasting.

**Shell commands:** 5 files call `execFile`/`execFileSync` directly — `tailscale.ts`, `resource-monitor.ts`, `service-monitor.ts`, `server-connection.ts`, `vpn-services.ts` — each with its own timeout handling, error wrapping, and platform assumptions.

**Data access:** 15+ files make direct Prisma calls. Service layer exists but is used inconsistently — alerts and chain-presets go through services, users and servers go direct.

## Scope

### 1. Create shared HTTP client
- **files**: Create `src/lib/http-client.ts`
- **action**:
  - Wrap `fetch` with configurable timeout (default 15s), retry (1 attempt on 5xx), error enrichment
  - Include request/response logging in dev mode
  - Handle JSON parsing consistently
  - ~60-80 lines
- **verify**: Unit test with mocked fetch confirming timeout, retry, and error enrichment behavior
- **done**: `http-client.ts` exported and usable

### 2. Create shared command executor
- **files**: Create `src/lib/command-executor.ts`
- **action**:
  - Wrap `execFile` with configurable timeout, error standardization, and platform detection
  - Provide `execCommand(cmd, args, opts)` and `execCommandSync(cmd, args, opts)`
  - Log command + duration in dev mode
  - ~50-70 lines
- **verify**: Unit test confirming timeout throws, error includes command name
- **done**: `command-executor.ts` exported and usable

### 3. Migrate call sites (incremental)
- **files**: `config-applier.ts`, `panel-health-checker.ts`, `panel-sync-client.ts`, `tailscale.ts`, `resource-monitor.ts`, `service-monitor.ts`, `server-connection.ts`, `vpn-services.ts`
- **action**:
  - Replace raw `fetch` calls with `httpClient` in 3-4 files (priority: `config-applier.ts`, `panel-sync-client.ts`, `panel-health-checker.ts`, `geoip-manager.ts`)
  - Replace raw `execFile` calls with `execCommand` in 3-4 files (priority: `tailscale.ts`, `service-monitor.ts`, `resource-monitor.ts`, `server-connection.ts`)
  - Each migration is a separate commit for safe rollback
- **verify**: Dev server starts; panel health checks work; config push works; GeoIP refresh works
- **done**: 6-8 call sites migrated to shared abstractions

### 4. Decompose panel-health-checker.ts (stretch goal)
- **files**: `src/lib/panel-health-checker.ts`
- **action**:
  - Extract DB queries to inline repository functions at top of file
  - Extract HTTP calls to use new `httpClient`
  - Keep orchestration logic in main file
  - Target: main file under 200 lines, helper sections clearly separated
- **verify**: Panel health dashboard shows same data; alerts fire correctly
- **done**: `panel-health-checker.ts` under 200 lines
