# Quick Plan: PR #1260 workflow improvement intake

## Source
- PR #1260: fix: resolve #1247 - [maintenance] Daily maintenance failed
- URL: https://github.com/kostua16/amnezia-control-panel/pull/1260

## Summary
PR #1260 hardens the daily maintenance sweep after run #1247's failure: adds a validated 90-day UTC cutoff step and a dated 'gh issue list --search created:<cutoff' (replacing freeform agent judgement), expands allowed-tools with rtk-prefixed gsd-tools/df grants, adds a TOOL GRANTS prompt contract (one shell op per call, no temp files, exact-form pins for validate.health / npm audit / git log), a single-line plain-text issue-body rule, and a new maintenance-tool-grants.test.cjs pinning the allowlist against the prompt (run-zai settings-isolation assertions split into their own test file). Follow-ups target three gaps the fix leaves open: the skill mirror was not updated, truncation of the 100-issue search is summary-only, and the paraphrase rule trades body fidelity for shell safety. Roadmap-scale work: generalize the grant-coverage check repo-wide, single-source the sweep policy, and route planning-health drift into planning PRs.

## Quick Wins
- Mirror new stale-sweep rules into kos-daily-maintenance-sweep skill -- PR #1260 added the single-line plain-text issue-body rule and the dated 'gh issue list --state open --search "created:<… sort:updated-desc" --limit 100' command to the maintenance.yml prompt (lines 54, 61) and to '.claude/agents/kos-maintenance.md' (Tools and Techniques), but '.claude/skills/kos-daily-maintenance-sweep/SKILL.md' still describes the stale sweep without either rule (its step 5 at SKILL.md:47 covers skip labels only). The updated docs row MNT-I08a in docs/workflow-e2e-scenarios.md now claims "the maintenance agent and skill document the skip rules" — the skill is already behind. Mirror both rules into the skill and extend maintenance-tool-grants.test.cjs (or the MNT-I08a characterization) to pin the agent/skill mirror so the three surfaces cannot drift. (owner: kos-maintenance, type: quick-task)
- Add structured truncation flag to stale-issues schema -- The new prompt instruction "If the result count reaches the requested limit, note in the summary that additional matches may remain" writes truncation into the free-text 'summary' field only. The json-schema pinned at maintenance.yml:112 gives 'stale-issues' just findings_count/issue_created/skip_reason, so run-monitoring cannot alert on a silently truncated sweep. Add an optional 'limit_reached' boolean to the stale-issues category and update maintenance-sweep-schema.test.cjs (which pins the schema per MNT-I10a) plus the prompt's reporting instruction to set it. (owner: kos-maintenance, type: quick-task)
- Use 'gh issue create --body-file -' heredoc instead of paraphrasing issue bodies -- The fix's quoting rule — "Paraphrase any text containing backticks, dollar signs, backslashes, or double quotes before putting it in the body" — is a workaround for '--body "…"' double-quote shell expansion, and it forbids markdown (lists, code fences) in security/stale/TODO issue bodies, degrading every filed issue. 'gh issue create --body-file -' with a quoted heredoc reads the body from stdin: no shell expansion of issue content, no temp file, no /tmp redirect, fully compatible with the new TOOL GRANTS constraints and the already-granted 'gh issue create:*'. Swap the rule in maintenance.yml prompt + kos-maintenance.md for the heredoc form and update the maintenance-tool-grants.test.cjs prompt-command pins accordingly. (owner: kos-maintenance, type: quick-task)

## pr1260.x Phase Candidates
- pr1260.2: Generalize prompt-vs-grants coverage checks to all run-zai workflows -- maintenance-tool-grants.test.cjs (new in PR #1260) embeds two reusable checks — the 'covers()' grant matcher and the '/'([a-z][a-z0-9-]*(?: [^'\n]+)+)'/g extraction of backticked commands from a prompt — but applies them only to maintenance.yml. Over ten other workflows (fix-issue.yml, code-review.yml, docs-drift.yml, audit-fix.yml, audit-auto-prs.yml, triage, etc.) pass 'allowed-tools' to run-zai with prompts that name shell commands, and nothing verifies prompt commands are covered by their grants; the exact failure mode #1247 was filed for (agent invokes a command form the allowlist denies) can recur in any of them. Extract the matcher/extraction into scripts/__tests__/helpers/prompt-grants.cjs and fan out per-workflow expectations, keeping each workflow's exact-form pins (like 'npm audit --json') explicit. (owner: kos-workflow-health-optimize)

Wire the planning-health findings into that intake so desync between .planning/STATE.md and ROADMAP.md opens an actionable planning PR (auto-mergeable, like other planning workflow PRs) instead of a 'maintenance'-labeled issue, closing the loop between the daily sweep and the GSD planning automation that #1251 showed is needed after every GSD upgrade. (owner: kos-gsd-command-routing)
