## Summary
PR #1260 hardens the daily maintenance sweep after run #1247's failure: adds a validated 90-day UTC cutoff step and a dated 'gh issue list --search created:<cutoff' (replacing freeform agent judgement), expands allowed-tools with rtk-prefixed gsd-tools/df grants, adds a TOOL GRANTS prompt contract (one shell op per call, no temp files, exact-form pins for validate.health / npm audit / git log), a single-line plain-text issue-body rule, and a new maintenance-tool-grants.test.cjs pinning the allowlist against the prompt (run-zai settings-isolation assertions split into their own test file). Follow-ups target three gaps the fix leaves open: the skill mirror was not updated, truncation of the 100-issue search is summary-only, and the paraphrase rule trades body fidelity for shell safety. Roadmap-scale work: generalize the grant-coverage check repo-wide, single-source the sweep policy, and route planning-health drift into planning PRs.

## Quick Wins
- Mirror new stale-sweep rules into kos-daily-maintenance-sweep skill -- PR #1260 (merged 2026-11-26) added two rules the skill does not mirror: the single-line plain-text issue-body rule ("Write issue bodies as single-line plain text enclosed in ordinary double quotes. Paraphrase any text containing backticks, dollar signs, backslashes, or double quotes before putting it in the body.") and the dated 'gh issue list --state open --search "created:<cutoff sort:updated-desc" --limit 100' command. Both live in the maintenance.yml prompt; the body rule is also mirrored in '.claude/agents/kos-maintenance.md'. '.claude/skills/kos-daily-maintenance-sweep/SKILL.md' has neither rule — its stale-sweep text (the category-5 entry at SKILL.md:47 and the disposition line near :72) documents the skip-label exemptions only. The docs row MNT-I08a in docs/workflow-e2e-scenarios.md claims "the maintenance agent and skill document the skip rules" — that claim is already true for skip rules; the actual gap is only these two new rules. Mirror both into the skill, update the MNT-I08a row (or its characterization) to cover them, and extend maintenance-tool-grants.test.cjs to pin the agent/skill mirror so the surfaces cannot drift. (owner: kos-maintenance, type: quick-task)
- Add structured truncation flag to stale-issues schema -- The prompt instruction "If the result count reaches the requested limit, note in the summary that additional matches may remain" writes truncation into the free-text 'summary' field only. The json-schema in maintenance.yml gives 'stale-issues' just findings_count/issue_created/skip_reason, so run-monitoring cannot alert on a silently truncated sweep. Add a 'limit_reached' boolean to the stale-issues category, set to true exactly when the returned result count equals the '--limit 100' value (not left to agent judgement), and update the prompt's reporting instruction accordingly. maintenance-sweep-schema.test.cjs (the 'per-category outcome schema is identical and complete for every category' test) asserts every category deep-equals one shared outcome object, so this is a schema-shape decision, not a one-line edit: extend 'limit_reached' to all five categories and widen the shared expected shape in that test — do not carve out a stale-issues-only exception and do not weaken the shared-shape assertion to get green. (owner: kos-maintenance, type: quick-task)
- Use 'gh issue create --body-file -' heredoc instead of paraphrasing issue bodies -- The fix's quoting rule — "Paraphrase any text containing backticks, dollar signs, backslashes, or double quotes before putting it in the body" — is a workaround for '--body "…"' double-quote shell expansion, and it forbids markdown (lists, code fences) in security/stale/TODO issue bodies, degrading every filed issue. 'gh issue create --body-file -' with a quoted heredoc reads the body from stdin: no shell expansion of issue content, no temp file, no /tmp redirect, fully compatible with the new TOOL GRANTS constraints and the already-granted 'gh issue create:*'. Swap the rule in maintenance.yml prompt + kos-maintenance.md for the heredoc form and update the maintenance-tool-grants.test.cjs prompt-command pins accordingly. (owner: kos-maintenance, type: quick-task)
