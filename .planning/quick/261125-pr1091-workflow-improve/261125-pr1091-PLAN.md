# Quick Plan: PR #1091 workflow improvement intake

## Source
- PR #1091: fix(ci): make stale PR consolidation decisions explicit
- URL: https://github.com/kostua16/amnezia-control-panel/pull/1091

## Summary
PR #1091 makes merge-pr selection decisions explicit (decision_code / disposition / consolidation_eligible / closure_policy per group), fixes fail-closed --dry-run parsing in run-merge-pr-selection.cjs, renders one stable per-group table with per-PR closure labels in upsert-merge-pr-report.cjs, and adds a full characterization suite (run-merge-pr-selection.test.cjs, MP1c/MP7b/MP8–MP12 scenarios). Follow-ups found in the base checkout: (1) the flag-safe getArg + isDryRun fix landed in exactly one of 40+ script-local getArg copies, and repair-planning-intake.cjs:315 / upsert-planning-pr.cjs:343 still parse --dry-run with the naive getArg AND default to write mode — the exact misparse class MP1c guards against; (2) enrichGroup now emits dual spellings (id/group_id, recommended_action/action, reason/rejection_reason) with renderer fallbacks and no downstream consumer of the legacy spellings or of the selection step outputs (only steps.report.outputs.report_path is read anywhere); (3) decisionForAction silently funnels unknown actions into MANUAL_REVIEW_UNKNOWN_ACTION with no registry-drift test tying recommendActionForGroup's action set to explicit branches. Milestone-scale: the write/close path is still a stub (closure_results hardcoded not-attempted even with --dry-run false, per merge-pr.yml:12-16,167 and .planning/ideas/merge-pr-plan.md), replacement-PR merge governance for the new decision records is undecided, and unsafe groups (e.g. workflow-877) live only in the daily #859 report with no path into the issue/triage backlog.

## Quick Wins
- Port the flag-safe getArg + fail-closed isDryRun to the sibling scripts that still default to write mode -- PR fixed the misparse only in run-merge-pr-selection.cjs:11 (value starting with -- no longer adopted as the flag's value) plus isDryRun (only explicit 'false' enables writes). repair-planning-intake.cjs:315 and upsert-planning-pr.cjs:343 still do naive getArg('--dry-run', 'false') === 'true': a bare --dry-run before another flag adopts '--out-dir' as the value and lands in WRITE mode, and even a correct parse defaults to write. Extract the guarded getArg(name, fallback, argv) + isDryRun into one shared helper (e.g. scripts/lib/argv.cjs, matching the existing __tests__/helpers/ shared-module precedent) used by run-merge-pr-selection.cjs, repair-planning-intake.cjs, upsert-planning-pr.cjs, and add MP1c-style parsing tests per consumer; run both gates (npm run test-only and node --test .github/workflows/scripts/__tests__/*.test.cjs) per the workflow change protocol. (owner: gsd-quick (workflow scripts), type: quick-task)
- Add a registry-drift guard test: every action recommendActionForGroup can emit must have an explicit decisionFor branch -- decisionForAction in run-merge-pr-selection.cjs funnels any unrecognized recommended_action into MANUAL_REVIEW_UNKNOWN_ACTION — a safe fallback, but nothing ties it to the grouping layer: if someone adds a new action in merge-pr-logic.cjs's recommendActionForGroup, selection silently degrades it to manual-review. Add a characterization test in run-merge-pr-selection.test.cjs that builds groups covering each action recommendActionForGroup can return (consolidate / rebase-first / manual-review / report-only, per merge-pr-logic.cjs:132) and asserts none resolves to DECISION_CODES.MANUAL_REVIEW_UNKNOWN_ACTION — so a new grouping action fails selection tests until an explicit decision branch + REJECTION_REASONS entry exists. Mirrors the per-file coverage assertions already used by checkout-before-local-action.test.cjs to keep scanners from passing vacuously. (owner: gsd-quick (e2e suite), type: quick-task)
- Collapse or invariant-test the dual field spellings and the changed safe_group_count output -- enrichGroup now emits both id+group_id, recommended_action+action, and reason+rejection_reason, and upsert-merge-pr-report.cjs falls back between spellings (g.group_id ?? g.id, g.action ?? g.recommended_action). Grep shows no consumer of the legacy spellings: merge-pr.yml reads only steps.report.outputs.report_path, and selected_json / skipped_json / safe_group_count / has_safe_group outputs have no readers in any workflow — the outputs are staging for the deferred write path. Pick canonical names (group_id / action / decision_code), drop the duplicates and renderer fallbacks (or, if the write path will keep reading id, add an invariant test asserting both spellings are always equal in merge-pr-groups.json), and rename or document safe_group_count, whose semantics silently changed to selected + capped_deferred — a future consumer reading 'safe' as 'actionable now' would wrongly treat capped-deferred groups as selected. (owner: gsd-quick (workflow scripts), type: quick-task)
