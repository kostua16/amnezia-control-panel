# Quick Plan: PR #885 workflow improvement intake

## Source
- PR #885: fix: resolve #882 - WHO-I08: Harden post-agent steps against wasted agent spend (workflow-health-optimize)
- URL: https://github.com/kostua16/amnezia-control-panel/pull/885

## Summary
PR #885 hardens workflow-health-optimize.yml against duplicate-detection failures by adding continue-on-error + warning step. 6 other workflows use the same find-duplicate-automation-pr.cjs script without this hardening — any script failure in those workflows wastes prior agent work identically.

## Quick Wins
- Apply WHO-I08 continue-on-error hardening to remaining duplicate-detection steps -- 6 other workflows (audit-auto-prs.yml:123, fix-issue.yml:234, gsd-planning-execute.yml:311+530, maintenance.yml:143, monitor-amnezia-control-panel-github-runs.yml) run find-duplicate-automation-pr.cjs without continue-on-error. A script crash in any of them kills the job and wastes the Claude agent's prior edits, the exact failure mode WHO-I08 fixed in workflow-health-optimize.yml. Each needs the same continue-on-error: true + ::warning:: step pattern from this PR. (owner: kos-workflow-health-optimize, type: quick-task)
- Extract duplicate-detection hardening into a shared composite action -- The continue-on-error + warn-on-failure + downstream-outcome-check pattern is now copy-pasted logic. A composite action wrapping find-duplicate-automation-pr.cjs with built-in failure tolerance would eliminate the 7-site copy-paste drift risk and ensure future hardening (e.g. retry, degraded-mode output defaults) propagates automatically. (owner: kos-gh-automation-tooling, type: workflow-improvement)
- Add ::warning:: annotation to gate step when duplicate detection failed -- In workflow-health-optimize.yml:409, the validate gate step runs when duplicate_found != 'true'. After a detection failure (outputs empty), this silently proceeds without dedup — the warning step fires but the gate step itself doesn't annotate its own skip-of-dedup. A conditional ::warning:: on the gate step would make it visible in the run summary that dedup was bypassed. (owner: kos-workflow-health-optimize, type: quick-task)

## pr885.x Phase Candidates
- pr885.1: Policy: all post-agent network steps must be continue-on-error with warning -- WHO-I08 is a specific instance of a general pattern: any step after a Claude agent run that calls external APIs (gh, curl, duplicate detection) can fail independently of the agent's work. A central workflow policy in docs/code-standards.md or a shared action contract would codify this as a trust gate — post-agent steps are advisory, never blocking. (owner: workflow-standards)
- pr885.2: E2e test: verify duplicate-detection failure doesn't block PR creation -- docs/workflow-e2e-scenarios.md tracks e2e scenarios. Add a scenario for workflow-health-optimize where find-duplicate-automation-pr.cjs exits non-zero, asserting that the optimization PR is still created (with the ::warning:: annotation). Currently no e2e coverage for this failure path. (owner: kos-e2e)
