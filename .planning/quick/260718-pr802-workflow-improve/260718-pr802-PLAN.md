# Quick Plan: PR #802 workflow improvement intake

## Source
- PR #802: fix(workflows): route parked dead letters to retry before priority escalation
- URL: https://github.com/kostua16/amnezia-control-panel/pull/802

## Summary
PR #802 fixes a routing-order bug in issue-catch-up.yml where priority_escalation captured high/critical parked dead letters before the dead-letter retry branch could run, causing hourly reminder spam (18 copies on #759) and permanently blocking the one-shot fresh-context retry. The fix defers escalation routing to after comments are fetched, adds a 24h nudge dedupe, detects inert bot attempts to waive the 7-day cooldown for legacy pre-repair dead letters, and holds manually parked issues from re-triage. New behavioral test suite (issue-catch-up-collect.test.cjs) executes the real embedded collect script against fixture issues. Two tactical follow-ups and two phase-scale suggestions identified.

## Quick Wins
- Replace shouldNudgePriority body-text match with an HTML comment marker -- issue-catch-up.yml:175 uses 'includes('Priority issue awaiting attention')' for the 24h dedupe — a weak contract that breaks silently if the reminder text is copy-edited. The workflow already uses deterministic markers elsewhere ('', ''). Add '' to the Phase 3 comment template at issue-catch-up.yml:845 and gate 'shouldNudgePriority' on that marker instead. Update the NUDGE_COMMENT fixture in issue-catch-up-collect.test.cjs:238 to include the marker. (owner: kos-issue-catch-up, type: quick-task)
- Remove hardcoded owner login from test fixture default author -- issue-catch-up-collect.test.cjs:185 hardcodes 'login: 'kostua16'' as the default author in makeIssue(). If tests run in a fork or the repo ownership changes, every fixture issue appears human-authored by the actual owner, which could silently flip auto_fix_eligible or trigger association-based trust gates. Use '{ login: 'test-user', type: 'User' }' as the default instead. (owner: kos-issue-catch-up, type: quick-task)
