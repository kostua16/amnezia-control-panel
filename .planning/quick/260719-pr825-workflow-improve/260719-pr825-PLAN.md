# Quick Plan: PR #825 workflow improvement intake

## Source
- PR #825: fix: resolve #820 - [audit-auto-prs] Auto PR audit workflow failed
- URL: https://github.com/kostua16/amnezia-control-panel/pull/825

## Summary
PR #825 adds transient-cancellation guards in two composite actions (report-failure Rule 2c for cancelled steps, run-claude-params cancelled-outcome early exit). The fix is correct but has gaps in test coverage and a parallel transient-detection system that should be aligned.

## Quick Wins
- Add e2e tests for cancelled-step outcome in run-claude-params and report-failure -- PR #825 adds Rule 2c (OUTCOME=cancelled → failed=false) in run-claude-params/action.yml:1028 and a CLAUDE_STEP_OUTCOME=cancelled guard in report-failure/action.yml:354, but neither path has e2e test coverage. Existing test files (e2e-pr651-flows.test.cjs) cover report-failure always() guards but not the new cancellation-skipping behavior. Without tests, a regression could silently re-introduce the #820 false-positive failure reports. (owner: claude, type: quick-task)
- Align report-failure cancelled guard with collect-workflow-failure-context transient patterns -- collect-workflow-failure-context/action.yml:112 already matches /Runner cancelled/i as a transient pattern and sets is_transient=true. report-failure's new CLAUDE_STEP_OUTCOME=cancelled check is a second independent cancellation signal that could diverge from the transient patterns list. Documenting the relationship or unifying detection prevents drift where one action recognizes a cancellation the others miss. (owner: claude, type: quick-task)
- Update run-claude-params rules comment block to include Rule 2c -- The new Rule 2c (cancelled → failed=false) is inserted between Rule 2 and Rule 3 but the action.yml comments above the classify block still list Rules 1-7 from before this PR. Stale rule documentation leads to future maintainers misunderstanding the classification order. (owner: claude, type: quick-task)

## pr825.x Phase Candidates
- pr825.2: Centralized step-outcome classification with shared cancellation-detection module -- Three actions now independently detect cancellation/transient states: run-claude-params (OUTCOME=cancelled), report-failure (CLAUDE_STEP_OUTCOME=cancelled), and collect-workflow-failure-context (regex on logs). A shared classify-step-outcome script would be a single source of truth, preventing drift where one action recognizes a cancellation signal the others miss. (owner: claude)
- pr825.2: Workflow-level retry policy for transient runner cancellations -- PR #825 treats cancelled runs as transient infra and silently skips failure reporting, but the workflow still consumes a concurrency-group slot. A retry-on-cancelled policy for scheduled workflows (maintenance, monitor, audit-auto-prs) would recover those slots automatically instead of waiting for the next schedule. (owner: claude)
