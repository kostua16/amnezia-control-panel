# Quick Task 260601-c3m: Schema hygiene — migrations, indexes, enum promotion

## Problem

The Prisma schema has drifted significantly from the single initial migration:
- **7 models** exist in `schema.prisma` but have no corresponding migration SQL (ConfigTemplate, GeoRoutingRule, RoutingRuleTemplate, ChainPreset, RemotePanel, PanelConnectionHistory, CachedPanelConfig)
- **No indexes** on fields used in frequent `where` clauses: `User.isActive`, `User.isBlocked`, `Service.type`, `Service.status`, `UserProtocol.isActive`, `Configuration.isActive`
- **6 string fields** should be Prisma enums but are documented as string unions in comments: `GeoRoutingRule.matchType`, `GeoRoutingRule.source`, `ChainPreset.topology`, `RoutingRuleTemplate.category`
- **10 models** missing `updatedAt` timestamps (Server, Service, TrafficLog, RoutingRule, Alert, UserQuota, UserProtocol, Admin, Configuration, ConfigTemplate)
- `User.trafficQuotaBytes` is redundant with the `UserQuota` relation — dual-source of truth

## Scope

### 1. Generate missing migration
- **files**: `prisma/schema.prisma`, `prisma/migrations/`
- **action**:
  - Run `npx prisma migrate diff --from-migrations prisma/migrations --to-schema-datamodel prisma/schema.prisma --script` to generate the delta SQL
  - Review SQL for correctness (no data loss on existing tables)
  - Create `prisma/migrations/20260601_add_missing_models_and_indexes/migration.sql`
  - Run `npx prisma migrate resolve --applied 20260601_add_missing_models_and_indexes` if DB already has the tables
- **verify**: `npx prisma migrate status` shows no drift; `npx prisma validate` passes
- **done**: Single migration that brings DB in sync with schema

### 2. Add performance indexes
- **files**: `prisma/schema.prisma`
- **action**: Add `@@index` directives to:
  ```
  User:        @@index([isActive]), @@index([isBlocked])
  Service:     @@index([type]), @@index([status])
  UserProtocol: @@index([isActive])
  Configuration: @@index([isActive])
  ```
- **verify**: New migration includes `CREATE INDEX` statements; query plan for `WHERE isActive = 1` uses index
- **done**: 7 new indexes covering most-filtered columns

### 3. Promote string-as-enum fields to Prisma enums
- **files**: `prisma/schema.prisma`
- **action**:
  - Create enums: `GeoMatchType` (COUNTRY, REGION, SPECIAL), `GeoRuleSource` (CUSTOM, IMPORTED, TEMPLATE), `ChainTopology` (LINEAR, SPLIT, MESH), `RoutingTemplateCategory` (GEO, IP, DOMAIN, BUNDLE)
  - Change field types from `String` to enum types
  - Add migration to convert existing string data
- **verify**: Existing data migrates correctly; TypeScript types are narrower
- **done**: 4 new enums replacing string fields with documented unions

### 4. Add missing updatedAt timestamps
- **files**: `prisma/schema.prisma`
- **action**: Add `updatedAt DateTime @updatedAt` to: Server, Service, RoutingRule, Alert, UserQuota, UserProtocol, Admin, Configuration, ConfigTemplate
  - Skip TrafficLog (append-only, timestamp sufficient)
- **verify**: `prisma validate` passes; new migration adds columns
- **done**: 9 models gain updatedAt audit field

### 5. Remove User.trafficQuotaBytes redundancy (stretch)
- **files**: `prisma/schema.prisma`, `src/app/api/users/`, `src/lib/quota-monitor.ts`
- **action**:
  - Audit all reads/writes of `User.trafficQuotaBytes` vs `UserQuota`
  - Migrate to single source (UserQuota relation)
  - Remove field from schema
- **verify**: No references to `trafficQuotaBytes` in codebase; quota functionality works
- **done**: Single source of truth for user quotas
