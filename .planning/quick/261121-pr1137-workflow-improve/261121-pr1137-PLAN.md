## Summary
PR #1137 auto-fixes npm audit findings from run 44955406659: next 16.3.6→16.4.6 (GHSA-rhh4-g77r-r9qj), brace-expansion 5.0.8→5.0.13, minimatch@3-scoped brace-expansion 1.1.22 (review-corrected from unscoped key that also forced 1.x into minimatch@11), new exact 'effect: 3.22.5' override (@prisma/config pins effect@3.20.0 exact so audit fix cannot move it), plus lockfile refresh (prisma 7.10.1, typescript-eslint 8.73.0, sharp 0.35.5). Gaps: override pins have no CI resolution check (npm only warns on inert overrides), the docs/npm-overrides.md review policy is prose-only (no pr-policy enforcement), and agent-authored dependency PRs (#1133→#1137 chain) had no owner-based approval gate (no CODEOWNERS).

## Quick Wins
- Add override pin-resolution gate to supply-chain.yml -- the supply-chain.yml validate job only runs 'npm audit signatures' (continue-on-error, so it enforces nothing) and 'npm audit --audit-level=high'; its other steps (workflow-governance-check.cjs action-pin verification, lockfile-v3 assertion) never inspect overrides; nothing verifies the pins actually resolve. npm silently downgrades inert override keys to a warning, so a future prisma release that moves or drops the 'effect' dependency relative to '@prisma/config', or a dependency refresh that adds a brace-expansion 1.x consumer outside the minimatch@3 subtree the version-qualified key reaches, could leave effect or brace-expansion 1.x resolving unpinned and reopen GHSA-7589-6fvf-x4pw / the 2026 brace-expansion advisories with a green CI. The pins to guard are the two exact, version-qualified keys in package.json 'overrides': '@prisma/config.effect': 3.22.5 and 'minimatch@^3.0.0.brace-expansion': 1.1.22; there is no top-level brace-expansion override (removed as a no-op on 2026-11-22, see docs/npm-overrides.md), and the nested brace-expansion@5.0.13 under minimatch@11 is resolved by minimatch@11's own '^5.0.12' range, so no override owns it. Add a small .github/workflows/scripts/ check that maps each of those keys to the dependency path it owns and asserts the version npm reports at that path equals the pinned value: 'effect' under '@prisma/config' must be 3.22.5 and every 'brace-expansion' under a minimatch@3 copy must be 1.1.22 ('npm ls effect brace-expansion --all' marks exactly those paths 'overridden'). Do not compare the flat set of reported versions against the 'overrides' values — that false-fails on the valid nested 5.0.13 — and fail the check when a key matches no installed path instead of passing vacuously, since that is the inert-override case. Wire it into the supply-chain job after npm ci. (owner: ci-maintainer, type: quick-task)
- Add .github/CODEOWNERS for dependency files -- No .github/CODEOWNERS exists in this repo, and the only thing that caught the unscoped 'minimatch' override key silently forcing brace-expansion 1.x into the minimatch@11 chain (corrected to 'minimatch@3' in this PR's review) was ad-hoc reviewer attention. Map package.json, package-lock.json, and docs/npm-overrides.md to the maintainer team so reviews are requested automatically on dependency PRs from the _auto-fix-ci.yml / approve-auto-fix.yml chain. Caveat: CODEOWNERS only requests reviews; it becomes an approval gate only when branch protection (scope: whichever branches are targeted) sets 'Require review from Code Owners', which is not configured in this repository's settings, so pair it with the pr-finalizer policy gate (pr1137.3). (owner: repo-maintainer, type: quick-task)
