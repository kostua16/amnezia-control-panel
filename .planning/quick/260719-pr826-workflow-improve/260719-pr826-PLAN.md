# Quick Plan: PR #826 workflow improvement intake

## Source
- PR #826: fix: resolve #813 - APR-E02: File-overlap conflict matrix artifact (audit-auto-prs)
- URL: https://github.com/kostua16/amnezia-control-panel/pull/826

## Summary
PR #826 adds a file-overlap conflict matrix to audit-auto-prs workflow. New CLI mode '--overlap-matrix' lists contested files across open automation PRs and writes a GITHUB_STEP_SUMMARY table. 130 lines of production code, 89 lines of tests. Clean addition, but overlaps conceptually with existing '--detect-overlap' in 'run()'.

## Quick Wins
- DRY up gh pr list + file-fetch between run() and buildOverlapMatrix() -- 'buildOverlapMatrix()' duplicates the 'pr list' + label-filter + file-fetch pattern already in 'run()' (lines 321–390). Both call 'gh pr list --json number,title,url,headRefName,labels' and 'createPullRequestFileGetter()'. Extract a shared 'fetchAutomationCandidates({repo, label, titlePrefix, excludeHead, ghCommand})' helper so both CLI modes reuse the same candidate-fetching + caching logic. Eliminates divergent filter behavior if the label schema changes. (owner: workflow-scripts, type: quick-task)
- Add a negative test for buildOverlapMatrix when gh returns garbage/malformed JSON -- Existing tests mock clean JSON arrays. 'parseJson()' (line 17) silently returns undefined on malformed input — the '|| []' fallback saves it, but there's no test proving the function degrades gracefully when 'ghCommand' returns ''not json'' or ''{broken''. One test asserting 'result.prs === []' on malformed 'ghCommand' output would harden the contract. (owner: workflow-scripts, type: quick-task)
- Gate the overlap-matrix step behind a workflow-level flag or input -- The new step is unconditionally added with 'if: always() && steps.claude_run.outputs.claude_failed != 'true''. Every audit-auto-prs run now pays the gh API cost of listing + fetching files for up to 100 PRs. For repos with few automation PRs this is cheap, but it adds latency. A 'workflow_dispatch' input like 'skip_overlap_matrix' (default false) or a repository variable would let maintainers skip it when not needed. (owner: workflow-governance, type: quick-task)

## pr826.x Phase Candidates
- pr826.2: Pin Node version used by workflow scripts and add a matrix smoke test -- The overlap-matrix step runs on 'self-hosted' without a node-version setup visible in the step. If the self-hosted runner upgrades Node, 'parseJson' behavior or ES feature availability could silently break. Add an explicit 'uses: actions/setup-node' in the matrix step (or inherit from setup-environment), and add a CI smoke test that runs 'node find-duplicate-automation-pr.cjs --overlap-matrix --repo ${{ github.repository }}' against the real repo on schedule to catch drift. (owner: ci-team)
- pr826.3: Auto-label or comment on PRs that touch contested files -- The overlap matrix is currently display-only (GITHUB_STEP_SUMMARY). The next evolution is actionable: when contested files are detected, post a comment on each affected PR listing the conflicting PR numbers, or apply a 'file-conflict' label so the repo-flow's merge gate can block/demerge PRs touching contested paths. This turns passive awareness into an enforcement signal. (owner: workflow-governance)
- pr826.1: Unify duplicate-detection and overlap-matrix into a single CLI entry point with subcommands -- The script now has three CLI modes ('run' default, '--overlap-matrix', and the existing '--detect-overlap' flag within 'run') all driven by top-level flags on the same file. As modes multiply, 'if (require.main === module)' becomes harder to reason about. Refactor to 'node find-duplicate-automation-pr.cjs detect-duplicates|overlap-matrix' subcommands with a shared option parser, making each mode's flags self-documenting and preventing accidental flag collisions. (owner: workflow-scripts)
