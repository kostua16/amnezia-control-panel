# Quick Plan: PR #1243 workflow improvement intake

## Source
- PR #1243: fix: resolve #1229 - rebase-pr: post-job cleanup fails with 'Index was out of range' after rebase rewrites .github/actions (actions/runner#2816)
- URL: https://github.com/kostua16/amnezia-control-panel/pull/1243

## Summary
PR #1243 fixes the actions/runner#2816 post-step crash window in rebase-pr.yml by restoring original-head .github/actions manifests twice (after-push + always() final step), adds RB10 to the e2e scenario table, and a characterization test in workflow-triggers.test.ts. Follow-ups: the two restore blocks are ~40-line near-duplicates worth extracting to a scripts/ helper; the new 'rebase succeeded - manifest cleanup failed' error title has no consumer in any run classifier (zero grep matches for 'manifest cleanup' in .github/workflows/scripts/), so monitoring will treat cleanup-only red runs as real failures; and the post-push window (Capture new head SHA, Wake the PR orchestrator) has no per-step timeout, leaving the admitted timeout/shutdown crash window unbounded.

## Quick Wins
- Extract duplicated manifest-restore block into a shared bash helper -- The 'Restore original head action manifests after push' and always() 'Restore original head action manifests' steps in .github/workflows/rebase-pr.yml duplicate the identical original-head validation + 'git restore --source="$original_head" --staged --worktree -- .github/actions' block (~40 lines each), differing only in the trailing ::error note. Extract to .github/workflows/scripts/restore-head-actions.sh (bash helper convention exists: analyze-claude-runs.sh, edit-issue-labels.sh) with the error note as an argument. Must update src/lib/__tests__/workflow-triggers.test.ts regexes that pin inline 'run: |' git commands in the job YAML (assert the script content + step invocation instead), and keep both gates green per the workflow-change protocol (npm run test-only + node --test scripts/__tests__/*.test.cjs). (owner: gh-workflow-engineer, type: quick-task)
- Teach run monitoring the 'rebase succeeded - manifest cleanup failed' outcome -- The PR introduces ::error title='rebase succeeded - manifest cleanup failed' in both restore steps, but grep shows zero matches for 'manifest cleanup' / 'Index was out of range' across .github/workflows/scripts/*.cjs and src/lib. Run monitoring will classify a red run whose push and summary already succeeded as a real workflow failure, risking requeue/escalation of an already-completed rebase. Add the error-title string as a known cleanup-only outcome in the run failure classification path (e.g. the same taxonomy layer as classify-* / escalate-repeated-fixes.cjs) so it is reported but not re-dispatched. (owner: kos-run-monitoring, type: quick-task)
- Bound the post-push window with per-step timeout-minutes -- The restore-after-push comment admits a timeout-minutes or runner-shutdown termination between push and the restore 'can hardly leave the rebased manifests on disk' — but 'Capture new head SHA' and 'Wake the PR orchestrator' in rebase-pr.yml carry no timeout-minutes (only two timeout entries exist in the file, at lines 71 and 114). A hung wake step burns the whole job budget and shrinks the chance the always() restore runs cleanly. Add tight explicit timeout-minutes to those two steps so the admitted window is bounded by seconds, and record the residual shutdown-only window in the RB10 row of docs/workflow-e2e-scenarios.md. (owner: gh-workflow-engineer, type: quick-task)

## pr1243.x Phase Candidates

Extend the characterization layer (src/lib/__tests__/workflow-triggers.test.ts, which already scans workflow YAML) with a repo-wide invariant scan: any job that invokes ./.github/actions/* before mutating its worktree must end with an original-head manifest-restore always() step. Turns PR #1243's one-off fix into a permanent CI gate in the ci-correctness family (perf/build/CI accuracy). (owner: gh-workflow-engineer)

Add the outcome to the rebase gate taxonomy and the finalizer/monitor decision path so cleanup-only reds are reported as success-with-cleanup-failure and never re-queued. (owner: kos-project-manager)
