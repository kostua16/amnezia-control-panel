## Summary
PR #846 adds a documentation-only '_comment' to 'policy.json' explaining that the 'claude-workflow-optimize-' prefix is shared by 5 workflows but 'allowedPathGlobs: [".planning/**"]' ensures only planning-touching PRs get auto-merge; others (monitor, docs-drift, workflow-health) correctly fall through to manual-only. Analysis identified 2 quick tasks and 2 phase suggestions.

## Quick Wins
- Add e2e test: claude-workflow-optimize- branch with .github/workflows/** files gets manual_only=true -- The PR comment documents that monitor-github-runs branches touch .github/workflows/** and fall through to manual-only. No test in evaluate-pr-policy.test.cjs covers this path — the existing test at line 76 only tests .planning/roadmap.md (happy path). Adding this test locks in the documented behavior. (owner: kos-pr-improve, type: quick-task)
- Strip _comment keys from policy.json before evaluation in evaluate-pr-policy.cjs -- policy.json now contains a _comment field inside trustedPlanning. evaluate-pr-policy.cjs reads trustedPlanningConfig directly — underscore-prefixed keys pass through silently. A defensive strip prevents accidental policy drift if future _comment or _note keys are added and mistaken for real config. (owner: kos-pr-improve, type: quick-task)

## pr846.x Phase Candidates
- pr846.1: Split claude-workflow-optimize- prefix into intent-specific prefixes to eliminate allowedPathGlobs fallthrough ambiguity -- 5 workflows share claude-workflow-optimize- but only audit-auto-prs and suggest-improvements match allowedPathGlobs (.planning/**). Monitor-github-runs, docs-drift, and workflow-health-optimize always fall through to manual-only. Splitting into claude-planning-optimize- (planning files only) and claude-workflow-optimize- (workflow/maintenance files, manual-only by default) would make the branch prefix itself signal trust intent without relying on the path-glob layer as a safety net. (owner: kos-pr-improve)
- pr846.2: Add policy.json schema validation step to CI to catch unknown keys and policy typos before merge -- policy.json has no schema enforcement — underscore-prefixed _comment keys, unknown nested keys, or typos in policy field names pass silently. A lightweight validation script in CI that validates known top-level keys and warns/strips underscore-prefixed metadata keys would catch misconfiguration early. (owner: kos-pr-improve)
