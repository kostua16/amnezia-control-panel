# Plan: read Kilo review inputs via one GraphQL query, REST as fallback

Issue: #1157. Goal: replace the 5 REST reads in `collectExternalReview` with one GraphQL query without changing any verdict.

## Facts (verified)

- `collectExternalReview(pr)` (`orchestrate-pr-flow.cjs`, ~line 1393) calls `fetchPrIssueComments`, `fetchPrReviewComments`, `fetchPrReviews`, `fetchCheckRuns`, `fetchCommitStatuses`, then `evaluateExternalReview` (`evaluate-external-review.cjs`). It runs only when the PR is not a draft, required checks passed and the PR is not dependabot.
- GraphQL quota is almost idle (~4700/5000) while core is the exhausted bucket.
- **Login hazard (verified on PR #1090):** REST gives `kilo-code-bot[bot]`; GraphQL gives `kilo-code-bot`. `lib/kilo.cjs` `KILO_LOGINS = ['kilo-code-bot[bot]']`. Do NOT widen `KILO_LOGINS` (a human account named `kilo-code-bot` would become a trusted review signal). Normalize in the adapter: when `author.__typename === 'Bot'`, produce `login + '[bot]'`; otherwise keep the login as is. `lib/kilo.cjs` stays untouched.
- `evaluateExternalReview` consumes REST-shaped objects: comments `{user:{login}, body, created_at, updated_at}`; review comments `{user, body, commit_id, created_at, updated_at}`; reviews `{user, commit_id, submitted_at, state}`; check runs `{name, conclusion, app:{slug,name}, workflow_name?}`; statuses `{context, state, created_at}`.

## Behavior

New module `lib/review-inputs-graphql.cjs` exports `fetchReviewInputsGraphql({ repo, prNumber, headSha, runGraphql })` returning `{comments, reviewComments, reviews, checkRuns, statuses}` in the REST shapes above, or throwing a typed error `ReviewInputsUnavailable`. It uses cursor pagination (`first:100` with `pageInfo`) for comments, reviews, review threads' comments and `statusCheckRollup.contexts`. Fallback conditions (throw so the caller uses REST for that wake): non-zero exit, `errors` array present, any required field missing, pagination cap exceeded (cap 10 pages per connection), head commit oid of the PR not equal to `headSha`.

### GraphQL contract (validated by independent review; follow exactly)

- `CheckRun` has no top-level `app`/`workflow_name`. Query `... on CheckRun { name conclusion checkSuite { app { slug name } workflowRun { workflow { name } } } }` and map to `{ name, conclusion: lowercase(conclusion) or null, app: checkSuite?.app ?? null, workflow_name: checkSuite?.workflowRun?.workflow?.name ?? null }`. `... on StatusContext { context state description targetUrl createdAt }` maps to `{ context, state: lowercase(state), description, target_url: targetUrl ?? null, created_at: createdAt }` (GraphQL enums are UPPERCASE, REST is lowercase; also normalize `EXPECTED`/`ERROR` consistently).
- "Required field missing" means only the structural envelope: `data.repository.pullRequest`, `headRefOid`, `commits.nodes[0].commit.oid`, and `nodes` + `pageInfo` of each connection. These are legitimately nullable and must NOT trigger fallback: `statusCheckRollup` (-> `checkRuns: [], statuses: []`), `CheckRun.conclusion` (in-flight), `checkSuite`/`workflowRun`, `author` (-> `user: null`), `review.submittedAt` and `review.commit`.
- Review comments: do NOT filter `isResolved`/`isOutdated` (REST lists all threads). Map `commit_id` from `PullRequestReviewComment.commit.oid` (NOT `originalCommit`). Reviews map only `{ user, commit_id: commit?.oid ?? null, submitted_at: submittedAt, state }`; never attach `updatedAt` (it would change `itemTime`).
- Bot login: append `[bot]` only when `author.__typename === 'Bot'` and the login does not already end with `[bot]`; set `user.type` from `__typename`. `lib/kilo.cjs` stays untouched. (GitHub forbids brackets in human usernames; only Apps are `Bot`.)
- Nested pagination: `reviewThreads(first:100)` with `comments(first:50)`; paginate top-level `comments`, `reviews`, `reviewThreads` and `contexts` by cursor; if any thread's `comments.pageInfo.hasNextPage` is true, throw `ReviewInputsUnavailable` (REST fallback). The parity script must print the measured `rateLimit { cost }` of the query (a dry run on PR #1090 reported cost 1; record the real number for a large PR).
- Statuses from this path must carry `state`, `description`, `target_url`, `created_at` so they stay interchangeable with `fetchCommitStatuses`.
- Export `collectExternalReview` with injectable loaders for tests. Wire the rollback switch in `.github/workflows/pr-flow.yml` orchestrate step `env:` as `PR_FLOW_REVIEW_SOURCE: ${{ vars.PR_FLOW_REVIEW_SOURCE || '' }}` (empty means the shipped default), so rollback is a repository variable, not a commit.
- Parity script: pass ONE frozen `now` to both `evaluateExternalReview` calls and set `pr.headCommittedAt` via the same `fetchHeadCommittedAt` the orchestrator uses, otherwise PRs near the 30-minute boundary flake.

`collectExternalReview` selects the source with `PR_FLOW_REVIEW_SOURCE` (`graphql` | `rest`). Default `graphql` ONLY IF the parity run (task 3) is 100% identical; otherwise ship with default `rest` and say so in the PR. Any GraphQL failure always falls back to the current REST code path.

## Tasks

1. **Adapter + selector.** Implement `lib/review-inputs-graphql.cjs` and wire it into `collectExternalReview` with the REST fallback. Keep every existing REST fetch function in place (they are the fallback and the parity reference).
2. **Unit tests** (`__tests__/review-inputs-graphql.test.cjs`, injected `runGraphql`, no network): bot gets `[bot]`; non-Bot author named `kilo-code-bot` stays `kilo-code-bot` and `isKiloUser` is false for it; `kilo-code-bot[bot]` summary yields the same `evaluateExternalReview` verdict as the equivalent REST fixture (passed, blocked, pending); pagination across 2 pages; truncation beyond cap throws; GraphQL `errors` throws; head oid mismatch throws; missing field throws; fallback path in `collectExternalReview` calls REST when the adapter throws.
3. **Parity script** `compare-review-input-sources.cjs --pr <n> [--pr <n> ...] | --open | --merged <count>`: for each PR run the REST loaders and the GraphQL adapter, diff the normalized inputs (sorted by id/time, ignoring fields `evaluateExternalReview` never reads) and diff the `evaluateExternalReview` result; print a table and exit 1 on any verdict difference. Run it locally with `gh` against ALL open PRs and the last 30 merged PRs; paste the table and counts into the PR description. Read-only: it must never write to GitHub.
4. **Docs.** Update `docs/workflow-e2e-scenarios.md` (Kilo review input source, fallback, the bot-login rule) and keep the mapping table consistent.
