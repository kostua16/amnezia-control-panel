## Quick Wins
- Align remaining /commits/{sha}/status readers on per_page=100 -- orchestrate-pr-flow.cjs:1365 was fixed to 'commits/{sha}/status?per_page=100', but two sibling readers still use the default 30-item page: fetch-auto-cover-context.cjs:199 ('repos/${repo}/commits/${headSha}/status') and watch-pr-flow.cjs:325 ('repos/${repository}/commits/${pr.headRefOid}/status'). Once a head accumulates >30 statuses, pr-flow/* contexts can fall off page 1: the watchdog (watch-pr-flow.cjs) then misses ready/kilo pending/failure ages it uses for expiry, and fetch-auto-cover-context reads stale state. Same one-line ?per_page=100 change in both files, plus unit tests asserting the query param, plus a V-row update in docs/workflow-e2e-scenarios.md per the workflow-change protocol. (owner: ci-automation, type: quick-task)
- Fail open (post all) when the status page saturates -- fetchCommitStatuses (orchestrate-pr-flow.cjs:1361-1367) now reads per_page=100 but cannot see beyond page 1; shouldPublishStatus would then treat a context absent from the truncated page as 'no previous status' and POST it (safe) — but it can also index only 100-entry-old state. Add a cheap guard in publishFlowStatuses (orchestrate-pr-flow.cjs:1443-1460): if readStatuses returns exactly 100 entries, log 'status page saturated; posting all' and skip the dedupe index, mirroring the existing read-throws fail-open path. Pin with one test (readStatuses returns 100 entries → all posted, matching the existing 'posts everything when the read throws' test pattern at orchestrate-pr-flow.test.cjs). (owner: ci-automation, type: quick-task)
