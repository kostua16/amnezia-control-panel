# Quick Plan: PR #715 workflow improvement intake

## Source
- PR #715: fix(workflows): prevent PR flow wedging at flow/checks-pending
- URL: https://github.com/kostua16/amnezia-control-panel/pull/715

## Summary
PR #715 fixes PR-flow stuck-at-flow/checks-pending by adding a noise concurrency group for github-actions[bot] comments, stale-ready-pending watchdog recovery, and stricter cancel-in-progress semantics. Three quick tasks: auto-cover-review.yml has the same bot-displacement vulnerability (cancel-in-progress: true + issue_comment trigger), claude.yml wastes runner slots on bot-triggered no-ops, and the classify-trigger bot guard needs a dedicated regression test. Three phase suggestions: centralize noise isolation as reusable policy, emit structured metrics on watchdog recovery, and audit approval-path workflows for implicit bot-comment trust.

## Quick Wins
- Add noise-group isolation to auto-cover-review.yml -- Same concurrency-at-creation-before-job-if bug class as PR #695, different workflow. auto-cover-review.yml:37-44 has cancel-in-progress: true on its per-PR group and reacts to issue_comment — a bot sticky-comment upsert can cancel or displace a targeted fix-review wake. (owner: workflow-team, type: quick-task)
- Add github-actions[bot] filter to claude.yml authorize gate -- Self-hosted runner slots are scarce. claude.yml:31 passes any issue_comment containing '@claude' regardless of author; a bot upsert containing that string wastes a runner slot on a no-op run. (owner: workflow-team, type: quick-task)
- Add classify-trigger bot guard regression test -- The classify-trigger if: is the first defense line. Existing tests cover the step-level script gate (evaluate-trigger-policy.test.cjs:209,273) but not the workflow-level concurrency routing that happens before any step runs. A dedicated test makes the PR #695 regression guard independently verifiable. (owner: workflow-team, type: quick-task)

## pr715.x Phase Candidates
- pr715.1: Centralize bot-comment noise isolation as reusable workflow policy -- Prevents the next PR #695 in any workflow with issue_comment triggers + per-PR concurrency groups. PR #715 introduces the noise group ad-hoc in pr-flow.yml; at least two other workflows (auto-cover-review.yml, claude.yml) share the same surface. (owner: workflow-team)
- pr715.2: Emit structured metric when stale-ready-pending watchdog fires -- Watchdog recovery is silent today — a metric turns it from a band-aid into a detection signal. When stale-ready-pending fires, a reactive wake was lost (runner saturation or event-delivery gap); structured output lets monitor workflows detect systemic patterns before multiple PRs pile up. (owner: workflow-team)
- pr715.3: Audit approval-path workflows for implicit bot-comment trust -- Defense-in-depth: the noise group prevents displacement but not semantic misuse. approve-auto-fix.yml and fix-pr.yml process issue_comment for /approve and /fix commands — implicit bot-comment trust on approval/merge decisions should be audited and explicitly guarded. (owner: workflow-team)
