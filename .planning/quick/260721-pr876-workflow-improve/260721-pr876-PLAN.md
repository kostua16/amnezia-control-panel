# Quick Plan: PR #876 workflow improvement intake

## Source
- PR #876: fix: resolve #875 - SEC-I04: Preserve history when refreshing the tracking issue (security-audit-weekly)
- URL: https://github.com/kostua16/amnezia-control-panel/pull/876

## Summary
PR #876 swaps 'gh issue edit' → 'gh issue comment' in security-audit-weekly.yml to preserve per-run history when refreshing tracking issues. The infra path also drops '--add-label ci-failure' from the comment-only refresh, meaning the label is only applied on initial creation. Clean fix for SEC-I04. Two follow-ups surfaced: the infra issue loses its 'ci-failure' label on refresh (design gap), and the 'EXISTING_ISSUE' lookup via 'gh issue list --search' is duplicated across both issue-opening steps — extractable into a shared helper.

## Quick Wins
- Restore ci-failure label on infra issue refresh path -- PR #876 correctly switches to 'gh issue comment' but drops '--add-label ci-failure' from the infra refresh branch (line 176→178 in base). On initial creation the label is set, but on subsequent refresh comments the label is never re-applied. If a prior run removed it (or a human did), the infra issue loses its 'ci-failure' classification silently. Fix: add a separate 'gh issue edit $EXISTING_ISSUE --add-label ci-failure' call after the comment succeeds, matching the original intent. (owner: workflow-maintainer, type: quick-task)
- Extract existing-issue lookup into a reusable shell function -- Both issue-opening steps ('issue-vulns' at line 97-106 and 'Report audit infrastructure failure' at line 159-167) contain an identical 'gh issue list --search --json number --jq' pattern with the same error-swallowing fallback. Extracting a 'find_existing_issue()' function at the top of each step (or a shared script in '.github/workflows/scripts/') eliminates the duplication and ensures consistent error handling across future issue-opening steps. (owner: workflow-maintainer, type: quick-task)

## pr876.x Phase Candidates
- pr876.1: Add comment-count guard to prevent unbounded growth on long-lived tracking issues -- The PR changes edit→comment, which means every weekly run appends a new comment. Over months/years, the npm audit tracking issue accumulates dozens of comments with no cleanup. Add a guard: if the issue has >N comments (e.g. 52 = one year of weekly runs), close-and-recreate with a link to the archived issue. Prevents the tracking issue from becoming an unmanageable scroll that hides recent findings. (owner: workflow-maintainer)
- pr876.2: Add e2e test coverage for security-audit-weekly issue refresh/comment path -- The existing e2e suite in '.github/workflows/scripts/__tests__/' should cover the refresh-vs-create branching in security-audit-weekly.yml. Currently the PR changes untested shell branches (comment vs edit fallback). A targeted e2e scenario verifying that 'EXISTING_ISSUE' being set produces a comment (not an edit) and that the fallback still creates a new issue on comment failure would prevent regressions on this SEC-I04 class. (owner: workflow-maintainer)
