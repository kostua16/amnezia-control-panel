## pr1086.x Phase Candidates
- pr1086.2: Harden APR-E10 streak semantics: legacy-schema output must not reset an active streak -- extractRecommendations() treats a missing/non-array systemic_fix_recommendations identically to a genuinely empty one, and runAudit() persists that as a clean gap which resets every active streak (countConsecutive walks back and stops at the gap). A run shaped like the pre-PR schema (stale workflow revision, or any output path bypassing the json-schema gate) sandwiched between two runs emitting the same real recommendation silently breaks a legitimate ≥2 escalation. Mark such entries (e.g. legacy_schema flag or skip appending the gap) so countConsecutive skips rather than resets, add unit tests and an APR-E10i row in docs/workflow-e2e-scenarios.md. Run both e2e suites per the workflow change protocol. (owner: maintainer (kostua16) via audit-auto-prs systemic-fix PR)
