## pr1238.x Phase Candidates
- pr1238.2: Prisma schema-to-migrations drift gate in CI -- The bug class PR #1238 fixes is unguarded: prisma/schema.prisma:113 declared 'redirectIp String?' with no migration, and no workflow caught it — the resulting P2022 'column does not exist' failure on GET /api/servers was observed against a freshly migrate deploy-built database during the 261125-0l9 intake session; no production incident is on record, so the plan does not claim one. Add a CI step that exports an explicit throwaway 'DATABASE_URL=file:${RUNNER_TEMP}/drift-check.db' for the whole step — prisma.config.ts:12 resolves the datasource from process.env.DATABASE_URL, so without the override an inherited variable or secret would point 'migrate deploy' at a non-scratch database, and RUNNER_TEMP sits outside the checkout so the scratch DB never lands in the tree (a relative 'file:./drift-check.db' would leave an untracked checkout file on every run; .gitignore covers only /prisma/dev.db* and /dev.db*) — then runs 'prisma migrate deploy' followed by 'prisma migrate diff --from-config-datasource --to-schema prisma/schema.prisma' (no --exit-code: the flag is disregarded for drift semantics only — drift is judged by the diff's stdout, not by its exit code). The step must set pipefail or capture the diff's exit status explicitly, so any non-zero exit from the diff command itself (bad DATABASE_URL, missing migrations directory, CLI error) still fails the step — without that, a failed diff prints nothing to stdout and a filter-only pipeline reports the filter's status, going green on a check that never ran. Pass definition: the step captures the diff's stdout, filters out exactly two known residual drift lines — '[*] Redefined table admins' and '[*] Redefined table user_quotas' caused by migration 20260617 (the migration adds updatedAt via non-destructive 'ADD COLUMN ... NOT NULL DEFAULT CURRENT_TIMESTAMP' at migration.sql lines 8 and 72, which the schema renders as @updatedAt) — and passes only if the remaining output is empty; any other diff line fails the gate. The allowlist is provisional until the gate's first baseline run on main: the 261125-0l9 intake measurement (its artifact exists only in unmerged PR #1238, commit 052eb79 — not on this branch or main) recorded that the same diff with --exit-code returned exit 2 and that 'the only drift lines were [*] Redefined table admins and [*] Redefined table user_quotas, which are pre-existing and caused by migration 20260617'. The allowlist shrinks only via a reviewed PR: the candidate residual fix (local commit ff8b1445) is not on origin, so it cannot be a prerequisite — it becomes an explicit, reviewable dependency once delivered as a reviewed PR that removes both residuals, at which point the two filter entries are dropped. Per the workflow change protocol, add the scenario to docs/workflow-e2e-scenarios.md and run the e2e suite. (owner: gh-workflow-engineer)
