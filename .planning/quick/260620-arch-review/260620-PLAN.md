## Proposal 16: Deduplicate protobuf parsing and decompose geoip-manager.ts

**Severity:** Medium (Correctness + Maintainability)
**Area:** `src/lib/geoip-manager.ts`, `src/lib/routing-rule-templates.ts`

### Problem

Two lib files implement independent protobuf varint decoders and CIDR matching utilities:

| Function | `geoip-manager.ts` | `routing-rule-templates.ts` |
|----------|---------------------|-----------------------------|
| `readVarint()` | Lines ~120-140 | Lines ~550-570 |
| `varintSize()` | Lines ~142-155 | Lines ~572-585 |
| `cidrToNetworkAndMask()` | Lines ~160-175 | — |
| `matchesCIDR()` | Lines ~177-195 | — |
| `extractCountryCodesFromDat()` | Lines ~197-260 | Lines ~285-340 (different impl) |
| `decodeCountryMessage()` | Lines ~262-307 | Lines ~342-380 (different impl) |

The varint primitives are near-identical copy-paste. The higher-level decode functions have **diverged**: `geoip-manager.ts` decodes into a `Map<string, string>` for country lookups, while `routing-rule-templates.ts` decodes into a `Set<string>` of ISO codes for template import. Different outputs for the same protobuf format.

**Risk:** A bug fix in one copy (e.g., handling edge-case varint encoding) is not applied to the other. The divergent decode functions already produce different abstractions from the same binary format, making it unclear which is canonical.

**Compounding factor:** `geoip-manager.ts` is 653 lines (3.3× the 200-line guideline). The protobuf parsing section (~200 lines) is a natural extraction target that also enables the file decomposition the project rules require.

### Solution

**Part A: Extract shared protobuf utilities**

Create `src/lib/protobuf-varint.ts` (~60 lines):

```ts
// Shared varint decoder — used by both geoip-manager and routing-rule-templates
export function readVarint(buf: Uint8Array, offset: number): { value: number; bytesRead: number }
export function varintSize(value: number): number
```

Both files import from the shared module instead of maintaining private copies.

**Part B: Decompose geoip-manager.ts (653 lines → 4 files)**

| New file | Lines | Responsibility |
|----------|-------|----------------|
| `src/lib/geoip-downloader.ts` | ~120 | `streamWebResponseBodyToFile()`, download URLs, content-type validation |
| `src/lib/geoip-protobuf.ts` | ~200 | `parseGeoIPBuffer()`, `decodeGeoIPProtobufIntoMap()`, imports from `protobuf-varint.ts` |
| `src/lib/geoip-lookup.ts` | ~80 | `buildLookupIndex()`, `lookupCountryInIndex()` (pure functions, compounds with proposal 1 binary search) |
| `src/lib/geoip-manager.ts` | ~250 | `GeoIPManager` class (lifecycle, init, refresh, status), singleton export |

Original file becomes a thin barrel re-export for backward compatibility.

**Part C (optional, low priority): Align routing-rule-templates decode**

The divergent decode functions serve different purposes (Map vs Set). Rather than force-unifying them, document the divergence with a comment in `protobuf-varint.ts` pointing to both consumers. If proposal 1 (binary search) refactors the lookup layer, this alignment becomes natural.

### Scope

- Create `src/lib/protobuf-varint.ts` (~60 lines)
- Create `src/lib/geoip-downloader.ts`, `src/lib/geoip-protobuf.ts`, `src/lib/geoip-lookup.ts`
- Refactor `src/lib/geoip-manager.ts` to import from new modules (stays as orchestrator ~250 lines)
- Refactor `src/lib/routing-rule-templates.ts` to import `readVarint`/`varintSize` from shared module (~10 line change)
- All new files under 200 lines
- No behavioral change to GeoIP lookup or routing template import

### Acceptance Criteria

- [ ] Zero duplicated `readVarint` / `varintSize` implementations
- [ ] `geoip-manager.ts` is under 200 lines (orchestrator only)
- [ ] `geoip-downloader.ts`, `geoip-protobuf.ts`, `geoip-lookup.ts` each under 200 lines
- [ ] `routing-rule-templates.ts` imports from `protobuf-varint.ts`
- [ ] GeoIP lookup returns same results before and after (backward-compatible)
- [ ] Routing template import returns same ISO code set before and after
- [ ] Existing tests pass; add test for shared varint decoder edge cases

### Compounds With

- **Proposal 1** (GeoIP binary search): `geoip-lookup.ts` is the natural place to add the sorted-table + binary-search index. Doing this decomposition first makes proposal 1 implementation cleaner.
- **Proposal 5** (vpn-services decomposition): Same pattern (god file → focused modules). Sets precedent.
