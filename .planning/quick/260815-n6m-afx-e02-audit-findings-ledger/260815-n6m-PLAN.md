# Quick Plan: AFX-E02 — Persistent audit-findings ledger across audit-fix runs

## Goal

Audit-fix runs currently audit from scratch every time: manual findings become salted-fingerprint issues (weak cross-run dedup, AFX-E06 scope), fixed findings live only in the PR body, and nothing persists between runs. This change persists a findings ledger at `.planning/audit-backlog.json` that every audit-fix run appends to (workflow step, after parsing the agent's structured output) and consumes from (prompt instruction: read the backlog before fresh auditing). The ledger file must not force every audit PR into the manual-only lane, so `evaluateAuditSafePolicy` gains a surgical exact-path exemption (`auditSafe.ledgerPath`).

Reference: backlog TODO `AFX-E02` in `docs/TODOs-2.md`, issue #1072. Reference both in commits and the PR description (repo convention).

## Locked design decisions (from investigation — do not revisit)

- Ledger path: `.planning/audit-backlog.json`, committed to the repo (`.planning/` is NOT gitignored; only `.planning/debug/resolved/` is).
- New script `.github/workflows/scripts/audit-findings-ledger.cjs` (lib + CLI), reusing `fingerprintFinding` from `upsert-audit-manual-findings.cjs` WITHOUT the salt (unsalted fingerprint = sha256 of normalized summary + sorted files, 16 hex chars → stable across runs).
- Entry shape: `{fingerprint, status, severity, summary, details, files, first_seen, last_seen, last_seen_run, fixed_in_run}` with `status: open|fixed|manual`.
- Commands: `--append` (merge this run's `fixed_findings` + `manual_findings` from `CLAUDE_STRUCTURED_OUTPUT`, dedupe by fingerprint, bump `last_seen`) and `--list-open` (print non-fixed entries for humans/logs).
- audit-fix.yml: prompt instruction to read the ledger first; new step AFTER "Detect manual audit findings" and BEFORE the gate/commit-and-push, so the ledger update rides the same PR commit.
- Policy: add `auditSafe.ledgerPath: ".planning/audit-backlog.json"`; exempt exactly that path (string equality, no globs) from BOTH the manual-only and disallowed checks in `evaluateAuditSafePolicy`. The ledger still counts toward `maxFiles`/`maxChangedLines` (conservative; accepted).
- Do NOT change the salted fingerprint behavior in `upsert-audit-manual-findings.cjs` (issue dedup is AFX-E06 scope). Only additive exports are allowed there.

## Status machine (authoritative — implement exactly)

| source in this run's output | existing entry state | result status | fixed_in_run |
|---|---|---|---|
| `fixed_findings` | (new) | `fixed` | set to run id |
| `fixed_findings` | any existing | `fixed` | set to run id |
| `manual_findings` | (new) | `manual` | omitted |
| `manual_findings` | existing `fixed` | `open` (regressed — fix no longer holds) | cleared/omitted |
| `manual_findings` | existing `manual` or `open` | unchanged | unchanged |
| same fingerprint in BOTH lists (same run) | — | `fixed` wins; manual duplicate skipped (log a warning line) | set to run id |

- `--list-open` prints entries with `status !== 'fixed'` (i.e. both `open` and `manual`), severity-descending (critical > high > medium > low > unspecified), then `last_seen` descending.
- Ledger file format (deterministic serialization for stable git diffs): `{ "version": 1, "findings": [ ...entries sorted by fingerprint... ] }`, 2-space JSON + trailing newline. Entry field order: fingerprint, status, severity, summary, details, files, first_seen, last_seen, last_seen_run, fixed_in_run (omit `fixed_in_run` when not fixed).
- `first_seen`/`last_seen` = ISO-8601 UTC (`new Date().toISOString()`); `last_seen_run` = run id. Inject `now` and `runId` as parameters into the lib functions so tests are deterministic.
- Malformed input handling: missing ledger file → initialize empty ledger (`version: 1`, `findings: []`); unparseable/corrupt JSON → hard error, CLI exits non-zero (never silently wipe history — a failed step surfaces via report-failure); empty/unparseable structured output → zero findings → NO file write (no empty-diff churn).
- Fixed findings come ONLY from structured output (`fixed_findings`/`fixedFindings` keys); the agent's markdown response has no mandated fixed-findings section. Manual findings reuse `collectManualFindings` (structured first, `### Manual-only findings` text fallback via `CLAUDE_LAST_OUTPUT`).
