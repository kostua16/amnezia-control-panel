# Quick Plan: PR #721 workflow improvement intake

## Source
- PR #721: fix: resolve #703 - MON-I01: Catch timeout-cancelled runs in 'report-failure' (monitor-github-runs)
- URL: https://github.com/kostua16/amnezia-control-panel/pull/721

## Summary
PR #721 fixes the monitor-github-runs workflow's 'report-failure' blind spot: 'if: failure()' → 'always()' + result-check, and 'report-failure/action.yml' now catches 'timed_out'/'cancelled' conclusions via an 'actionableConclusions' Set. However, 9 other workflows sharing the same 'report-failure' action still use the old 'if: failure()' guard and have the same timeout-cancelled blind spot. One prior workflow (audit-fix) already uses the correct pattern, proving the migration is safe and known.

## Quick Wins

Nine other workflows still use 'if: failure()' on their report-failure job: suggest-improvements.yml:187, gsd-planning-execute.yml:585, pr-improve.yml:276, fix-issue.yml:327, workflow-health-optimize.yml:443, project-manager.yml:139, maintenance.yml:93, docs-drift.yml:149, audit-auto-prs.yml:265, issue-catch-up.yml:581. Same timeout-cancelled blind spot exists in all of them. 'audit-fix.yml:324' already uses the correct 'always()' + result-check pattern, proving the migration pattern. (owner: kos-workflow-engineer, type: quick-task)
