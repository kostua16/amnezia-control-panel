## Summary
PR #1268 tightens formatUnavailableLine slug order (rest-counter.cjs:219-227: strip-leading → slice(40) → strip-trailing) and hardens the shape-test Node-step detector plus a nodeSteps>0 guard (action-metadata-shape.test.cjs). Base checkout still holds pre-PR code. Highest-value gap found: the tightened 'required' preload map covers only 2 workflows while 19 workflow files reference REST_COUNTER_PRELOAD (85 occurrences), so the new guard fires for a fraction of the surface. Follow-ups: widen the map, deduplicate slug logic against REASON_CODE, pin the detector regex edges directly; phase work: derive preload coverage dynamically and lift the detector into pr-policy governance.

## Quick Wins
- Extend preload 'required' map beyond the 2 covered workflows -- action-metadata-shape.test.cjs:194-197 hardcodes 'required' to auto-pr-branch-cleanup.yml and workflow-health-optimize.yml only; PR #1268's new 'nodeSteps > 0' assertion ('must have a preload-wired Node step') therefore only fires for those 3 jobs. Grep shows 19 workflow files reference REST_COUNTER_PRELOAD (85 occurrences — fix-review.yml 15, code-review.yml 10, auto-pr-branch-cleanup.yml 7, issue-catch-up.yml 6, workflow-health-optimize.yml 8, ...). A new bare 'node' step added without REST_COUNTER_PRELOAD in any of the other 17 files passes CI silently. Add their Node-bearing jobs to the 'required' map so the tightened command-position regex enforces everywhere. (owner: gh-workflow-engineer, type: workflow-improvement)
- Extract a shared reason-slug helper aligned with REASON_CODE -- rest-counter.cjs:26 defines REASON_CODE = /^[a-z][a-z0-9-]{0,39}$/ (used by reportGhInstallFailure at :189-193 and readGhSetupFailure at :202-209), while formatUnavailableLine at :219-227 builds its code with a separate inline pipeline that PR #1268 reordered (strip leading non-alpha → slice(0,40) → strip trailing dashes). Two independent definitions of 'valid reason token' is exactly the drift class this PR fixed. Extract slugifyReason() consumed by all three call sites, plus a test asserting every emitted reason=/gh_reason= token matches REASON_CODE (gh_reason emitters at :276-285 are currently safe literal/readGhSetupFailure outputs — keep them pinned). (owner: gh-workflow-engineer, type: workflow-improvement)
- Unit-pin the tightened node-step detection regex edges -- The PR replaces the detector with /(?:^|[;&|(]|\b(?:then|do|else))[ \t]*node[ \t]/m plus ^actions/github-script@ (action-metadata-shape.test.cjs:213-222, the @@ -212,7 +212,13 @@ hunk) but its behavior is only exercised indirectly through two workflow fixtures. Add direct cases covering: 'echo "node ..."' and '# node ...' comment exclusions (the false positives the PR removed), 'then node' / 'do node' / line-start indentation matches, and prefixed invocations ('sudo node', 'env node', 'timeout 30 node') which the new regex silently misses — a step running node via a prefix bypasses the preload assertion. Documenting the accepted false-negative set prevents a future 'why did this pass' investigation. (owner: gh-workflow-engineer, type: workflow-improvement)
