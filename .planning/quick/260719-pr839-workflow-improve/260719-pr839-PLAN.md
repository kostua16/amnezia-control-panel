## Summary
PR #839 adds 'allow_protected_edits' maintainer opt-in (label + '--allow' flag + dispatch input), 'restored_only' detection distinguishing "no fix" from "fix reverted by force-restore", 'renderProtectedPathsOnly' sticky comment renderer, 'git clean -fd' for untracked protected files, structural invariant tests, and e2e scenario docs (FR14-16). Three quick tactical follow-ups and three phase-scale suggestions surfaced.

## Quick Wins
- Add resolveFinishedBody test: restored_only + gatePassed=true race -- The new test only covers gatePassed='false'. If a race lets the gate run when restoredOnly is true, resolveFinishedBody (upsert-fix-review-comment.cjs:403) checks restoredOnly before hasChanges — correct priority — but no test proves it wins over the gate-failure renderer. Add test with restoredOnly:'true', hasChanges:'false', gatePassed:'true' asserting body contains 'Fix limited to protected paths', not 'validation-failed'. (owner: workflow-scripts, type: quick-task)
- Anchor restored-only invariant tests to step id: not substring slicing -- fix-review-restored-only-invariant.test.cjs uses content.indexOf('Detect no-op') to isolate YAML blocks. Step name renames silently break slice boundaries. Switch to matching step id: attributes (e.g. id: detect-noop) which are stable workflow identifiers per e2e-scenarios conventions. (owner: workflow-tests, type: quick-task)
- Add restored_only branch to §6d Mermaid flowchart in e2e docs -- FR14-16 table rows added to workflow-e2e-scenarios.md §6d but the Mermaid flowchart has no restored_only=true branch. The diagram still shows detect-noop → has_changes=false → 'no actionable findings' as one path. Maintainers scanning the diagram miss the protected-paths-only routing. (owner: docs, type: quick-task)

## pr839.x Phase Candidates
- pr839.1: Generalize protected-path opt-in into a shared module for all fix workflows -- The allow_protected_edits pattern (policy label, --allow flag parsing, conditional restore+clean, restored_only detection) is only in fix-review.yml. fix-pr.yml and fix-issue.yml also force-restore .github/actions/ but lack the opt-in. Extract into a shared script (e.g. resolve-protected-paths.cjs) that all fix workflows source: takes allowProtectedEdits + policy, returns {excludes, protectedPaths, alwaysProtected}. Prevents divergence across 3 workflows. (owner: workflow-scripts)
- pr839.2: Add integration-level detect-noop pipeline test with mock git state -- The invariant test validates YAML structure via regex — it proves code is written, not that bash git operations behave correctly. Add a test harness (like checkout-before-node-script.test.cjs) that creates a temp git repo with staged changes under .github/actions/, runs the detect-noop bash logic via Node wrapper, and asserts correct has_changes/restored_only outputs for each combination. Catches bash arithmetic or git pathspec bugs invisible to string-matching tests. (owner: workflow-tests)
- pr839.3: Auto-remove allow-protected-edits label after successful fix-review push -- The label persists on the PR 'until removed'. After a successful push with opt-in, the label remains — a subsequent /fix-review still allows protected-path edits even if maintainer only wanted one-shot access. Add post-push cleanup step removing the label when allow_protected_edits=true AND pushed=true, matching existing gh label patterns in pr-flow. (owner: workflow-scripts)
