# Quick Plan: PR #839 workflow improvement intake

## Source
- PR #839: fix(workflows): report restore-protected fix-review edits instead of claiming no-op
- URL: https://github.com/kostua16/amnezia-control-panel/pull/839

## Summary
PR #839 adds restored_only detection to fix-review.yml's detect-noop step, preventing force-restored .github/actions/ edits from being misreported as clean no-ops or triggering false-positive-confirmed code-review relabels. Well-scoped fix with good e2e invariant tests. Two tactical follow-ups and two phase-scale suggestions identified.

## Quick Wins
- Add resolveFinishedBody test: restored_only=true + failed=true -- resolveFinishedBody checks failed before restoredOnly, so renderFailed fires. Correct but untested — if someone reorders the branches, this edge case silently flips. Add a test asserting renderFailed wins over renderProtectedPathsOnly when failed=true. (owner: claude, type: quick-task)
- Add .github/actions/ no-edit guidance to kos-fix-review agent contract -- The agent contract (.claude/agents/kos-fix-review.md) likely lacks an explicit 'do not edit .github/actions/' instruction. Adding it prevents agents from wasting turns on edits that will be force-reverted, reducing restore-only false positives at the source. (owner: claude, type: quick-task)

## pr839.x Phase Candidates
- pr839.2: Extract restore-protected-path logic into a reusable composite action -- fix-review.yml inlines the restore step (git checkout sha -- .github/actions/) and the detect-noop protected_dirty probe. If fix-issue.yml or future workflows need the same force-restore pattern, they'd copy-paste. A parameterized composite action (.github/actions/restore-protected-paths/) accepting a path list + base SHA would centralize the invariant and ensure detect-noop exclusion stays in sync with the actual restore step. (owner: claude)
- pr839.1: Auto-generate a copyable git patch in the protected-paths-only comment -- renderProtectedPathsOnly tells the user to 'apply the fix manually' but doesn't provide a ready-to-use patch. The agent's structured output includes changed_files[] and findings_addressed[]. The workflow could capture the agent's diff (git diff .github/actions/ before restore) and attach it as a collapsible code block in the sticky comment, letting the user copy-paste the fix instead of reconstructing it from the summary text. (owner: claude)
