# Dedupe Repeated Large PR Comments In PR Size Guard

During the 2026-06-12 auto-PR audit, open PR `#323` showed the same GitHub Actions `Large PR` warning twice with no new evidence between comments. The duplication comes from `.github/workflows/pr-size-guard.yml`, which previously called `gh pr comment` on every `opened` and `synchronize` event without checking for an existing workflow-owned warning.

## Root Cause

- The PR size guard had no sticky marker or update path, so repeated workflow runs always appended a fresh comment.
- The workflow also only added the `large-pr` label; it never reconciled comment/label state when a PR later shrank below the threshold.

## Completed

- Added `.github/workflows/scripts/upsert-pr-size-comment.cjs` to upsert a single `<!-- pr-size-guard -->` comment for oversized PRs and delete it when the PR drops back under the threshold.
- Kept the `large-pr` label synchronized with the same threshold decision so label state no longer drifts from the current diff size.
- Rewired `.github/workflows/pr-size-guard.yml` to call the shared helper and added a focused regression test for the helper’s sticky-comment detection and threshold behavior.
