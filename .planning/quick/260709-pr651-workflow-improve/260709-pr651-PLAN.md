# Quick Plan: PR #651 workflow improvement intake

## Source
- PR #651: feat(workflows): add autonomy round 2 recovery flows
- URL: https://github.com/kostua16/amnezia-control-panel/pull/651

## Summary
PR #651 adds 6 recovery/autonomy flows: fleet back-pressure gates (5 workflows), dead-letter retry (Phase 7), deferred proposal promotion lifecycle (promote + restore), CI cancelled rerun (PM37), disk-pressure self-heal, and flow/review-failed blocked escalation (PM38). High-value follow-ups center on DRY-ing the fleet-gate duplication, closing e2e coverage gaps for the new flows, and making the hardcoded back-pressure threshold configurable.

## Quick Wins
- Extract fleet-gate to composite action -- 5 workflows (audit-fix, docs-drift, monitor, gsd-planning-execute, workflow-health-optimize) now contain identical ~30-line fleet-gate blocks (checkout + setup-environment + check-pending-automation-pr.cjs). Extract to .github/actions/fleet-back-pressure/action.yml to eliminate the copy-paste and ensure future threshold/prefix changes propagate in one place. (owner: gh-workflow-engineer, type: quick-task)
- Add e2e scenario entries for new PR #651 flows -- docs/workflow-e2e-scenarios.md gained P9b, P11d, P11e, P14, PM37, PM38, G6-G8 but the .github/workflows/scripts/__tests__ suite has no e2e-level coverage for: fleet back-pressure gating (back-pressure trips -> run skipped), deferred proposal promotion PR lifecycle, restore-deferred-proposal on unmerged PR close, disk-pressure self-heal dispatch, and CI cancelled rerun action. Add scenario-level tests to close the gap per the workflow-change-protocol. (owner: gh-workflow-engineer, type: quick-task)
- Widen disk-pressure detection to non-failure conclusions -- monitor-amnezia-control-panel-github-runs.yml self-heal step only scans runs with --status failure and uses --log-failed. Disk exhaustion (ENOSPC) often manifests as runner eviction (cancelled/timed_out) or kills steps before they report failure. Changing to --status completed --json and checking all conclusions, plus using --log instead of --log-failed, catches ENOSPC regardless of how the run terminated. (owner: gh-workflow-engineer, type: quick-task)

## pr651.x Phase Candidates
- pr651.1: Centralize fleet back-pressure policy in policy.json -- The --max-open-automation-prs 8 threshold is hardcoded in 5 fleet-gate blocks plus 2 title-prefix callers (audit-auto-prs, suggest-improvements). The AUTOMATION_BRANCH_PREFIXES in check-pending-automation-pr.cjs (claude-, claude/, codex/) is separate from project-manager.cjs's list (which includes dependabot/). Move threshold + per-workflow overrides + branch prefix registry into policy.json so operators tune fleet behavior without touching workflow YAML. (owner: gh-workflow-engineer)
- pr651.2: Add CI rerun telemetry and guard against double-dispatch -- project-manager.cjs ciCancelledRerunAction checks state.ciRerunAt but does not verify whether a CI workflow_run is already in_progress for the head before dispatching rerun. Adding an active-run guard (like existing activeRun helper) prevents double-dispatch. Also, track rerun outcomes (rerun succeeded vs still failed) to distinguish genuinely transient infra from persistent issues that need /fix escalation. (owner: gh-workflow-engineer)
- pr651.4: Deferred proposal lifecycle metrics and promotion pipeline observability -- promote-deferred-proposal.cjs selects the oldest eligible issue and creates a PR, but there is no observability into the pipeline: time-to-promote, promotion success rate (merged vs closed unmerged), stranded in-progress recovery frequency. Add structured logging + a summary step to gsd-planning-execute.yml's promote-deferred job that reports queue depth, promotion history, and restore-trigger frequency to the run summary. (owner: gh-workflow-engineer)
- pr651.3: Auto-dispatch targeted re-review for flow/review-failed PRs -- PM38 added flow/review-failed to the blocked-escalation clock (72h wait + attention digest), but the only recovery is human intervention. For PRs where the review failure was transient (agent turn limit, runner pressure), auto-dispatch a single targeted re-review after a shorter cooldown (e.g. 4h) before escalating to the 72h human path. This mirrors the PM37 CI rerun pattern — one automatic retry before human escalation. (owner: gh-workflow-engineer)
