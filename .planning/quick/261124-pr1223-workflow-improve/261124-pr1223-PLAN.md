## Quick Wins
- Gate reconcileEscalationLabels after the migration is provably complete -- escalate-repeated-fixes.cjs:reconcileEscalationLabels() issues 'gh issue list --search 'APR-E10 escalate in:title' --limit 500' on EVERY audit run forever, even after it returns 0 relabeled — the code comment accepts this as 'a no-op scan'. The repo is actively cutting per-run REST calls (de15daa9 'ci(code-review): cut REST calls per run', ecf3ddef per-job REST counter). Persist a completion marker (e.g. a line in the recommendation-log issue body next to entries, or a '--migration-done' output consumed by the next run) and skip the scan once a run relabeled 0 with no legacy label found. Unit-testable with the existing injectable runGh harness in escalate-repeated-fixes.test.cjs. (owner: claude-bot (fix-issue or audit-fix workflow), type: workflow-improvement)
- Derive the stale-exempt contract test from one exported constant instead of per-token text.includes() -- The exempt-label set now lives in 5+ hand-synced sites: stale.yml exempt-issue-labels ('keep-open,backlog,in-progress,umbrella-sub-issue'), maintenance.yml prompt prose, kos-maintenance.md, kos-daily-maintenance-sweep/SKILL.md, and maintenance-escalation-contract.test.cjs which only asserts 'text.includes('\'<label>\'')' per token per file — a file can list the label in the wrong bucket (exempt vs eligible) and still pass. tracking-issue.cjs already exports TRACKING_LABELS/SUB_ISSUE_LABEL as the code source of truth. Export STALE_EXEMPT_ISSUE_LABELS from tracking-issue.cjs, parse stale.yml's exempt-issue-labels in the contract test, and assert exact list equality against the export so drift fails loudly instead of token-presence. (owner: claude-bot (gsd-quick), type: quick-task)
- Handle stale-closed pre-split escalations that keep umbrella-sub-issue forever -- reconcileEscalationLabels() lists '--state open' only. Before this PR, umbrella-sub-issue was NOT in stale.yml's exempt list, so a pre-split escalation could already be stale-closed while carrying the legacy label. If a human later reopens it, it re-enters every lifecycle exempt (stale close + maintenance 90d review) with no exit condition — the exact defect this PR fixes for open issues. Either widen the migration scan to non-open states for the one-time pass, or assert-and-document the edge in the APR-E10e scenario row of docs/workflow-e2e-scenarios.md. (owner: claude-bot (fix-issue workflow), type: workflow-improvement)
