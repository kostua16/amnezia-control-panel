## Quick Wins
- Key quota windows by core_reset only in summarize-rate-limit.cjs and report a token count per window -- summarize() keys each window on reset plus token_id, but the default GITHUB_TOKEN is job-scoped (a different string, so a different token_id, per job) while its REST limit is per repository. Running the PR's script on two jobs with the same reset and limit produced two rows (980 to 900, 890 to 820) instead of one row showing a drop of 160; a new line plus a pre-token_id line for the same window also split into one real-id row and one 'unknown' row. Change: group by core_reset, add a 'tokens' count (distinct token_id, 'unknown' counted once), keep token_id only for the start/end mismatch check, and add tests for both cases. Confirm the premise with two concurrent pr-finalizer.yml or fix-pr.yml jobs: same core_reset, same limit, different token_id. (owner: ci-workflow-scripts, type: workflow-improvement)
- Log and summarize the GraphQL bucket alongside core -- formatRateLimitLine emits graphql=<remaining>/<limit> (.github/actions/log-rate-limit/rate-limit.cjs:37) but no graphql_reset, and the new summarize() never reads 'graphql', so GraphQL exhaustion is invisible in the summary even though collect-review-feedback.cjs:70 ('gh api graphql') and the orchestrator GraphQL read (#1168) spend that separate bucket. Add 'graphql_reset' from resources.graphql.reset to the line, update the exact-line assertion in log-rate-limit.test.cjs, and print one GraphQL line per window in format(). (owner: ci-workflow-scripts, type: workflow-improvement)
- Add the quota summarizer to the GitHub-runs monitor agent checklist -- .claude/agents/kos-monitor-amnezia-control-panel-github-runs.md:57 lists 'rtk proxy gh run view --log-failed/--log' and scan-claude-logs.cjs but nothing quota-related, and setup-environment/action.yml:77-78 already names 'API rate limit exceeded' as a known failure. Add one step: when a failed run shows a rate-limit signature, pipe 'gh run view <id> --log' for the last N runs into .github/workflows/scripts/summarize-rate-limit.cjs and attach the output to the report. State the cost in the step: each 'gh run view --log' is one REST call, so cap N (about 20). (owner: kos-monitor-amnezia-control-panel-github-runs, type: workflow-improvement)
