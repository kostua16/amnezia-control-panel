The new node detector explicitly cannot see cuts that leave quotes balanced. Two wiring constraints pin the shape of that list: only the 'changes' job checks out with fetch-depth: 0 (ci.yml:28) and it publishes just 'run-heavy' (ci.yml:22-23), while the lint job checks out depth 1 (ci.yml:61-63) and has no base commit to diff against, so the viable source is a new changed-files output published by the 'changes' job (an inline 'git diff' in the lint job would need its own base fetch first); and the list must be filtered to workflow/action/sh paths before it reaches the helper's argv mode, which exits 1 on any entry that is not an existing workflow, action-metadata, or shell file (verify-changed-workflow-files.cjs:210-221, note at :176-178) — otherwise any non-workflow PR (say, one touching src/**) would turn the new ci.yml step red on every run; the CHANGED_FILES env diff mode tolerates unrelated or deleted paths (:176-178), so env mode with a filtered list (or filtering before argv) is the safe wiring. Any ci.yml actionlint step must keep that changed-files scoping (or reuse the helper): a repo-wide pass cannot be green today because untouched fix-review.yml still trips SC2129 (run 29803905118 / #881, recorded in the helper header and docs/workflow-e2e-scenarios.md:242) — exactly why the monitor lints only changed files. With that scoping, the offending PR would have failed at review time via shellcheck ("unexpected EOF while looking for matching quote"), and actionlint also catches the broader bash-syntax and expression-error classes in 'run:' blocks — for .github/workflows/** only; composite-action 'run:' blocks are schema-validated but never actionlint-scanned, so the detector test stays the only structural coverage there.
