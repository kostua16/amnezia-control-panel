# Quick Plan: PR #1014 workflow improvement intake

## Source
- PR #1014: fix: resolve #998 - WHO-E03: Queue-latency telemetry and starvation alerts (workflow-health-optimize)
- URL: https://github.com/kostua16/amnezia-control-panel/pull/1014

## Summary
PR #1014 adds WHO-E03 queue-latency telemetry and starvation alerting to the hourly workflow-health-optimize pipeline. Three concrete follow-ups identified: (1) the new report-queue-starvation job is not covered by the existing report-failure always-gate, so its failures are silent; (2) the starvation script hardcodes label names instead of reading from policy.json; (3) no scale boundary test for the telemetry computation.

## Quick Wins
- Wire report-queue-starvation into the report-failure always-gate -- The existing report-failure job (workflow-health-optimize.yml:520-522) gates on collect-runs, detect-flaky, and optimize but omits report-queue-starvation. If the starvation job fails (GH API error, timeout, missing GH_PAT), the failure is silently swallowed. (owner: workflow-health-optimize, type: quick-task)
- Parametrize starvation alert labels via policy.json manualLabels -- file-queue-starvation-alert.cjs:399 hardcodes --label 'auto-fix,needs-review'. The repo's policy.json:56 defines these as manualLabels. If labels change, the script won't follow. Other workflows (audit-auto-prs, audit-fix) already read policy.json. (owner: workflow-health-optimize, type: quick-task)
- Add scale boundary test for computeQueueLatencyTelemetry -- Existing tests cover 1-20 samples but not pathological burst scale (1000+ runs). After an outage, collect-runs could return hundreds of runs. A test with 1000+ synthetic samples validates sort performance and no integer overflow in percentile index math. (owner: workflow-health-optimize, type: quick-task)

## pr1014.x Phase Candidates
- pr1014.1: Alert cooldown policy to prevent starvation-issue storms -- When queue starvation is sustained (runner pool exhaustion lasting hours), the workflow fires every hour and comments on the same issue repeatedly. If the issue is closed, it re-opens indefinitely. No cooldown window exists. Add a configurable cooldown (e.g. 24h) stored as a label timestamp, mirroring the pattern used by report-blocked-gate (workflow-health-optimize.yml:486-518). (owner: workflow-health-optimize)
- pr1014.2: E2E scenario for starvation-alert flow in workflow-e2e-scenarios.md -- The new path (collect-runs → starvation_alert=true → report-queue-starvation → issue created/commented) has no e2e scenario in the characterization suite. Per ADR 0001, all workflow paths need scenario coverage. Add a scenario mocking high queueSec values and verifying the filing script invocation. (owner: workflow-health-optimize)
