# Quick Plan: PR #750 workflow improvement intake

## Source
- PR #750: fix(workflows): persist maintenance pruning changes
- URL: https://github.com/kostua16/amnezia-control-panel/pull/750

## Summary
PR #750 wires the maintenance workflow to persist agent pruning changes through branch → detect → validate → push → PR. The pipeline is sound (reuses existing actions correctly). Two tactical gaps found: a redundant fetch in detect_changes and a missing policy.json branch prefix that forces PM to classify maintenance PRs via generic claude- fallback. One governance-level gap: the trigger policy lacks an explicit maintenance PR entry despite the workflow now being a full PR producer.

## Quick Wins
- Remove redundant git fetch in maintenance detect_changes step -- maintenance.yml detect_changes runs 'git fetch origin main --depth=1 || true' but checkout already uses 'fetch-depth: 0'. The extra fetch is dead work; the '|| true' silently swallows network errors that should surface. (owner: claude, type: quick-task)
- Add claude-maintenance- branch prefix to policy.json -- PR_PRODUCER_REGISTRY (project-manager.cjs:207) now tracks 'maintenance.yml' with dedupe, but 'policy.json' has no 'branchPrefix' entry for 'claude-maintenance-'. Project-manager classifies these PRs via the generic 'claude-' fallback instead of purpose-specific logic. Add the prefix to 'branchPrefixAllowlist' and optionally a 'branchPrefixClassifications' entry so PM58 maps it to the workflow-automation rubric. (owner: claude, type: quick-task)

## pr750.x Phase Candidates
- pr750.1: Formalize maintenance PR lifecycle in evaluate-trigger-policy -- The maintenance workflow is now a full PR producer (branch → gate → push → upsert), but evaluate-trigger-policy.cjs has no explicit path for 'claude-maintenance-' branches. It falls through to generic claude- matching. Adding a dedicated trigger-policy entry would enable maintainer-triggered re-runs, explicit cooldown enforcement at the policy layer (not just PM registry), and proper branch-prefix classification for manual-only vs auto-merge decisions. (owner: claude)
- pr750.2: Add e2e scenario coverage for maintenance PR creation path -- P16 and P17 were added to workflow-e2e-scenarios.md documenting the new maintenance PR path and gate-failure path, but no corresponding automated test exists in .github/workflows/scripts/__tests__/. The fix-ci and fix-issue PR paths have e2e tests; maintenance should have parity to catch regressions like the original pruning-not-persisted bug. (owner: claude)
