# Quick Task 260610-k7m: Apply PR labels once after creation

**Date:** 2026-06-10
**Status:** Executing

## Goal

Stop duplicate pull-request label events from the shared automation PR upsert helper while keeping label application on both create and update paths.

## Implementation Tasks

1. Confirm from exact GitHub run and issue-event data that automation PR creation is emitting duplicate label events and redundant `PR Orchestrator` wakeups.
2. Update `.github/actions/upsert-pull-request/action.yml` so create and edit label flows use the correct CLI flags and labels are applied once after PR creation.
3. Add a focused invariant test for the shared helper.
4. Run targeted verification: tests, lint, Prettier, and `git diff --check`.

## Acceptance Criteria

- Creating an automation PR does not rely on `gh pr create --label`.
- Updating an existing PR uses the correct `gh pr edit --add-label` behavior.
- The helper still tolerates label-application failures without failing PR creation.
