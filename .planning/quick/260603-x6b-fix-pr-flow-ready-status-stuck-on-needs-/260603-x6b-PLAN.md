# Fix PR Flow Ready Status Stuck On Needs Review

## Evidence

PR #209 reached `pr-flow/ready=failure` because `needs-review` was included in
`blocking_labels_present`. The orchestrator then left worker diagnostics pending
without dispatching workers.

## Plan

- Treat `needs-review` as a manual-review marker, not a hard required-status
  failure.
- Mark manual-only/manual-review PRs as terminal `flow/manual-only` after CI is
  green, with diagnostic worker contexts set to N/A.
- Keep hard blockers such as `do-not-merge`, AI/security concerns, and blocked
  dependency labels as failures.
- Add regression tests for PR #209-style manual audit PR behavior.
- Re-run workflow script checks, unit tests, lint, Prettier, TypeScript, and
  actionlint.
