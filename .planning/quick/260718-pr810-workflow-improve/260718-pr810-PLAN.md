# Quick Plan: PR #810 workflow improvement intake

## Source
- PR #810: test(workflows): pin ensured workflow labels to policy.json definitions
- URL: https://github.com/kostua16/amnezia-control-panel/pull/810

## Summary
PR #810 adds a forward-reference scan test: every label ensured by workflows/actions must exist in policy.json. The test is narrow (regex only catches inline comma-separated lists), has a brittle canary assertion, and only validates one direction. Three tactical follow-ups and two roadmap suggestions identified.

## Quick Wins
- Extend test regex to handle YAML array label syntax -- The regex in ensure-workflow-labels.test.cjs:40 only matches inline comma-separated lists ('names: foo,bar'). GitHub Actions YAML commonly uses array syntax ('names:\n - foo\n - bar'). Any workflow adopting array syntax silently bypasses the forward-reference guard. Extend the parser in the test to handle both formats. (owner: claude, type: quick-task)
- Replace triage-failed canary with a count-based guard -- Line 48 asserts 'referenced.has('triage-failed')' as a scan canary. If triage-failed is legitimately removed from issue-catch-up.yml, the test fails with a misleading message. Replace with a count-based guard (e.g., 'assert.ok(referenced.size >= 10)') that validates the scan found labels without tying it to one specific name. (owner: claude, type: quick-task)
- Exclude composite-action input declarations from label scan -- report-failure/action.yml:32 declares 'ensure-labels:' as an input parameter (not a label list). The regex could false-match if the input default is label-like. The scan should skip lines inside 'inputs:' blocks of action.yml files, since those are parameter definitions not runtime label usage. (owner: claude, type: quick-task)

## pr810.x Phase Candidates
- pr810.2: Path-trigger the label-consistency test on policy.json or workflow changes -- The label-consistency test lives in the e2e suite under .github/workflows/scripts/__tests__/. A PR adding a new ensure-labels call or removing a policy.json label only catches the mismatch if the full e2e suite runs. Add a paths-filter CI job that runs ensure-workflow-labels.test.cjs when .github/workflows/**/*.yml, .github/actions/**/*.yml, or policy.json changes. Catches workflow↔policy mismatches at PR time. (owner: claude)
- pr810.1: Reverse-scan policy.json for orphaned label definitions -- The test validates forward references (workflow→policy) but not reverse. Labels defined in policy.json but never ensured or referenced by any workflow are dead entries that accumulate as workflows retire. Add a companion reverse-scan test that flags orphaned policy labels for cleanup or explicit exemption, keeping the registry lean. (owner: claude)
