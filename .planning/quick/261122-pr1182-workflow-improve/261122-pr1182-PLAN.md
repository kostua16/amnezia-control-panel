## Summary
PR #1182 moves the close jobs in auto-pr-branch-cleanup.yml to pull_request_target (closed, base main) with pinned refs/heads/main checkouts, adds the per-workflow cleanupPolicyErrors policy, bootstraps a checksum-pinned js-yaml parser for workflow-governance-check.cjs, and fixes the duplicated docker-publish rate-limit label. The diff is consistent with the base files: delete-generated-branch and the orphan sweep use the REST API or GH_TOKEN, never persisted git credentials. No approval-policy or planning-automation gap was found in this diff. Follow-ups: three narrow fixes (portable mktemp template plus an executed installer test, parsed-YAML trigger detection, orphan-sweep checkout hardening) and two roadmap items (declarative privileged-trigger policy with gate-file merge protection, one tested pinned-bootstrap helper). All touch .github/**, which policy.json manualOnlyPathGlobs keeps on the manual-merge path.

## Quick Wins
- Make install-governance-yaml.sh mktemp portable and add an executed installer test -- The new .github/workflows/scripts/install-governance-yaml.sh creates the parser path with mktemp "$RUNNER_TEMP/governance-yaml-XXXXXX.cjs"; the X run is not last and no --suffix is passed. Verified on this runner: busybox mktemp rejects that template ("Invalid argument", exit 1) while uutils 0.10.0 accepts it. GNU coreutils on ubuntu-latest could not be verified from here. Put the X run last (mktemp "$RUNNER_TEMP/governance-yaml-XXXXXX"; require() in workflow-governance-check.cjs still loads an extensionless file outside the repo as CommonJS) or pass --suffix=.cjs. The two new tests in workflow-yaml-parse.test.cjs only regex the script text, so a runtime fault in the script, the tarball member path package/dist/js-yaml.cjs.js, or the checksum step surfaces only when supply-chain.yml and workflow-governance.yml run. Add one test that executes the script with RUNNER_TEMP and GITHUB_ENV pointed at temp files, then runs GOVERNANCE_YAML_PARSER=<path> node .github/workflows/scripts/workflow-governance-check.cjs. (owner: claude, type: quick-task)
- Detect pull_request_target structurally in workflow-governance-check.cjs -- main() still gates the allow-list with the text regex /pull_request_target:/ (base line 96). A workflow using on: [pull_request_target], a block list entry (- pull_request_target), or a quoted key passes undetected, and it then gets a write-capable base-branch run with no policy applied. This PR already imports a YAML parser at module scope and adds cleanupPolicyErrors, so main() can yaml.load each workflow and test the on key as a string, array, or object, failing closed on parse errors. Add the three undetected forms as cases next to the existing require('../workflow-governance-check.cjs') test. This closes the allow-list bypass for the same trigger class this PR hardens (scenario G8a). (owner: claude, type: quick-task)
- Disable credential persistence on the orphan-sweep checkout and assert it in cleanupPolicyErrors -- auto-pr-branch-cleanup.yml line 196 (cleanup-orphan-branches) is the only checkout in the workflow left without persist-credentials: false. The job runs under workflow-level contents: write and only uses GH_TOKEN (line 206) and the log-rate-limit token input, so the persisted git credential is unused. The new cleanupPolicyErrors checks the sweep's if condition and job permissions but not its checkout. Add with: persist-credentials: false, one policy assertion for the sweep checkout, and a test mutation that proves the assertion fires. (owner: claude, type: quick-task)

## pr1182.x Phase Candidates
- pr1182.1: Declarative privileged-trigger policy for all pull_request_target workflows, with gate-file merge protection -- cleanupPolicyErrors is hand-written for auto-pr-branch-cleanup.yml only. pr-flow.yml and pr-policy.yml are allow-listed through allowedPullRequestTarget but have no structural policy on permissions, checkout ref, credential persistence, or job set, and the rest of the checker (jobBlocks, hasTopLevelPermissions, trigger detection) is line-regex based. Phase work: move per-workflow privileged policy into a declarative table (for example a privilegedWorkflows key in policy.json) that workflow-governance-check.cjs applies to all three workflows, migrate the regex checks to the parsed YAML this PR now provides, and add the governance gate files (workflow-governance-check.cjs, install-governance-yaml.sh, workflow-governance.yml, supply-chain.yml) to projectManager.protectedMergeAuthorityPaths (policy.json line 113, read at project-manager.cjs line 58). Those files decide what other PRs may merge and are absent from that list today. Adding protected paths is a merge-policy decision, so it needs a maintainer call. (owner: maintainer)
- pr1182.2: Unify pinned bootstrap downloads into one tested helper with drift-proof pins -- The repo now has three hand-written pinned download bootstraps: install-governance-yaml.sh (sha512, bounded curl), the RTK installer in .github/actions/setup-environment/action.yml (pin comment at lines 50-54, install at 232-264), and actionlint (pin comment at 67-72, install at 279-303). Each has its own curl flags, temp-file handling, and bump-both convention, and none has an executed test. The js-yaml pin is the first coupled to package-lock.json by a test: workflow-yaml-parse.test.cjs compares the script's literal URL and digest with the lockfile entry (root range "js-yaml": "^5.2.1" at lockfile line 41). Every js-yaml bump therefore fails the suite until the script is hand-edited, and the assert.ok message does not say which file to edit. Phase work: one shared helper (url, digest, bounded curl, portable mktemp), executed tests for each bootstrap, and either derive the js-yaml pin from the lockfile at run time or emit an actionable bump-both message. Deriving the pin replaces the hard-coded pin this PR chose on purpose, so that part needs a maintainer decision. (owner: maintainer)
