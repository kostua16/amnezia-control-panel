## Quick Wins
- Make install-governance-yaml.sh mktemp portable and add an executed installer test -- Gate: only once #1182 is merged (see Precondition); edit the merged .github/workflows/scripts/install-governance-yaml.sh. The script creates the parser path with `mktemp "$RUNNER_TEMP/governance-yaml-XXXXXX.cjs"`; the X run is not last and no --suffix is passed. Verified on this runner (Ubuntu image, BusyBox v1.37.0 and uutils coreutils 0.10.0): busybox mktemp rejects that template ('Invalid argument', exit 1) and also rejects --suffix ('unrecognized option', exit 1), while uutils accepts both; GNU coreutils on ubuntu-latest could not be verified from here. Required fix, one form only: put the X run last on a directory and give the parser an explicit .cjs name -- `parser_dir="$(mktemp -d "$RUNNER_TEMP/governance-yaml-XXXXXX")"; parser="$parser_dir/js-yaml.cjs"` (verified on this runner: busybox and uutils both accept it). Cleanup: the merged trap is `trap 'rm -f -- "$archive"' EXIT`, which cannot remove a directory, so the new directory needs its own removal. The parser must outlive the installer -- GITHUB_ENV values are visible only to later steps, and both jobs run workflow-governance-check.cjs in the step after the installer -- so the trap must not remove it on the success path. Require: initialize `parser_dir=''` before the trap (the script runs under set -u), extend the trap to `trap 'rm -f -- "$archive"; rm -rf -- "$parser_dir"' EXIT` so every failure exit removes the directory, and restore the archive-only trap (`trap 'rm -f -- "$archive"' EXIT`) as the last statement after the GITHUB_ENV write so the parser stays for the next step; a success flag tested inside the trap is equivalent. Do not add a job-level cleanup step: GitHub documents RUNNER_TEMP as emptied at the beginning and end of each job, so the directory cannot accumulate across runs on any runner. The surface that does accumulate is the executed test, which must create its RUNNER_TEMP root with fs.mkdtempSync and remove it in an after hook that also runs when the test fails. Do not use the extensionless `mktemp "$RUNNER_TEMP/governance-yaml-XXXXXX"` form: require() routes a no-extension file through the .js loader, so its module type comes from Node's format detection rather than from the file name (verified on Node 24.22.3: it loaded as CommonJS even under a 'type': 'module' scope, but that is detection, not a guarantee). Do not use `--suffix=.cjs` either: it fails on busybox. The two new tests in workflow-yaml-parse.test.cjs only regex the script text, so a runtime fault in the script, the tarball member path package/dist/js-yaml.cjs.js, or the checksum step surfaces only when supply-chain.yml and workflow-governance.yml run. Make the archive source overridable so an executed test never downloads, and make the override test-only and fail closed: the installer takes a local archive path and its expected digest from env (GOVERNANCE_YAML_ARCHIVE_PATH and GOVERNANCE_YAML_ARCHIVE_SHA512) only behind an explicit fixture opt-in -- GOVERNANCE_YAML_ALLOW_FIXTURE=1 must be set alongside the path for the fixture branch to activate and skip curl. The opt-in is not a trust boundary: whatever can set it can also set the path and a matching digest, so it only stops partial or accidental overrides; the control that keeps the SHA-512 trust anchor the installer exists to enforce meaningful is the rule that supply-chain.yml and workflow-governance.yml never set any of the three variables. Specify the whole gate matrix. Every refused combination exits non-zero with a refusal message of its own, printed before any download, so no partial override silently changes which archive or which anchor is trusted: (i) none of the three set: download from the literal registry URL and verify the literal digest; (ii) the opt-in and the path set, no digest override: fixture branch verified against the literal digest (case c); (iii) the opt-in, the path, and the digest override all set: fixture branch verified against the override digest (case b); (iv) every other combination is refused -- the path without the opt-in, the digest override without the opt-in, the opt-in without a path (it would otherwise fall through to the registry and break the no-network rule for tests), the digest override with the opt-in but without a path (it would re-anchor the real download), and the opt-in set to anything but the exact value 1. The fixture branch must print a visible line on every run (a ::notice:: naming the fixture archive and saying the pinned download was skipped) so an override is never silent. The registry URL and the expected digest stay the script's literal defaults because the lockfile-drift test greps for that literal digest. Only the unit test may set these variables: supply-chain.yml and workflow-governance.yml must never set any of the three, and the real download plus checksum verification stays in those jobs, which already call the installer. Add to workflow-yaml-parse.test.cjs: (a) a text assertion for the required `mktemp -d` call and the .cjs parser name, and for the cleanup (`parser_dir=''` initialized before the trap and `rm -rf -- "$parser_dir"` inside it), so a revert to either rejected form or to the archive-only trap fails the suite; (b) one test that assembles a fixture tarball at test time from the lockfile-installed node_modules/js-yaml/dist/js-yaml.cjs.js laid out as package/dist/js-yaml.cjs.js, computes its sha512 digest in the same base64 form the script uses, executes the script with RUNNER_TEMP and GITHUB_ENV pointed at temp files and GOVERNANCE_YAML_ALLOW_FIXTURE=1 plus both override variables set, asserts the fixture notice line and that the parser file still exists after the installer exits, then runs GOVERNANCE_YAML_PARSER=<path> node .github/workflows/scripts/workflow-governance-check.cjs; (c) a negative case that passes the fixture path (with the fixture opt-in) but not the digest override, so the script compares the fixture against the pinned default digest and fails the integrity comparison. Assert that failure specifically, not as a bare non-zero exit: with 'set -euo pipefail' an unset GOVERNANCE_YAML_ARCHIVE_SHA512, a missing package/dist/js-yaml.cjs.js member in the tar extraction, or the post-extraction bundle check all exit non-zero too, so a status-only assertion can pass without ever reaching the integrity comparison. Capture the script output and require the exact mismatch line the merged script prints ('::error::Governance YAML parser integrity check failed') plus evidence the download branch was skipped (the fixture notice line was printed, so the fixture archive was the source and nothing reached registry.npmjs.org); (d) the fail-closed gate, one case per refused combination in (iv), starting with GOVERNANCE_YAML_ARCHIVE_SHA512 set but GOVERNANCE_YAML_ALLOW_FIXTURE unset: each must exit non-zero with its own refusal message printed before the script reaches curl, and write no parser path to GITHUB_ENV, so an override can never silently re-anchor trust; (e) the cleanup contract: a run that fails after the directory exists (a fixture tarball without the package/dist/js-yaml.cjs.js member, so tar exits non-zero) must leave no governance-yaml-* directory under the test's RUNNER_TEMP, which proves the trap removes the parser directory on failure; the refused and digest-mismatch runs must leave none either; (f) a text assertion that no file under .github/workflows/ names any of the three variables, which turns the never-set rule into a checked one. No test may reach registry.npmjs.org. (owner: claude, type: quick-task)
