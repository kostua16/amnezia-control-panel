## Summary
PR #1076 is sound: it moves debug-doc pruning into a deterministic script and stops the maintenance agent from inheriting the repo's wide Bash grants. Three narrow follow-ups remain. The trimmed allowlist still carries 'Bash(rtk:*)', which 'rtk proxy' turns into a bypass of every exact-match grant. The new prune script keys on 'status: resolved', a value no debug doc in '.planning/debug/' has, so it prunes nothing. The settings-isolation generator lives in an unlinted heredoc that the test scrapes out of the YAML. At phase scale: extend settings isolation to the other read-only Claude workflows with a policy test, finish converting the sweep's agent-judgment checks into scripts with exact issue titles, and path-scope trust for the maintenance PR now that only a script can change the tree.

## Quick Wins
- Drop bare 'Bash(rtk:*)' from the maintenance allowlist: 'rtk proxy' bypasses every exact-match grant -- The trimmed list at '.github/workflows/maintenance.yml:111' keeps 'Bash(rtk:*)' next to exact grants such as 'Bash(npm audit --json)' and 'Bash(git log --since="12 hours ago" --grep="TODO\|FIXME" --oneline)'. 'rtk proxy' is an alias of 'rtk bypass' ("Execute command without filtering", confirmed with 'rtk proxy --help'), so 'rtk proxy git push', 'rtk proxy npm install <pkg>', or 'rtk proxy node <script>' satisfies the wildcard and the exact-match grants are decorative. 'run-zai' also appends 'Agent' unconditionally ('.github/actions/run-zai/action.yml:220'), although the 'kos-maintenance' agent contract lists only Glob, Grep, Read, Bash, TaskGet, TaskList, TaskUpdate. Change: remove 'Bash(rtk:*)' (the PR already enumerates 'Bash(rtk gh issue create:*)' and the other rtk-prefixed commands, and reading goes through Read/Glob/Grep), add an opt-out input for the 'Agent' append in 'run-zai' and set it off in maintenance. Extend the allowlist assertion in 'prune-stale-debug-docs.test.cjs' so the sorted list equals the enumerated set with no 'rtk:*' wildcard. Run both e2e suites per the workflow change protocol. (owner: workflow-health-optimize, type: workflow-improvement)
- Make debug-doc retention match GSD's real status vocabulary: 'status: resolved' prunes nothing -- 'prune-stale-debug-docs.cjs' deletes only docs whose frontmatter says 'status: resolved'. No doc in '.planning/debug/' carries that value. Of the 12 docs, 5 carry another status ('fixed' at '.planning/debug/users-create-404.md:3', 'fixing', 'diagnosed', 'investigating' at '.planning/debug/pr-522-rebase-disallowed-tools.md:2') and 7 have no top-level 'status:' line at all. GSD's debug template only writes 'status: investigating' ('.claude/get-shit-done/workflows/debug.md:184'); 'status: resolved' belongs to UAT gap frontmatter ('.claude/get-shit-done/workflows/execute-phase.md:1181'), not debug sessions. Every 'updated' date is May or June 2026, so the new deterministic step is a no-op on real data and the P16 row in 'docs/workflow-e2e-scenarios.md' describes a path that never fires. Change: treat 'fixed' and 'resolved' as terminal, add both to the test matrix, and decide what happens to docs with no parseable 'updated' (today they are immortal): fall back to 'created:' or leave them and say so in P16. (owner: workflow-health-optimize, type: workflow-improvement)
- Move the isolated-settings heredoc into a linted script module -- The 'Prepare isolated Claude guard hooks' step in '.github/actions/run-claude-params/action.yml' embeds a 'node - <<'NODE'' program, and the new test in 'prune-stale-debug-docs.test.cjs' digs it out of the YAML with the regex '/<<'NODE'\n([\s\S]+?)\nNODE$/m' and pipes it to 'node -'. The inline JS is invisible to 'eslint .', even though the config covers '.github/workflows/scripts/**' ('eslint.config.mjs:42'). The test also asserts 'post[0].timeout === 5', a value owned by '.claude/settings.json:202', so an unrelated settings edit fails a workflow test. The same PR already established the better pattern for pruning: a 'require.main === module' script under '.github/workflows/scripts/'. Change: extract to '.github/workflows/scripts/build-isolated-claude-settings.cjs' taking the output path as argv[2], call it from the step, 'require' it directly in the test, and derive the expected timeout from the parsed settings file instead of the literal. (owner: workflow-health-optimize, type: workflow-improvement)
