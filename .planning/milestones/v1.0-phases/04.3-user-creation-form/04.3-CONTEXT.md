# Phase 4.3: User Creation Form - Context

**Gathered:** 2026-04-29
**Status:** Ready for planning

<domain>
## Phase Boundary

Build form to create new users with name, limits, and protocol selection. Modal dialog triggered from "Create User" button on users page. Fields: username, password, display name, collapsible advanced section (traffic quota GB, speed limit Kbps), AWG/3x-ui service checkboxes. Client-side validation. POST to /api/users, close modal + refresh list on success.

</domain>

<decisions>
## Implementation Decisions

### Form Layout & Fields
- Modal/dialog triggered from "Create User" button on users page
- Username + Password + Display Name as primary fields (minimum viable)
- Collapsible "Advanced" section with traffic quota (GB input) + speed limit (Kbps input)
- Checkboxes for AWG and 3x-ui services — simple dual-service toggle

### Form Behavior
- Client-side required field validation (username, password min length 3)
- POST to /api/users, loading state during submit, close modal + refresh list on success
- Inline error messages below fields + toast/alert for API errors
- Cancel closes modal, discards form state

### Claude's Discretion
Modal implementation approach (portal/dialog primitive vs custom), exact GB conversion display, animation/transition details.

</decisions>
