# Phase 1.3: Database Schema Setup - Research

**Researched:** 2026-04-28
**Status:** Complete

## Prisma 7.8.0 Key Findings

### Architecture Change (Prisma 7)
- **Rust-free/ESM Prisma Client** is now the default
- Up to 90% smaller bundle size, up to 3x faster queries
- `prisma-client` generator replaces deprecated `prisma-client-js`
- **Requires explicit `output` path** in generator block

### Configuration (Prisma 7)
- New `prisma.config.ts` file at project root for schema path, migration path, and datasource URL
- Datasource URL can use `env("DATABASE_URL")` or a literal string like `"file:./dev.db"`
- Schema file no longer needs `url` in datasource block for SQLite (it's in prisma.config.ts)

### SQLite Specifics
- SQLite provider: `provider = "sqlite"`
- URL format: `file:./dev.db` (relative to prisma.config.ts location)
- **Enums ARE supported** in Prisma 7.x for SQLite
- **Json type IS supported** in SQLite
- No native array type (use Json for arrays)

### Init Command
```bash
npx prisma init --datasource-provider sqlite --output ../generated/prisma
```
This creates:
- `prisma/schema.prisma` with SQLite provider
- `prisma.config.ts` with datasource URL
- `.env` with `DATABASE_URL="file:./dev.db"`

### Migration Commands
```bash
npx prisma migrate dev --name init    # First migration
npx prisma generate                   # Regenerate client
```

### Relations
- One-to-many: `Model { relationField RelatedModel[] }` + `RelatedModel { model Model @relation(fields: [id], references: [id]) }`
- onDelete options: `Cascade`, `SetNull`, `Restrict`, `NoAction`

### Generated Client Location
- Recommended: `../generated/prisma` (sibling to prisma/ dir)
- Import in code: `import { PrismaClient } from '@/generated/prisma'` (with path alias)
- Must add `generated/prisma` to `.gitignore`

## Schema Design Decisions

### ID Strategy
- Use `Int @id @default(autoincrement())` for SQLite -- simple, efficient, no external deps needed
- Autoincrement is suitable for 1-3 server, 50-user scale

### Enum Handling
- Prisma 7.x supports native enums for SQLite
- Use for: ServiceType (AWG, THREE_XUI), ServiceStatus (RUNNING, STOPPED, ERROR), AlertSeverity (INFO, WARNING, CRITICAL), QuotaPeriod (DAILY, WEEKLY, MONTHLY)

### JSON Fields
- Use `Json` type for flexible configuration data: Service.config, Configuration.content, UserProtocol.config
- Allows schema evolution without migrations for config changes

### Indexes
- Add `@@index` for foreign key fields used in queries (userId, serverId, serviceId)
- Add `@@unique` for natural keys where appropriate (username, email)

### Relation Patterns
- User -> TrafficLog: one-to-many (onDelete Cascade)
- User -> UserQuota: one-to-one
- User -> UserProtocol: one-to-many
- Server -> Service: one-to-many
- Server -> TrafficLog: one-to-many
- Service -> Configuration: one-to-many (optional serviceId)
- User -> RoutingRule: one-to-many (optional userId for global rules)
- RoutingRule: optional userId allows global rules

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| Prisma 7 config change breaks existing setup | Use `prisma init` to scaffold correctly |
| SQLite enum support regression | Test after first migration |
| Generated client import path issues | Configure @ alias in tsconfig |
| Migration conflicts with future phases | Use descriptive migration names |

## Next.js Integration Notes

- Prisma Client must be instantiated as a singleton to prevent connection exhaustion in development
- Standard pattern: `src/lib/prisma.ts` with global singleton check
- Import generated client: `import { PrismaClient } from '@/generated/prisma'`
