- `stats:update` WS event now correctly invalidates `['dashboard-stats']` query (was `['dashboard', 'stats']` which never matched)
- `resource:update` WS event now correctly invalidates `['system-resources']` query (was `['monitoring', 'resources']`)
- `panel:fallback-change` WS event now correctly invalidates `['fleet-status']` query (was `['panels']`)
- Removed duplicate `alert:new` invalidation entry (use-alerts.ts self-invalidates)

## Decisions Made

- `panel:push-progress` and `chain:status-update` removed entirely because `push-wizard.tsx` reads `lastEvent` directly and `use-chain-status.ts` uses direct Socket.IO with manual `useState` -- neither has a React Query consumer
