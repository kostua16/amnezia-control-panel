## Fixed Issues

### CR-01: Push always fails -- empty API keys rejected by push endpoint schema

**Files modified:** `src/app/api/panels/push/route.ts`
**Commit:** 3afdf8a
**Applied fix:** Changed `z.string().min(1)` to `z.string()` in the push endpoint schema so empty API key strings are accepted, allowing the cached-key fallback design to work as intended by the wizard.

### CR-02: Switch statements without default case produce no output for unknown topologies

**Files modified:** `src/app/api/panels/push/chain-config/route.ts`
**Commit:** ed26062
**Applied fix:** Added `default` case to both `generateWireGuardPeers` and `generateXrayRoutingRules` switch statements that throws an explicit error for unsupported topologies, preventing silent empty config generation.

### CR-03: `allowedIPs` exceeds /32 subnet boundary for linear topology with >254 nodes

**Files modified:** `src/app/api/panels/push/chain-config/route.ts`
**Commit:** baffc10
**Applied fix:** Added `MAX_NODES = 10` validation guard in the chain-config POST handler to reject templates with excessive node counts before IP address generation, returning a clear 422 error.

### WR-01: Panel mapping validation does not check mapping against selected panels

**Files modified:** `src/components/push/push-wizard.tsx`
**Commit:** 3367697
**Applied fix:** Added `Object.values(panelMapping).every(id => selectedPanelIds.has(id))` to the Next button disabled condition, ensuring mapped panel IDs are a subset of the user-selected panels.

### WR-02: `console.error` left in production code

**Files modified:** `src/components/push/push-wizard.tsx`
**Commit:** 24dc675
**Applied fix:** Replaced `console.error('Rollback failed:', err)` with `setPushError(...)` to surface rollback failures to the user through the existing error display.

### WR-03: `console.log` statements in WebSocket hook used in production

**Files modified:** `src/hooks/use-websocket.ts`
**Commit:** ebcfe4a
**Applied fix:** Removed three `console.log` debug statements from `useWebSocket` hook (Connected, Disconnected, Reconnect attempt) that were left in production code.

### WR-04: Hardcoded port 3000 in chain-config generation

**Files modified:** `src/app/api/panels/push/chain-config/route.ts`
**Commit:** ad4c08c
**Applied fix:** Changed port extraction to parse the port from `panelUrl` when present (e.g., `https://host:8080`), falling back to 3000 as default when no port is specified.

### WR-05: Polling fallback is a no-op -- status endpoint returns empty events forever

**Files modified:** `src/components/push/push-wizard.tsx`
**Commit:** 39a1834
**Applied fix:** Removed the non-functional polling fallback entirely. Disabled the Push button when WebSocket is disconnected, and added an amber warning banner on step 2 explaining that real-time progress requires WebSocket. This prevents users from initiating a push they cannot monitor.
