```prisma
model CachedPanelConfig {
  id            Int      @id @default(autoincrement())
  panelId       Int?
  configVersion Int
  config        Json
  receivedAt    DateTime @default(now())
  /** Previous config version (for rollback support) */
  previousConfigVersion Int?
  /** Previous config JSON (for rollback support) */
  previousConfig Json?
  /** When the previous config was received */
  previousConfigReceivedAt DateTime?

  @@unique([panelId])
  @@map("cached_panel_configs")
}
```

The three new fields (`previousConfigVersion`, `previousConfig`, `previousConfigReceivedAt`) are all nullable. They are populated when a new config is pushed and overwrites the current config.

**Create `src/lib/rollback-manager.ts`:**

```typescript
import { prisma } from '@/lib/prisma';
import type { PanelSyncPayload } from '@/types/panel-sync';
```

Implement these functions:

**storePreviousConfig(panelId: number): Promise<void>**
- Called BEFORE a new config overwrites the current cached config
- Fetches the current CachedPanelConfig for the panel
- If a current config exists, copies its `config` -> `previousConfig`, `configVersion` -> `previousConfigVersion`, `receivedAt` -> `previousConfigReceivedAt`
- Updates the record in place (not a separate write -- just prepares the previous fields)
- This is called by the sync/receive endpoint BEFORE writing the new config

**rollbackPanelConfig(panelId: number): Promise<{ success: boolean; configVersion: number | null; error: StructuredPushError | null }>**
- Fetches CachedPanelConfig for the panel
- Checks if previousConfig is not null
- If no previous config exists, return error: "No previous config available for rollback"
- Swaps current and previous: current becomes previous, previous becomes current
  - current.config = old previousConfig
  - current.configVersion = old previousConfigVersion
  - current.previousConfig = null
  - current.previousConfigVersion = null
  - current.previousConfigReceivedAt = null
  - (the old current is discarded -- rollback is one-level only per D-02)
- Updates the record in DB
- Re-pushes the restored config to the remote panel via pushConfigToPanel
  - Looks up the panel from RemotePanel table
  - Gets the cached API key from panel-health-checker's cache
  - Calls pushConfigToPanel with the restored PanelSyncPayload
- Returns success/failure with the new configVersion
