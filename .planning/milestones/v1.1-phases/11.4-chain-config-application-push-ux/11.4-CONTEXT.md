# Phase 11.4: Chain Config Application & Push UX - Context

**Gathered:** 2026-04-30
**Status:** Ready for planning

<domain>
## Phase Boundary

Pushed chain configurations are actually applied to AWG and 3x-ui services on remote servers, with diff preview, rollback, and actionable error reporting. This phase turns the stub `applyChainConfig` into real CLI/REST operations and provides the admin UI for previewing, pushing, and rolling back configurations.

Requirements: CPUSH-04, CPUSH-05, CPUSH-06, CHAIN-01, CHAIN-02, CHAIN-03

</domain>

<decisions>
## Implementation Decisions

### Config Application Strategy
- AWG: `amneziawg`/`amneziaawg`/`awg`/`wg` CLI + `docker exec` — both local (same-server) and SSH over Tailscale connections
- 3x-ui: REST API via community endpoint (`POST /xui/inbound/update`)
- Sequential application (predictable errors at 1-3 server scale)
- Partial failure: report succeeded + failed panels, admin decides (rollback or manual fix)

### Push UX & Diff Preview
- Diff format: side-by-side (current config vs new config per panel)
- Push UI location: dedicated page `/panels/push` with panel selector, preview, and action buttons
- Push flow: preview → confirm → push → results (multi-step wizard)
- Status feedback: real-time per-panel progress via WebSocket + polling fallback

### Rollback & Error Reporting
- Rollback storage: last 2 configs in SQLite via CachedPanelConfig (current version + previous)
- Rollback scope: per-panel (single server rollback)
- Error reporting: structured errors with `type`, `message`, `recommendation`, `known_fix` fields
- Known fixes: pattern matching on common errors (timeout, auth fail, invalid config) + generic fallback

### Claude's Discretion
- Exact CLI command sequences for amneziawg/wg operations
- Docker exec vs SSH detection logic (how to determine which method to use)
- 3x-ui REST API endpoint paths and payload format
- Side-by-side diff component implementation details
- WebSocket event payload structure for push progress
- Error pattern definitions and matching logic

</decisions>

<specifics>
## Specific Ideas

- AWG CLI must handle both native (`amneziawg setconf`) and docker (`docker exec container wg setconf`) invocation
- The push page should show a visual chain diagram indicating which panels will be affected
- Rollback should be a single-click operation per panel — no confirmation dialog (admin can always push again)
- Error messages should be actionable — not just "push failed" but "panel X: connection timeout, check Tailscale status"

</specifics>

<deferred>
## Deferred Ideas

- Full audit log of push/rollback operations (nice-to-have, not in requirements)
- Auto-rollback on push failure (too risky without admin confirmation)

</deferred>
