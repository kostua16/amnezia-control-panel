# 12.5-01: Mount PushWizard on push page and wire panel boundaries

## Objective

Replace the dead ChainFlowEditor-only push page with PushWizard as the primary component, and provide ChainFlowEditor as a secondary "visual reference" tab with proper `panels` and `serverPanelMap` props wired.

## Context

- `PushWizard` at `src/components/push/push-wizard.tsx` is fully implemented but never mounted
- Current push page (`src/app/(dashboard)/panels/push/page.tsx`) renders ChainFlowEditor with only `servers` prop
- ChainFlowEditor accepts optional `panels?: RemotePanel[]` and `serverPanelMap?: Record<number, number>` props for panel boundary rendering
- No FK between Server and RemotePanel; `serverPanelMap` must be built by matching server tailnetIP/hostname to panel URL hostname

## Tasks

### Task 1: Create buildServerPanelMap utility

**Type:** auto
**Action:** Create `src/lib/build-server-panel-map.ts` that constructs `Record<number, number>` (serverId -> panelId) by matching server `tailnetIP` or `tailnetHostname` against panel `panelUrl` hostname.
**Done when:** Exported function accepts `(servers: Server[], panels: PanelItem[]) => Record<number, number>`.
**Verification:** TypeScript compiles, no runtime errors on empty arrays.

### Task 2: Rewrite push page to mount PushWizard with tab toggle

**Type:** auto
**Action:** Rewrite `src/app/(dashboard)/panels/push/page.tsx`:
- Import `PushWizard` and `ChainFlowEditor`
- Import `buildServerPanelMap`
- Fetch panels and servers (existing fetch logic)
- Build `serverPanelMap` from fetched data
- Show two tabs: "Push to Panels" (PushWizard) and "Visual Chain Editor" (ChainFlowEditor)
- Default to "Push to Panels" tab
- Pass `panels` to PushWizard
- Pass `servers`, `panels`, and `serverPanelMap` to ChainFlowEditor
- Keep the empty state for no panels
**Done when:** `/panels/push` renders PushWizard when panels exist, ChainFlowEditor in secondary tab with panel boundary support.
**Verification:** No TypeScript errors; PushWizard renders with panels prop; ChainFlowEditor receives all three props.

### Task 3: Verify API endpoints are accessible with JWT middleware

**Type:** auto
**Action:** Verify that the following API routes used by PushWizard are not blocked by JWT middleware:
- `/api/panels/diff` (POST)
- `/api/panels/push` (POST)
- `/api/panels/push/chain-config` (POST)
- `/api/panels/rollback` (POST)
- `/api/panels` (GET)
- `/api/chains/templates` (GET)

Check JWT middleware configuration and ensure these routes are not excluded from auth (they should require auth, which the page session provides). Verify the middleware doesn't redirect API routes to /login.
**Done when:** All listed API endpoints are confirmed to work with JWT session auth (not excluded or broken).
**Verification:** Review middleware.ts and confirm the public route exclusions do NOT include any of the push API routes.

## Success Criteria

1. `/panels/push` page renders PushWizard as primary component when panels exist
2. PushWizard receives `panels` prop correctly
3. ChainFlowEditor secondary tab receives `servers`, `panels`, and `serverPanelMap` props
4. `buildServerPanelMap` utility correctly maps servers to panels via Tailscale addresses
5. No TypeScript compilation errors in modified files
6. PushWizard's 4-step flow (select panels -> diff -> push -> results) is accessible via the UI
