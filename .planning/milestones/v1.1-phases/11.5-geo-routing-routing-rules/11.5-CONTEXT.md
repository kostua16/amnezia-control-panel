# Phase 11.5: Geo-Routing & Routing Rules - Context

**Gathered:** 2026-05-01
**Status:** Ready for planning

<domain>
## Phase Boundary

Geo-routing rules are persisted to SQLite (replacing v1.0 in-memory stores), GeoIP lookup drives geo-aware routing, routing rules support full CRUD with priority and match conditions, admins can load artifacts aligned with the v2fly/geoip and sendmiche/rulite ecosystems, and templates provide best-practice defaults. Scope matches ROADMAP success criteria and requirements GEO-01–04, RULE-01–03.

<decisions>
## Implementation Decisions

### GeoIP data & operations
- **D-01:** On-disk GeoIP databases/files (not primary reliance on live HTTP lookup), with **periodic refresh** comparable to the Xray/v2fly operational model. Research/planning should align with how **https://github.com/v2fly/geoip** and **https://github.com/sendmiche/rulite** distribute and update data.
- **D-02:** Primary file source: **v2fly/geoip-style prebuilt artifacts** (same class of artifacts Xray deployments already use), not MaxMind-direct download as the default path.
- **D-03:** Refresh: **built-in scheduler** in the panel (configurable interval) plus **manual “update now”** (or equivalent).
- **D-04:** Lookup failure (missing DB, bad file, private IP, unknown geo): **fail open** — no geo match; **fall through** to lower-priority rules / default routing.

### Rule evaluation & transport
- **D-05:** Enforcement model: **push resolved Xray-oriented routing config** — central expands geo (and other matches) into concrete routing suitable for application on remote panels; panels continue to apply config as today, with **Xray runtime** using on-disk geoip data where relevant.
- **D-06:** **IPv4-only** geo matching for this phase; IPv6 can be a follow-up if gaps appear.
- **D-07:** Match ordering: **strict numeric priority** from the admin — reorder in UI; **lower number = higher precedence** (exact semantics for ties left to planner with explicit documentation).
- **D-08:** **SQLite is canonical** for rule definitions; allow a **short-lived cache** in front of DB reads for API performance.

### External imports (v2fly / rulite)
- **D-09:** Import placement: **replace only the “imported bundle” tier** — custom/admin rules live outside that replaceable slice (two-tier mental model).
- **D-10:** When an imported rule **collides** with an existing rule on the same condition key: **overwrite after confirmation** (destructive path is explicit).
- **D-11:** Outbound/tag mapping: **auto-match by name** to existing node/chain labels where possible; **unmatched tags** require an explicit admin mapping step before apply.
- **D-12:** Import scope: **best-effort parse** — import what maps cleanly; **surface errors** for unsupported constructs (no silent drop without feedback).

### Admin UX
- **D-13:** Layout: **tabs** (e.g. Geo | IP/Domain | Templates — exact labels for planner).
- **D-14:** Templates: **both** — template picker when creating a rule **and** a **dedicated templates gallery** (or page) with apply flows.
- **D-15:** Empty state: offer **one-click “load recommended starter rules”** as a **non-destructive** demo path (planner defines what “starter” means and safe defaults).
- **D-16:** Editor pattern: **drawer / slide-over** so the rule list stays visible.

### Migration from v1.0 in-memory geo
- **D-17:** **Auto-migrate on first boot** after upgrade: copy prior in-memory geo rules into SQLite where technically feasible; **log counts** and failures.
- **D-18:** Detailed reconciliation between existing **`RoutingRule` Prisma model**, new geo persistence, and any in-memory API stubs was **not fully locked** in discussion (user skipped deep migration questions) — **planner must review** `prisma/schema.prisma` and `src/app/api/routing/` and propose a single coherent model/migration story.

### Claude's Discretion
- Exact geoip.dat / MMDB paths, file validation, and checksum strategy
- Scheduler defaults (interval, backoff, failure alerting)
- Cache TTL and invalidation for routing rule reads
- Drawer vs sheet component choice; tab copy and IA details
- Exact duplicate-key definition for “same condition” during import
- Tie-break behavior when two rules share the same priority number

</decisions>
