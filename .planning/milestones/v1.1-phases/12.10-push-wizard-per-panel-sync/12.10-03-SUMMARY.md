# Phase 12.10 Plan 03: Chain apply panelCredentials + editor API key dialog Summary

Fix `/api/chains/apply` to accept `panelApiKeys` from callers and build a real `panelCredentials` map. Add a "Provide API Keys" dialog to ChainFlowEditor that collects shared secrets per panel before applying chain configuration.

## Tasks Completed

| Task | Name | Commit | Files Modified |
|------|------|--------|----------------|
| 1 | Add panelApiKeys to chains/apply route and build panelCredentials | efeadbe | `src/app/api/chains/apply/route.ts` |
| 2 | Add API key collection dialog to ChainFlowEditor | c73160e | `src/components/chains/chain-flow-editor.tsx` |

## Changes Made

### Task 1: chains/apply route (efeadbe)

- Added `cachePanelApiKey` import from `@/lib/panel-health-checker`
- Added optional `panelApiKeys` field to Zod schema (`z.record(z.coerce.number().int(), z.string()).optional()`)
- Destructured `panelApiKeys` from parsed request data
- Replaced empty `panelCredentials` map with real credential building: caches API keys via `cachePanelApiKey` and populates `panelCredentials` by matching `panel.serverId` / `panel.id` against `panelApiKeys` entries
- Removed the TODO comment referencing Phase 12.10

### Task 2: ChainFlowEditor dialog (c73160e)

- Added imports: `Eye`, `EyeOff` from lucide-react, `Input` from UI components
- Added state: `saveDialogOpen`, `panelApiKeys`, `visibleKeys`, `saveError`
- Added `saveDialogPanels` memo deriving unique panels from chain nodes + `serverPanelMap`
- Split `handleSave` into `handleSaveClick` (opens dialog) and `handleSaveDirect` (sends request with `panelApiKeys`)
- Updated Save Chain button to call `handleSaveClick`
- Added "Provide API Keys" Dialog with one password input per unique panel, show/hide toggle, Cancel and Apply to Panels buttons
- "Apply to Panels" disabled until all panel keys are non-empty
- Error responses displayed in dialog

### Decision: chain-builder.tsx unchanged

The plan decided not to modify `chain-builder.tsx` because it lacks `panels` and `serverPanelMap` props needed to determine which panels to show. The route's `panelApiKeys` field is optional, so backward compatibility is preserved. The primary editor path (ChainFlowEditor) gets the dialog; ChainBuilder continues to work for local-only chains.

## Deviations from Plan

None - plan executed exactly as written.

## Threat Surface Scan

No new threat surface introduced. The `panelApiKeys` field passes plaintext keys from browser to backend over HTTPS, matching the existing push route pattern (T-12.10-05 through T-12.10-08 already documented in the plan).
