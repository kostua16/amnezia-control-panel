# Phase 11.8: Multi-Panel Dashboard - Context

**Gathered:** 2026-05-01
**Status:** Ready for planning

<domain>
## Phase Boundary

Central health dashboard that aggregates service status, traffic metrics, and alerts from all registered remote panels into a single overview. Enhances the existing `/dashboard` page with multi-panel awareness. Requires a new aggregation API endpoint that collects metrics from all remote panels via Tailscale, and a UI layer that presents per-panel status cards with expandable detail views.

</domain>

<decisions>
## Implementation Decisions

### Dashboard Layout & Structure
- Enhance existing `/dashboard` page with multi-panel section below current single-panel metrics
- Card grid layout (1 card per panel) — matches existing MetricsCards pattern
- 30s polling for `/api/panels/[id]/status` + WebSocket events for fallback/push updates
- Subscribe to `panel:fallback-change` and `panel:push-progress` WebSocket events in providers.tsx

### Per-Panel Content
- Per-panel card shows: connection status badge + latency + services online/total + last sync time
- Click card expands inline accordion with traffic chart + resource bars
- Aggregate summary strip above panel cards: total panels online/degraded/offline + total traffic

### Alert Unification & Visual Polish
- Use existing AlertBanner in header + filter alerts by panel name in alert type field
- Consistent visual hierarchy: red (offline/CRITICAL) → yellow (degraded/WARNING) → green (connected/INFO)
- Empty state when no remote panels: show current dashboard as-is + CTA card "Add your first remote panel"

### Claude's Discretion
- Exact card layout breakpoints and responsive behavior
- Accordion animation details
- Traffic chart granularity in expanded view
- CTA card design for empty state

</decisions>
