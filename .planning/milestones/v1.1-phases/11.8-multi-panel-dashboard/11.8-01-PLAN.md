  const k = 1024;

    ```typescript
    import type { PanelConnectionStatus } from '@/lib/panel-health-checker';
    import type { PanelConnectionRecord } from '@/types/remote-panel';

    /** Per-panel status as displayed on the dashboard card */
    export interface PanelDashboardStatus {
      panelId: number;
      panelName: string;
      panelUrl: string;
      status: PanelConnectionStatus;
      latencyMs: number | null;
      lastCheckedAt: string | null;
      lastSyncAt: string | null;
      servicesOnline: number;
      servicesTotal: number;
      isFallback: boolean;
    }

    /** Aggregated fleet status returned by GET /api/panels/status */
    export interface FleetAggregatedStatus {
      panels: PanelDashboardStatus[];
      summary: {
        total: number;
        online: number;
        degraded: number;
        offline: number;
        unknown: number;
      };
    }
    ```

    **Step 2: Create aggregation API endpoint**

    Create `src/app/api/panels/status/route.ts` with a `GET` handler that:

    1. Queries all active remote panels from Prisma: `prisma.remotePanel.findMany({ where: { isActive: true } })`
    2. For each panel in parallel (`Promise.all`), calls `getPanelStatus(panel.id)` from `@/lib/panel-health-checker` to derive connection status
    3. Checks `isPanelInFallback(panel.id)` for each panel
    4. For `lastSyncAt`, queries `prisma.cachedPanelConfig` for the most recent sync per panel: `prisma.cachedPanelConfig.findFirst({ where: { panelId }, orderBy: { updatedAt: 'desc' } })`
    5. For `servicesOnline` / `servicesTotal`, queries `prisma.service` with `where: { serverId: panelId }` -- note: services are tied to Server, not RemotePanel. For the initial implementation, set `servicesOnline: 0` and `servicesTotal: 0` since cross-panel service queries require remote panel API access (which is not yet available in v1.1). This is accurate -- the central panel does not have direct knowledge of remote panel services.
    6. Constructs a `PanelDashboardStatus` object for each panel
    7. Computes summary counts (online, degraded, offline, unknown)
    8. Returns `FleetAggregatedStatus` using `success()` from `@/lib/api-response`

    Per CONTEXT.md decision: "30s polling for /api/panels/[id]/status" -- this endpoint provides the aggregated version that the client fetches once instead of N individual calls.

    Response shape:
    ```json
    {
      "success": true,
      "data": {
        "panels": [...],
        "summary": { "total": 3, "online": 2, "degraded": 1, "offline": 0, "unknown": 0 }
      }
    }
    ```
