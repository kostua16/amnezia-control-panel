  <action>
    Create `src/app/api/tailscale/setup/verify/route.ts` with a POST handler that accepts a JSON body with a `step` field and runs the corresponding verification.

    **Request schema (zod):**
    ```typescript
    const verifySchema = z.object({
      step: z.enum(['install', 'auth', 'ip-forwarding', 'subnet-config', 'tailnet-check']),
      subnets: z.array(z.string()).optional(),  // Only for 'subnet-config' step
    });
    ```

    **Step handlers:**

    1. `install` -- Call `verifyInstalled()`. Return `{ success: installed, version, message }`. Message: installed version string or "Tailscale is not installed. Install from https://tailscale.com/download".

    2. `auth` -- Call `getBackendState()`. Return `{ success: state === 'Running', state, message }`. If "NeedsLogin": message = "Tailscale installed but not logged in. Run: tailscale login". If "Running": message = "Tailscale is connected and authenticated". If "Stopped": message = "Tailscale daemon is not running. Start with: sudo systemctl start tailscaled".

    3. `ip-forwarding` -- Run `sysctl net.ipv4.ip_forward` using `execFileAsync('sysctl', ['net.ipv4.ip_forward'])`. Check if output contains `= 1`. Return `{ success, message }`. If not enabled: message = "IP forwarding is disabled. Enable with: sudo sysctl -w net.ipv4.ip_forward=1". This is per RESEARCH.md Pitfall 4.

    4. `subnet-config` -- Validate the `subnets` array from request body. Each subnet must match CIDR regex `/^[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\/[0-9]{1,2}$/`. Return `{ success, subnets, warnings }`. Per D-05, auto-detect default subnets if none provided: `[ "10.0.0.0/24", "172.16.0.0/12" ]` (AmneziaWG and Xray defaults). Per D-06, check for overlapping subnets by comparing CIDR ranges of provided subnets. If overlaps found, include in `warnings` array but do NOT block (D-06: warn but don't block).

    5. `tailnet-check` -- Call `getStatus()`. If null: return failure. Check that `status.Self` has non-empty `TailscaleIPs`. Call `getNodes()` and check the current node appears. Return `{ success, nodeIP, nodeHostname, peerCount, message }`. Message: "Node is visible in tailnet with N peers".

    **Response format (all steps):**
    ```json
    { "success": true, "data": { "step": "...", "passed": true, "message": "...", ... } }
    ```
    On validation error (invalid step or subnets): 422 with zod error message.

    Use `import { verifyInstalled, getStatus, getBackendState, getNodes } from '@/lib/tailscale'` and `import { execFile } from 'child_process'` (for sysctl). Use `promisify(execFile)` for sysctl call.
  </action>

    **File 1: `src/app/api/tailscale/setup/advertise/route.ts`**

    POST handler that advertises subnet routes. Per D-10 and RESEARCH.md: use `tailscale set --advertise-routes=...` for already-connected nodes.

    Request schema:
    ```typescript
    const advertiseSchema = z.object({
      subnets: z.array(
        z.string().regex(
          /^[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\/[0-9]{1,2}$/,
          'Invalid CIDR format. Expected: x.x.x.x/y'
        )
      ).min(1, 'At least one subnet is required'),
    });
    ```

    Handler:
    1. Parse body with `advertiseSchema.safeParse`
    2. Call `advertiseRoutes(subnets)` from tailscale.ts
    3. On success: also call `getStatus()` to confirm routes are in `Self.AllowedIPs` or `Self.PrimaryRoutes`. Return `{ success: true, data: { subnets, message: "Routes advertised successfully" } }`
    4. On failure: return `{ success: false, error: result.message }` with 500 status
    5. Import: `import { advertiseRoutes, getStatus } from '@/lib/tailscale'`

    **File 2: `src/app/api/tailscale/status/route.ts`**

    GET handler that returns the current Tailscale node status. Per D-02: runs fresh every call, no caching.

    Handler:
    1. Call `getStatus()` from tailscale.ts
    2. If null: return `{ success: false, error: "Tailscale is not running or not installed" }` with 503 status
    3. Call `getNodes()` to get full peer list
    4. Call `getNodeIP()` to get local node IP
    5. Return `{ success: true, data: { self: { hostname, dnsName, ip, version }, backendState, peerCount, peers: TailscaleNodeInfo[] } }`
    6. The `peers` array must NOT include `PublicKey` from the raw TailscalePeer -- only the fields in TailscaleNodeInfo
    7. Import: `import { getStatus, getNodes, getNodeIP } from '@/lib/tailscale'`

    Both routes follow the existing `{ success: boolean; data?: ...; error?: string }` response pattern from the servers API.
