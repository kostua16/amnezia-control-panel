    Create `src/lib/tailscale.ts` -- a thin utility file with exported async functions (per D-03: no class-based abstraction). Follow the `runCommand` pattern from `vpn-services.ts` exactly.

    Structure the file with these sections:

    **1. Imports and CLI helper:**
    ```typescript
    import { execFile } from 'child_process';
    import { promisify } from 'util';
    import type { TailscaleStatus, TailscalePeer, TailscaleNodeInfo, TransportAddress } from '@/types/tailscale';

    const execFileAsync = promisify(execFile);

    /** CLI binary path -- D-04: try PATH first, fallback to /usr/bin/tailscale */
    const TAILSCALE_BIN = 'tailscale';
    const TAILSCALE_FALLBACK = '/usr/bin/tailscale';
    ```

    Internal helper `runTailscale(args, label, timeout = 10_000)`:
    - Try TAILSCALE_BIN first, then TAILSCALE_FALLBACK if ENOENT
    - Uses `execFileAsync(bin, args, { timeout, encoding: 'utf-8' })`
    - Returns `{ success: boolean; stdout: string; message: string }`
    - Logs with `[tailscale]` prefix
    - Never throws (catches all errors and returns structured result)

    **2. Exported functions (per D-03):**

    `verifyInstalled()` -- runs `tailscale version`, returns `{ installed: boolean; version: string }`. Parse first line of output as version string.

    `getStatus()` -- runs `tailscale status --json`, parses JSON with `JSON.parse`, returns `TailscaleStatus | null`. Wrap parse in try/catch, return null on failure.

    `getNodes()` -- calls `getStatus()`, converts `Object.values(status.Peer)` to array, prepends `status.Self` with `isSelf: true`. Returns `TailscaleNodeInfo[]`. Map each peer using internal `toNodeInfo`:
    ```typescript
    function toNodeInfo(peer: TailscalePeer, isSelf: boolean): TailscaleNodeInfo {
      return {
        id: peer.ID,
        hostname: peer.HostName,
        dnsName: peer.DNSName,
        os: peer.OS,
        tailscaleIPs: peer.TailscaleIPs ?? [],
        online: peer.Online,
        relay: peer.Relay ?? '',
        primaryRoutes: peer.PrimaryRoutes ?? [],
        isSelf,
      };
    }
    ```

    `getNodeIP(hostname?: string)` -- runs `tailscale ip -4` (no arg = local IP) or `tailscale ip -4 &lt;hostname&gt;` (specific node). Returns `string | null`. Trim the result.

    `isReachable(hostname: string)` -- calls `getStatus()`, finds peer by matching `HostName` or `DNSName`, returns `peer.Online`. Returns `false` if not found.

    `advertiseRoutes(subnets: string[])` -- runs `tailscale set --advertise-routes=&lt;comma-joined CIDRs&gt;`. Returns `{ success: boolean; message: string }`. Validate each subnet with CIDR regex `/^[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\/[0-9]{1,2}$/` before calling. If any invalid, return failure with message listing the invalid CIDR.

    `getBackendState()` -- calls `getStatus()`, returns the `BackendState` string (e.g., "Running", "NeedsLogin", "Stopped"), or `"Unknown"` if status is null.

    All functions follow the non-throwing pattern from vpn-services.ts.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argument injection | User-provided CIDRs/hostnames passed to execFile args array |
| Tailscale topology exposure | Node listing data served to frontend |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11.1-01 | T (Tampering) | `advertiseRoutes()` CIDR args | mitigate | `execFile` with array args prevents shell injection by design. Validate CIDR format with regex before passing. Do NOT use `exec` or string concatenation. |
| T-11.1-02 | I (Information Disclosure) | `getNodes()` / `getStatus()` response | mitigate | Strip `PublicKey` from TailscaleNodeInfo -- only include id, hostname, dnsName, tailscaleIPs, online, relay, primaryRoutes, isSelf. Never expose full TailscalePeer to API consumers. |
| T-11.1-03 | E (Elevation of Privilege) | `tailscale set --advertise-routes` | accept | Panel must run with sufficient privileges. At single-server deployment (per PROJECT.md), panel typically runs as root. If not, this is a deployment config issue, not a code issue. Document in setup wizard. |
| T-11.1-04 | D (Denial of Service) | `tailscale status --json` on every API call | accept | Per D-02, fresh status on every call. At 1-3 server scale with less than 100ms CLI latency, this is negligible. No rate limiting needed. |
</threat_model>
