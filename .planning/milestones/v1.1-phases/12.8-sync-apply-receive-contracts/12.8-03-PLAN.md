Add a module-level mock for `../geo-routing` in `chain-router.test.ts` that replaces `resolveGeoRoute` with a stub function returning `{ matched: false, action: 'ALLOW' }`. This severs the transitive import chain so `@/lib/prisma` and `@/lib/geoip-manager` are never evaluated at test runtime.

**Approach -- `node:test` `mock.module`:**

The test file already uses `import { mock } from 'node:test'`. Node.js built-in `mock.module()` (available since Node 18.19 / 20.x, stable in 22+) intercepts module resolution. However, since the test uses `tsx` for TypeScript compilation and ESM handling, the mock must be set up BEFORE the `import { applyChainConfig }` line that triggers evaluation.

Use this pattern at the TOP of the file (before the `applyChainConfig` import):

```typescript
import { mock, describe, it, beforeEach, afterEach } from 'node:test';
import assert from 'node:assert/strict';

// Mock geo-routing to prevent transitive @/lib/prisma import
const mockResolveGeoRoute = mock.fn(async (_ip: string) => ({
  matched: false,
  action: 'ALLOW' as const,
}));

mock.module('../geo-routing', {
  namedExports: {
    resolveGeoRoute: mockResolveGeoRoute,
  },
});
```

Then remove the now-redundant re-import of `mock` from the existing destructured import line (it is already imported above). Keep the existing `import { applyChainConfig }` from `../chain-router` as-is -- the import will now resolve `geo-routing` to the mock.

**Important:**
- The mock MUST be declared BEFORE `import { applyChainConfig }` because ESM evaluates imports eagerly. If the mock is declared after the import, `geo-routing.ts` will already have been evaluated (and `@/lib/prisma` will fail to resolve).
- If `mock.module` does not work with tsx's ESM loader, fall back to manually overriding the import: declare `mockResolveGeoRoute` as above, and add `beforeEach(() => { mockResolveGeoRoute.mock.resetCalls(); })` with a `// @ts-expect-error -- module mock` assignment like `chainRouterModule.resolveGeoRoute = mockResolveGeoRoute;` after a dynamic import approach. But try `mock.module` first since the project runs Node 22+ (tsx 4.x targets modern Node).
- The existing test "returns valid result object when sourceIp is provided" (test 5) already expects the happy path (ALLOW), so the default mock return value is correct.
- Keep ALL existing tests and assertions unchanged. Only add the mock setup at the top of the file.
- Keep `globalThis.fetch` mocking in `beforeEach`/`afterEach` as-is -- that mocks the network layer, not the geo-routing layer.
