## Decisions Made

**CJS preload mock over `node:test` `mock.module`:** The plan specified using `mock.module('../geo-routing', ...)` from `node:test`. However, tsx compiles TypeScript to CJS internally, and `mock.module` only intercepts ESM module resolution via Node's loader hooks. tsx's internal CJS `require` chain bypasses these hooks entirely, meaning the real `geo-routing.ts` was still evaluated (triggering the `@/lib/prisma` import). The CJS preload approach using `Module._resolveFilename` patching intercepts at the correct layer.

**Test run command:** `node --import tsx --require ./src/lib/__tests__/_setup-geo-routing-mock.cjs --test src/lib/__tests__/chain-router.test.ts`

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] mock.module incompatible with tsx CJS module resolution**
- **Found during:** Task 1 (Mock geo-routing module)
- **Issue:** `node:test` `mock.module()` does not intercept module resolution when tsx is used as the TypeScript loader. tsx resolves imports through its own CJS pipeline, bypassing Node's ESM mock hooks. The test file would fail with "Cannot find module '@/generated/prisma/client'" because geo-routing.ts was still being evaluated.
- **Fix:** Replaced `mock.module` approach with a CJS preload script (`_setup-geo-routing-mock.cjs`) that patches `Module._resolveFilename` to redirect geo-routing imports to a mock module (`_geo-routing-mock.cjs`). The preload runs before any test code is loaded, intercepting at the correct CJS resolution layer.
- **Files modified:** Created `src/lib/__tests__/_setup-geo-routing-mock.cjs` and `src/lib/__tests__/_geo-routing-mock.cjs`; reverted `chain-router.test.ts` to original (no mock.module code needed)
- **Verification:** All 5 chain-router tests pass without Prisma client generated; config-applier (7/7) and panel-sync-client (16/16) pass with no regression
