# Phase 12.6 Plan 01: Geo-routing runtime E2E wiring

## Objective

Wire `resolveGeoRoute()` into the runtime chain/traffic path (GEO-03) and narrow GEO-04 requirement text to match shipped scope (v2fly geoip.dat import only).

## Context

- `src/lib/geo-routing.ts` has `resolveGeoRoute(ip)` and `evaluateGeoRulesFromDB()` -- fully implemented but zero callers
- `src/lib/rule-enforcement.ts` evaluates routing rules and generates configs for AWG/3x-ui
- `src/lib/chain-router.ts` applies chain configs to remote panels
- `src/app/api/routing/apply/route.ts` triggers rule application

## Tasks

### Task 1: Add geo-routing resolution to rule enforcement

**type:** auto

Wire `resolveGeoRoute` into the rule enforcement module so that geo-routing decisions are evaluated alongside standard routing rules.

- In `src/lib/rule-enforcement.ts`:
  - Import `resolveGeoRoute` from `@/lib/geo-routing`
  - Add a new exported function `resolveGeoRoutingForDestination(ip: string)` that calls `resolveGeoRoute(ip)` and returns a `GeoRoutingResult`
  - Integrate geo-routing into `applyRoutingRules()` and `applyAllRules()`:
    - After generating AWG and 3x-ui configs, also evaluate geo rules
    - Add a `geoRoutingResults` field to `RuleEnforcementResult` containing per-rule geo evaluations
    - If any geo rule returns `action: 'ROUTE'` with a `chainId`, include that info in the result
    - If any geo rule returns `action: 'BLOCK'`, include that in the result

**done when:**
- `resolveGeoRoute` is imported in `rule-enforcement.ts`
- Geo-routing results are included in `RuleEnforcementResult`
- `applyRoutingRules` and `applyAllRules` return geo-routing info
- TypeScript compiles without errors

### Task 2: Add geo-routing pre-check to chain config application

**type:** auto

In `src/lib/chain-router.ts`, add a geo-routing pre-check before applying a chain configuration.

- Import `resolveGeoRoute` from `@/lib/geo-routing`
- Modify `applyChainConfig()` to accept an optional `sourceIp` parameter
- Before applying chain config to each node, evaluate geo rules for the source IP
- If geo rules dictate a different chain (`action: 'ROUTE'` with `chainId`), return early with info about the geo-redirect
- If geo rules say `action: 'BLOCK'`, skip application and report the block
- If geo rules say `action: 'ALLOW'` or no match, proceed with normal chain application
- Update return type to include geo-routing decision info

**done when:**
- `resolveGeoRoute` is imported in `chain-router.ts`
- `applyChainConfig` accepts optional `sourceIp` parameter
- Geo-routing pre-check is evaluated before chain application
- Return type includes geo-routing decision
- TypeScript compiles without errors

### Task 3: Add geo-routing resolve API endpoint

**type:** auto

Create a new API endpoint so the UI can trigger geo-routing resolution for testing and verification.

- Create `src/app/api/routing/geo-resolve/route.ts`
- Accept `{ ip: string }` in POST body
- Call `resolveGeoRoute(ip)` and return the `GeoRoutingResult`
- Validate input with zod
- Return proper error responses

**done when:**
- Endpoint exists at `/api/routing/geo-resolve`
- Accepts POST with `{ ip: string }`
- Returns `GeoRoutingResult` with `action`, `matched`, optional `rule` and `chainId`
- TypeScript compiles without errors
