# Phase 12.4 Plan 01: Sync apply endpoint + WS query invalidation

## Objective

Create the missing `/api/sync/apply` endpoint (GAPL-01) and wire WebSocket events to React Query invalidation in providers.tsx (GAPL-02). Clean up the silent 404 fallback in config-applier.ts.

## Context

@12.4-CONTEXT.md

- `src/app/api/sync/receive/route.ts` stores config in CachedPanelConfig, verifies HMAC via X-API-Key/X-Signature headers
- `src/lib/config-applier.ts` sends POST to `${panelUrl}/api/sync/apply` with `{ service: 'awg'|'three_xui', config, routingRules }` payload
- `src/components/providers.tsx` has QueryClient + WebSocket but no invalidation bridge
- `src/hooks/use-alerts.ts` already uses `lastEvent` + `invalidateQueries` as the pattern to follow
- `src/lib/vpn-services.ts` has stub commands for AWG (`amneziawg`) and 3x-ui (`xui`)
- `src/lib/hmac.ts` provides `verifySignature(payload, secret, signature)`
- `src/middleware.ts` lists public routes — `/api/sync/apply` must be added (HMAC auth, not JWT)

## Tasks

<task type="auto" name="Create /api/sync/apply endpoint">
<files>
- src/app/api/sync/apply/route.ts (create)
- src/middleware.ts (modify)
</files>

Create `POST /api/sync/apply` endpoint that:

1. Extracts X-API-Key and X-Signature headers (same auth pattern as `/api/sync/receive`)
2. Validates HMAC signature against the request body
3. Reads the config payload: `{ service: 'awg' | 'three_xui', config?: string, routingRules?: object[] }`
4. Reads the latest cached config from CachedPanelConfig for the authenticated panel
5. For `awg` service: applies WireGuard config via vpn-services pattern (wg-quick or amneziawg CLI). Uses the `config` field (wg.conf text) or the cached wireguardPeers.
6. For `three_xui` service: applies routing rules via 3x-ui REST API or CLI stub. Uses the `routingRules` field or cached routingRules.
7. Returns `{ success: true, data: { applied: true, configVersion, service } }` on success
8. Returns structured error with actionable message on failure
9. Uses idempotency check: if already applied at this configVersion, return early

Also add `/api/sync/apply` to PUBLIC_API_ROUTES in `src/middleware.ts`.

<done>
- `curl -X POST http://localhost:3333/api/sync/apply -H "Content-Type: application/json" -d '{"service":"awg","config":"test"}'` returns 401 (no auth headers)
- Endpoint validates HMAC signature
- Endpoint reads from CachedPanelConfig
- Returns structured JSON response with applied flag and configVersion
- Middleware allows unauthenticated access to /api/sync/apply (HMAC auth instead)
</done>
</task>

<task type="auto" name="Wire WebSocket events to React Query invalidation">
<files>
- src/components/providers.tsx (modify)
</files>

In `src/components/providers.tsx`, add a `useEffect` inside the `Providers` component that:

1. Watches `lastEvent` for changes
2. Maps WS event types to React Query key patterns:
   - `stats:update` -> invalidate `['dashboard', 'stats']`
   - `resource:update` -> invalidate `['monitoring', 'resources']`
   - `alert:new` -> invalidate `['alerts']`
   - `user:status-change` -> invalidate `['users']`
   - `panel:push-progress` -> invalidate `['panels']`
   - `chain:status-update` -> invalidate `['chains']`
   - `panel:fallback-change` -> invalidate `['panels']`
3. Uses `queryClient.invalidateQueries({ queryKey: [...] })` (partial match via array prefix)
4. Keeps polling as fallback (does NOT remove staleTime/refetchInterval)

Follow the pattern from `use-alerts.ts` which already does `lastEvent['alert:new']` checks.

<done>
- WS events trigger query invalidation in browser console (React Query devtools or network tab)
- No TypeScript errors
- Polling fallback still works (staleTime/refetchInterval unchanged)
- Existing use-alerts.ts invalidation still works (no regression)
</done>
</task>
