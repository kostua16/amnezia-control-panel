# Phase 12.1 Plan 1: Admin API JWT Enforcement

## Objective

Wire JWT protection on all admin API routes by creating `src/middleware.ts` that reuses JWT verification logic from `src/proxy.ts`. Closes audit gap PROJ-AUTH-01.

## Context

- 76 API routes under `src/app/api/`
- Only 2 routes (`auth/me`, `panels/rollback`) verify JWT inline
- `src/proxy.ts` has correct JWT verification logic but is NOT wired -- not imported anywhere, no `src/middleware.ts` exists
- Next.js 16 project using `jose` for JWT operations

## Public Routes (NOT protected)

| Route | Reason |
|-------|--------|
| `/api/auth/login` | Login endpoint -- no token available yet |
| `/api/health` | Health check -- must be accessible without auth |
| `/api/ws` | WebSocket -- Socket.io handles upgrade, not Next.js middleware |
| `/api/sync/receive` | Uses HMAC + API key auth, not JWT |

All other `/api/*` routes need JWT verification.

## Tasks

### Task 1: Create `src/middleware.ts` with JWT enforcement

**Type:** auto
**What:** Create Next.js middleware that:
- Matches all `/api/*` routes except public ones
- Extracts `auth-token` cookie
- Verifies JWT using `jose/jwtVerify`
- Returns 401 JSON for unauthenticated API requests
- Passes through for authenticated requests
- Also protects page routes (dashboard, users, services, etc.) by redirecting to `/login`

**Implementation:**
- Extract JWT helper functions from `proxy.ts` into a shared module or inline them
- Export named `middleware` function and `config` with matcher
- For API routes: return `NextResponse.json({ error: 'Unauthorized' }, { status: 401 })`
- For page routes: redirect to `/login?expired=true` (existing pattern from proxy.ts)

**Done when:**
- `src/middleware.ts` exists with proper exports
- No TypeScript errors
- Matcher covers all `/api/*` routes and page routes

### Task 2: Remove inline JWT checks from routes now handled by middleware

**Type:** auto
**What:** Clean up inline JWT verification from `auth/me/route.ts` and `panels/rollback/route.ts` since middleware now guarantees authentication. Remove the `getJwtSecret` helper and `authenticateAdmin` function from rollback route.

**Important:** Keep `auth/me` functional -- it still needs to extract user info from the verified token to return. The route handler should trust that middleware has already verified the token.

**Implementation:**
- `auth/me/route.ts`: Remove JWT verification, just extract token from cookie and decode payload (middleware already verified it)
- `panels/rollback/route.ts`: Remove `getJwtSecret` and `authenticateAdmin` function. The route can trust request is authenticated.

**Done when:**
- No duplicate JWT verification in route handlers
- Routes still function correctly (auth/me returns user info, rollback processes requests)

### Task 3: Remove `src/proxy.ts`

**Type:** auto
**What:** Delete `src/proxy.ts` since its logic has been moved to `src/middleware.ts`. It was never imported by any file.

**Done when:**
- `src/proxy.ts` is deleted
- No broken imports (verified by grep)

## Verification

1. `src/middleware.ts` exists and exports `middleware` function and `config`
2. Public routes (`/api/auth/login`, `/api/health`, `/api/sync/receive`) are in the exclusion list
3. Protected API routes return 401 without valid token
4. No TypeScript errors: `npx tsc --noEmit`
5. No broken imports referencing `proxy.ts`

## Output Spec

- `src/middleware.ts` (created)
- `src/app/api/auth/me/route.ts` (modified)
- `src/app/api/panels/rollback/route.ts` (modified)
- `src/proxy.ts` (deleted)
